# 1257 — A flag is a claim, and a form says whether its pages are its own

Status: accepted and **built**.
Context: `crates/pdf-archive/src/table/interaction.rs` (`visible_widgets`),
`crates/pdf-transform/src/archive/{sites,prepare,decision,rewrite,config,report,mod}.rs`,
`crates/pdf-transform/tests/archive.rs`.
Answers: `doc/todo/66`'s **forms** family — `forms/need-appearances-absent-or-false` and
`forms/no-xfa-key`, the two sites `as-if-printed` still named at PDF/A-2b.
Builds on: `doc/adr/1105` (a construction narrowed to the annotations the output holds),
`doc/adr/0947` (nothing changed that no failed requirement asked for), `doc/adr/0816` (the fence),
`doc/adr/0965` (the `/NeedsRendering` half, whose sentence this amends),
`doc/questions/A21` (a constructed appearance is reported).
Clauses: ISO 32000-2 §12.7.3 (Table 224), §12.7.2, §12.7.4.3, §12.7.5.2.3, §12.5.3 (Table 167),
§12.5.5 (Table 170), §7.7.2 (Table 29), Annex K.1 and K.2; ISO 19005-2 sections 6.4.1 and 6.4.2;
ISO 19005-4 sections 6.4.1 and 6.4.2.

## 1. Removing a flag is making a claim, and the claim has to be true

Both parts' section 6.4.1 require Table 224's `/NeedAppearances` to be absent or false. The
table's own row says what an absent one asserts:

> A PDF writer shall include this key, with a value of true , if it has not provided appearance
> streams for all visible widget annotations present in the document.

So this is not a key that can simply be deleted. Deleting it states that appearance streams *have*
been provided, and a conversion that deletes it without providing them writes a file that lies
about itself. That is why `doc/pdf-a-mitigations.md` calls the pair **owed, not optional**, and why
`construct = true` is the default rather than an option.

## 2. The population is the obligation's own, and it is narrower than it looks

`pdf_archive::visible_widgets` is the reading, beside ADR 1234's other populations and for its
reason: a findings list is capped where a document's widgets are not, and this requirement reports
**one** finding at one flag. Three sentences narrow it, each from the base standard:

- **Visible.** §12.5.3's Table 167 makes `Hidden` and `NoView` the bits that keep an annotation off
  the screen, and the obligation is about the *visible* widgets. Giving marks to one its producer
  hid would be this converter deciding it should be seen.
- **Provides none.** §12.5.5's Table 170 makes `/N` the normal appearance. A widget that states one
  has been provided for, and its producer's bytes stay: §12.7.2 makes the consistency of a stated
  stream with its field's value the producer's obligation, and the file kept it. Rebuilding it
  would replace a producer's marks with this program's for no requirement at all.
- **Not a button.** §12.7.5.2.3 makes a check box's `/N` a subdictionary of one appearance per
  state, which the field's value selects among, and a file stating none says nothing about what
  those states look like. One stream written there would replace a set of states with a picture.

A widget the section 6.3.3 construction already writes for is skipped, so a widget in both
populations gets one `/AP`, not two writers racing for the key.

## 3. What cannot be built keeps the flag, by name

A widget whose appearance `pdf_model::appearance::for_annotation` cannot complete — a button, a
subtype whose clause states artwork this program cannot derive, one owing something — leaves the
site refused, and `Conversion::unconstructed` names the **field** it belongs to (§12.7.4.2's
name, the same one `pdf_model::view::Written::unconstructed` reports, because §12.7.4.1 lets one
field spread over two widgets). The alternative — clearing the flag for the rest — is the file
making the claim in section 1 while some widget still has nothing to draw.

## 4. What makes an XFA form dynamic is the document's own sentence

Annex K is normative and defines no test. It says the architecture exists because "the number of
fields needs to vary depending upon the quantity of entries", that "[t]he introduction of
dynamically generated pages guided by schemas is a considerable departure from the fixed page model
of PDF files", and — decisively for any attempt to read it off the pages — that "[w]hether or not
the pages generated by the processing of an XFA schema are materialized as PDF pages is
implementation dependent". The template that would settle it is XML `CLAUDE.md` excludes on the
annex's own permission.

What the base standard *does* state about this form is §7.7.2's Table 29, of `/NeedsRendering`:

> ( Optional; deprecated in PDF 2.0 ) A flag used to expedite the display of PDF documents
> containing XFA forms. It specifies whether the document shall be regenerated when the document is
> first opened. See Annex K, ' XFA forms ' . Default value: false .

A document stating it true says its own pages are regenerated before anybody reads them. That is
the dynamic case exactly, stated by the file, in the base standard, without reading a packet. One
stating it false or nothing states the default, and what a reader shows is the pages the file holds
— so the removal is safe there on Annex K's own consistency requirement: "The other entries in the
interactive form dictionary shall be consistent with the information in the XFA resource", and
"PDF interactive form field objects shall be present for each field specified in the XFA resource."
The AcroForm *is* the form, and what goes with the key is the behaviour the template carried.

**The honest limit**: a producer whose form is dynamic and who wrote no `/NeedsRendering` has stated
the default, and nothing in the file tells them apart. This reads what a document says; it does not
discover what a document omitted.

## 5. One sentence beside this becomes false, and it is deleted rather than annotated

ADR 0965 made `forms/no-needs-rendering` lossless partly on the ground that "a document whose form
dictionary still states an `/XFA` fails `forms/no-xfa-key`, which this converter refuses, so no
file this rewrite reaches is one where a reader had a form to regenerate." That refusal is gone.
The removal is still lossless, on the half of the argument that was always the load-bearing one —
the entry is deprecated, its default is `false`, and removing it states what an absent entry states
— and `Rewrite::NeedsRendering`'s comment now says only that. The two rewrites read the source, so
neither erases what the other's predicate is about.

## 6. What the operator chooses, and where the choice lives

`construct = true | false` at the appearance site and `dynamic = "stop" | <remedy>` at the XFA site
reach `ArchivePlan::forms`, a struct of two booleans rather than two remedy words, because at both
sites the *word* is `discard` and what is being chosen is what goes with the removal. `construct =
false` routes the decision to `Loss::FieldAppearances` through `Conditional::PerConfiguration`, a
new kind beside ADR 1210's `PerDocument`: the answer is lossless under one of a site's answers and
a loss under the other, and which it is the **operator** says rather than the file.
