# 3056 — A time-stamp token's own path is asked by clause 9.5 as the signer's is

Session 2089, a signatures round (`doc/todo/77` section 2 item 3). Status: implemented. Rows:
§12.8.3.4.5. Context: ADRs 2928 (its items 2 and 4, which this extends), 2878, 2996; ETSI TS 119 312
V2.1.1 (2026-06) clauses 9.4 and 9.5; ETSI TS 119 172-4 REQ-4.5-01 h); RFC 3161 section 2.4.1;
RFC 5280 section 6.1. Cited by clause and paraphrased (ADR 1085).

## Context

Clause 9.5 names "TSU keys" and "CA keys" among the other keys, each to resist over its own
certificate's validity and that of the certificates relying on it, and each at least as strong as
the keys it certifies. ADR 2928 asked a token's unit over its own certificate and nothing above it:
`timestamp::Time::Established` dropped the path step 4 validated (`Trust::Anchored { .. }`), so the
unit's issuer was not carried and the unit was in no pair.

## Decision

1. **The token's path is carried where its time was established.** `Time::Established` gains `keys`
   and `responders`, `Trust::Anchored`'s own, so the path is the one RFC 5280 section 6.1 validated
   from the unit's certificate to the anchor that established the time, the reader's or a listed
   service's (ADR 2878) — never a path assembled from whatever certificates the token carried.
2. **Where no path validated, the unit alone is asked**, as before: no issuer is known to the
   report, because an unvalidated chain names a certificate nobody vouched for.
3. **The unit's key keeps the token's padding.** A path's first key saw no signature of its own, so
   its `rsaEncryption` row would be unread; the token's `SignerInfo` signature is the one the unit
   made, and it decides Table 2's row (ADR 2928 item 1).
4. **Roles mirror the signer's path.** `KeyRole::TimeStampingAuthority { position }` is an authority
   on the token's path, the unit at 0; its period runs to the latest `notAfter` at or below it, it
   certifies the key one below, and families are compared as ADR 2928 item 4 says. The anchor is
   clause 9.4's and is not asked here (ADR 3058).

## Consequences

`Report::of` asks each established token's authorities and pairs, over document timestamps and the
signature timestamp attribute alike. The fixture is `crates/pdf-signature/tests/fixtures/token_path/`,
generated by its `generate.sh` (a test root, a 2048-bit intermediate, a 3072-bit unit) and asked in
`a_tokens_own_path_and_its_responders_are_asked_by_clause_9_5_in_the_report`; with no anchor the same
document asks the unit alone. Two tokens from one unit ask its path twice, once per token.
