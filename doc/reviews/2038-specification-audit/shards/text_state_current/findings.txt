Text state and text object audit (baseline b901326c)

The reviewed source is ISO 32000-2:2020(E), not an older wording: footer-bearing physical pages 315–326 correspond to printed pages 300–311 (physical = printed + 15). The primary page ranges relevant here are §9.3.1–.4, physical pp.315–318; §9.3.5–.8, physical pp.318–321; §9.4.1, pp.321–322; §9.4.2, pp.322–324; §9.4.3, pp.324–325; and §9.4.4, pp.325–326. The exact footer was checked on each page. EC3 changes checked: #368 adds text-matrix save/restore to q/Q within BT…ET; #373 corrects the T* expansion from TD to Td; #376 normalizes Tz's percentage to Th and changes §9.4.4 NOTE 2's Trm description to normative text. The corresponding EC3 records are summarized in `doc/errata-read.md`; the source collection itself is `doc/ISO_32000-2_sponsored_EC3.pdf`.

**Concrete ledger correction.** The §9.3.2 ledger note says “The vertical branch does not exist because no writing mode 1 does.” That is contradicted by the defining §9.3.2 text on physical p.317, which says Tc is added to the horizontal or vertical displacement, and by this implementation's actual vertical font path. `text_state_residual_audit.rs::vertical_spacing_rise_and_horizontal_scale_keep_distinct_axes` checks vertical Tc, Tw and Tz with an embedded font, but the ledger test list for §9.3.2 only names the horizontal Tc test. The row should describe both writing modes and name the vertical assertion. This is an evidence-note defect, not a detected code defect.

**Word spacing.** Physical p.317 expressly distinguishes single-byte code 32 from byte value 32 inside multibyte codes. `Code::takes_word_spacing` checks both code value and encoded length; `show.rs::advance_past` consults it before Tw. The simple-font positive consumer test asserts a +50 placement shift. The negative composite test asserts identical placements but can return early on machines without a substitute face. The embedded vertical Type0 fixture proves Tw on a one-byte composite code, but not the multibyte negative. `drafts/text_state_vertical_spacing_and_tj.rs` supplies an exact-xref Type0/embedded-font draft comparing both code lengths. It is unexecuted; validate its mixed-length CMap syntax in the parent's run before treating it as an accepted fixture.

**Horizontal scaling and spacing.** Physical pp.317–318 plus EC3 #376 require the normalized factor to scale glyph shape and horizontal displacement in either writing mode, and, only for horizontal writing, Tc, Tw and numeric TJ. Current code's Tz is `percent / 100`; `glyph_to_text` scales glyph x, horizontal position/advance includes Th, and vertical advance/TJ avoids Th. Tests directly assert the horizontal Tc and TJ step ratios and the vertical font's halved horizontal extent while preserving vertical Tc+Tw displacement. There is no direct horizontal outline-width assertion in the inspected text-state tests, so shape coverage is strongest in the vertical-font case. No code discrepancy was found.

**Rise, leading and rendering mode.** Physical pp.318–320 require unscaled rise and leading movement; tests assert rise across sizes and T* positioning. For clipping, glyphs accumulate through ET and the clip is applied after paint; no outlines mean no new clip. `text_clipping_audit.rs::modes_five_and_six_paint_both_shows_before_the_text_clip_takes_effect` distinguishes deferred clipping using two shows and later paint. `text_render_modes.rs` covers Table 104 modes and empty outline cases; vertical rise is also tested in the embedded vertical fixture. Implementation at `text/end_object.rs` applies a nonzero clip at ET and leaves state unchanged on an empty path. This bounded review did not exhaust every compositing/clip interaction.

**Matrices and positioning.** Table 106 on physical pp.323–324 owns Td, TD, Tm and T*. The implementation assigns Tm/Tlm directly on Tm (replace), applies TD's leading side effect, and computes T* by moving Tlm then copying it into Tm. EC3 #373 changes only the descriptive operator token in the T* row; the arithmetic is unchanged. `text_positioning_audit.rs` has exact-xref Type3 public-placement tests for TJ, T*, Tm replacement, quotes and q/Q line restoration. EC3 #368's graphics stack semantics are implemented together in `run/graphics.rs` and are asserted by `text_state.rs::q_and_q_save_the_text_matrices_inside_a_text_object` and `text_positioning_audit.rs::q_restore_recovers_the_line_matrix_used_by_the_next_line_operator`. However, those targeted tests are absent from the ledger test arrays for 9.4.1/9.4.2; named evidence should be reconciled. ADRs 0421 and 0548 correctly distinguish this synthetic valid-rule test from damaged corpus examples and identify the added requirement.

**TJ vertical evidence gap.** Table 107 on physical p.324 says numeric TJ is subtracted from the current coordinate for the writing mode; §9.4.4 on pp.325–326 gives vertical `ty = (w1 − Tj/1000)Tfs + Tc + Tw`. `run_text_showing_op` follows that formula and gates Th to horizontal mode. Existing public numeric TJ tests verify horizontal positive subtraction and horizontal Tz scaling. Existing vertical font tests verify ordinary W2 advance, not the numeric TJ term. The draft supplies an independent expected displacement: W2=-1000 at 20 pt advances -20; positive TJ=250 changes the next vertical displacement by -5, and 50% Tz must leave that vertical adjustment unchanged. This is a focused coverage gap, not a demonstrated implementation failure.

**Decision boundaries.** ADR 0022's fill/stroke/clip decomposition agrees with §9.3.6 and the tests inspected. ADR 0746's #376 reading is supported. ADR 1490's inferred readback word-gap threshold is policy and was not used to judge explicit Tw/TJ behavior here. No API-level host warning or font substitution behavior is part of this shard.

No Cargo command or test execution was performed; parent execution evidence remains separate. The JSON records the feature-level evidence, ledger mappings, and limits. The draft is not promoted or counted as passing.
