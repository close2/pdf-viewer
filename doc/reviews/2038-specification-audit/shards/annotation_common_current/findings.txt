Bounded audit covers §§12.5.2–12.5.5 common dictionaries, flags, border/BS/BE, appearance selection, and selected Rect placement. It does not re-audit subtype families. Effective source: ISO 32000-2 primary plus EC3; processed Markdown omits annotations. Verified printed/physical locator pairs from the primary page footer: §12.5.2/Table166 printed pp.467–470, physical pp.482–485; Table167 printed pp.471–472, physical pp.486–487; Table168 printed pp.473–474, physical pp.488–489; Table169 and start of §12.5.5 printed p.474, physical p.489; appearance mapping/compositing continues beyond there.

The main interactions are present in current code. `stored_appearance` resolves N/R/D, falls back to N for missing rollover/down, uses AS for state dictionaries, and returns `StateNotDefined` where no state exists. Existing raster tests use distinct colors for N/R/D and On/Off; printing is checked to stay on N even with a pressed pointer. The source asks for reasonable behavior for unknown AS (display nothing is an example), so the reader's empty result is within the clause.

AP rules need a producer/reader distinction. EC3 #22 requires AP for PDF 2.0 producers except the listed degenerate Rect and Popup/Projection/Link cases; #34 says a missing AP's rendered appearance is implementation-dependent. Current derived appearances for some subtypes are a permissible local choice and not a universal mandatory fallback. Likewise a writer's required Rect/Subtype does not automatically imply a reader must reject malformed dictionaries.

Table167 visibility uses separate screen and print conditions. Current tests assert both screen and paper for Print, Hidden and NoView combinations; the missing-AP Print exception has controls where a valid AP stream changes whether the Print bit applies; a state-dictionary stream with AS selecting no state still counts as an appearance stream. ToggleNoView is exercised through hover/pointer state. The table also says selected; current view APIs expose Over/Down but no independent persistent annotation-selection state was found, so report that as a product-surface residual rather than a confirmed ISO defect. NoZoom and NoRotate code applies exact cardinal transforms around Rect's upper-left point. Existing assertions cover 90-degree NoRotate with exact extent and NoZoom at 2x, 0.5x and unspecified zoom; other rotation branches are not independently pixel-tested. Text says these properties are on screen, so print behavior should not be held to a screen-only clause as a conformance defect.

For borders, EC3 #287 strengthens Table166's /BS precedence to `shall be ignored`. Current `Border::geometry` drops all /Border geometry if /BS exists; old regression asserts /Border-only rounded vs /BS square and identifies the historical radius leak. Since /Border and /BS widths match in that focused regression, it proves the radius case but not all components in isolation. `drafts/bs_precedence_ignores_entire_border_entry.rs` adds conflicting Border width, radius and dash with a BS-only control and a Border-only control. It has exact xref and asserts no recovery; it is unrun.

Table168 defaults have concrete differential pixel coverage: omitted dashed /D equals explicit [3], differs from [1 3], and compares against independent phase-zero page stroke. Unknown style solid fallback, zero width, underline containment and cloudy BS width/dash have assertions. B/I relief colors and cloud geometry are local choices where the table gives no colors/curve; they are not ISO-specified expected pixels.

EC3 #23/#34 remove BM from the Table166 ignore list; #56 adds MK. Code passes BM to both stored and constructed annotation appearances while opacity CA/ca is only a constructed-appearance input. The `stored-vs-constructed opacity` test covers opacity, but I found no dedicated stored AP pixel test isolating /BM. This is a targeted test coverage gap, not proof of a rendering bug. The feature row records the limit and does not assert that every ignore-list entry has an independent test.
