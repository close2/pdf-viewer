# Structured interactive errata candidates: source and consumer disposition

## Method and scope

I opened the primary `doc/ISO_32000-2_sponsored_EC3.pdf` in the audit worktree, enumerated the listed `/Subj` annotations through pikepdf, inspected the `Contents`, `/IRT` relation and redline geometry, and compared the corrected words to the printed page context. Physical PDF page / printed ISO page pairs below come from the source footers. These issue IDs were discovery pointers, not presumed defects. I then checked current ledger rows, source call paths, and the actual named assertion owners. No Cargo or test run was performed; no new draft is warranted by these cases.

## Material source-to-ledger correction

The important stale claim is in `doc/conformance/ledger.toml`'s §12.5.1 aggregate note, nested within the §12.5.6.18 Screen row. It quotes the effective rule as “If AP is not present, the screen annotation shall not have a default visual appearance and shall not be printed.” That entire sentence is crossed out by EC3 Issue #42 at physical p.513 / printed p.498 (StrikeOut object 5349, followed by the PDF Association completion note 5351). The struck text is not a surviving limitation or a current `shall`. The adjacent `/P` sentence is untouched: a Screen annotation referenced by a Rendition action shall reference a valid Page object and shall occur in that page's `/Annots` array. That rule is separately reviewed by `rendition_preconditions_current`; #42 does not change it.

I do not infer that removing the sentence requires a reader to synthesize an appearance or to print an AP-less Screen annotation. The surviving preceding text says a supplied Screen `/AP` normal appearance is used for printing and default display when a media clip is not being played. The old no-AP outcome has been removed, but no replacement reader action appears in this overlay. Thus the ledger's precise source citation is stale, while this bounded review does not establish a substitute behavior obligation or a runtime defect. The rest of #42 is already handled by `annotation_remaining_current`: at physical p.499 / printed p.484 it strikes “if present,” in FreeText Table 177's AP-precedence phrase (StrikeOut object 5193); at p.520 / printed p.505 it removes the whole Projection zero-Rect AP prohibition (object 13474). Issue #94 on that latter page inserts “, and thus an AP dictionary is not required” after Projection's associated-runtime sentence (Caret object 13478). These overlays are related but distinct; #94 does not restore the struck Screen rule.

## Remaining issue dispositions

- **#477, physical 471 / printed 456:** the StrikeOut/Caret pair replaces the heading `12.3.6 Navigators` with `12.3.5.3 Collection navigators`; the Caret's editorial contents explicitly say all of the old subclause was moved/demoted. This is an effective-numbering correction, not another layout algorithm. The current `collections` shard covers layout preference and host cells, including its separately identified missing schema values; no duplicate finding here.
- **#386, physical 551 / printed 536:** the StrikeOut is on §12.7.5.2.2 Push-buttons, not Check boxes. It removes the sentence forbidding `/V` and `/DV` entries, with no replacement. The surviving push-button definition says the control retains no permanent value. Current reader code classifies Pushbutton separately from toggling fields; the ledger's Push-buttons row records the deletion. This loosens a producer restriction and does not create a reader rejection or value-retention duty. The broader `interactive_framing_current` scratch text misattributes #386 to check boxes and should be corrected before reuse.
- **#131, physical 560 / printed 545:** Table 236 `/P` receives a Caret carve-out for incremental updates containing only DSS and/or document timestamp data. The existing `forms_remaining_current` and signature-transform review distinguish the field-lock /P rule from DocMDP B18. This is not a second general permission or a request to ignore arbitrary changes.
- **#176, physical 572 / printed 557:** Caret inserts `application/fdf, or the deprecated alias` before `application/vnd.fdf`; the source permits both spellings and marks `application/vnd.fdf` deprecated. A separate IANA note identifies the alias. `viewer-host/src/submit.rs::FDF_TYPES` accepts both literal names, and `::an_fdf_answer_is_imported_under_either_name` checks both through the HTTP-reply-to-FDF import route. The assertion is direct and discriminating, so no draft is needed.
- **#54, physical 582 / printed 567:** StrikeOut corrects the typo `attrib0ute` in the PrintField sentence of §12.7.9. No behavioral effect.
- **#685, physical 582 / printed 567:** StrikeOut removes only `for annotations in FDF files)` from Table 254 `/Page`; `Required` survives. The table title already scopes it to the additional entries for annotation dictionaries in an FDF file. This neither deletes the required status nor adds a Page entry for unrelated FDF objects.
- **#55, physical 583 / printed 568:** Caret inserts that approval signatures “shall follow the certification signature if one is present.” It adds a producer ordering constraint. The source does not in this insertion direct a PDF reader to reject, reorder, or issue a warning for a violating file. `signature_framing_current` already records that distinction.
- **#121, physical 584 / printed 569:** Table 255 Filter loses only the word `inheritable`; it remains Required. `pdf-signature/src/signature.rs::read` reads `Filter` directly from the signature dictionary passed to it and does not consult field ancestors. This is consistent with the erratum. I do not infer a malformed-signature rejection obligation from the writer-facing table entry.
- **#33, physical 592 / printed 577:** the two bare Carets insert `fully qualified` and a §12.7.4.2 reference into Table 259 `/Fields`. The source requires the listed field-name strings to be fully qualified. As `qualified_failure_second_review_current` already explains, that does not specify how identity is tracked across signed/current revisions after `/T` changes, and its test is not an authenticated signature. Preserve the prior B42 qualification; no new defect.

## Tests, ADRs and limits

Relevant previous owners are `annotation_remaining_current` / `rendition_preconditions_current` for #42/#94, `collections` for #477, `forms_remaining_current` and `signatures_transforms` for #131, `signature_framing_current` for #55/#121, and `field_mdp_identity_current` plus `qualified_failure_second_review_current` for #33. They cover the substantive cases or already state their limits. The only notable current ledger discrepancy surfaced here is the obsolete Screen missing-AP sentence; it changes the source description but does not on its own demonstrate a behavior failure. The issue #386 subtype description in aggregate scratch is also wrong and should say Push-buttons.

I reviewed no unrelated Adobe/XFA implementation, no external 3D runtime, no signature trust policy, and no broad FDF writer conformance. No new Rust test is drafted: the actionable MIME alias already has literal host-route coverage; other corrections are editorial, producer-side, already owned by sibling shards, or do not establish a missing reader mandate. Parent should reconcile the stale ledger quote against EC3 before treating §12.5.6.18's reported status as evidence for that deleted sentence.
