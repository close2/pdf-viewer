# Transparency foundations review

This is a bounded review of effective ISO 32000-2 EC3 §§11.3.1–.2, 11.4.1–.3, 11.5.1–.2, and 11.6.1. The formula images and surrounding requirements were read from the primary PDF, then checked against actual reader/interpreter/backend code and assertion bodies. No tests were run and no tracked code or ledger changes were made. The prior transparency groups and compositing shards were consulted to avoid duplicating their numeric tests.

## Source and formula reading

§11.3.1 (physical 404, printed 389) introduces compositing of a single object with its backdrop and says §11.4 extends it to multiple-object groups. It states no independent SHALL. §11.3.2 (physical 404–405, printed 389–390) defines lowercase scalars, uppercase vectors, shape `f`, opacity `q`, and alpha as their product. It separately requires that undefined values not cause overflow/division-by-zero malfunction and mandates `0 ÷ 0 = 0`. Its stated rationale is that an undefined intermediate has no effect after it is multiplied by zero or cancelled.

The formula at §11.3.3 (physical 405, printed 390) is read from the primary page, not reconstructed from the markdown placeholder:

`Cr = (1 − αs/αr) Cb + (αs/αr) ((1 − αb) Cs + αb B(Cb,Cs))`.

The result alpha is the union `αr = αb + αs − αb αs`; multiplying the displayed colour expression by `αr` yields the premultiplied expression used by CPU `blend::composite`: `(1−αs) cb + (1−αb) cs + αs αb B(Cb,Cs)`. That transformation avoids division by result alpha. When source alpha is zero the CPU path skips the pixel; when a source is present over a zero-alpha backdrop, the straight backdrop color accessor returns zero for the `0/0` case. Inputs/outputs are byte-bounded and normalized before the blend arithmetic, so the cited code avoids both exceptional division and nonfinite color propagation in this case. The existing valid-PDF regression `compositing_notation.rs::a_blend_over_an_undefined_backdrop_is_the_source_and_the_next_blends_over_the_result` exercises a first Hue blend over the isolated group's transparent initial backdrop, then a blue Multiply mark over that first result. The independently simple expected samples are red, blue, and black at the first-only, second-only, and overlap pixels; white outside controls the page. This is a real PDF with calculated classic xref offsets and requires a complete interpretation. It tests the observable zero-backdrop and recurrence cases, not every possible undefined operand or backend arithmetic path.

§11.4.1 (physical 417–418, printed 402–403) requires the grouped objects be collected into a separate stack, yield a color/shape/opacity at each point, and later act as one object. It names the initial-backdrop choice and isolation/knockout behavior; a group's ability to have an independent blending space or to supply a mask is presented as an additional attribute/permission, with the actual requirements elsewhere. The primary §11.4.2 recurrence (physical 418–419, printed 403–404) indexes elements bottom-to-top and uses the previous element's result as the next one's immediate backdrop. Its formula set recurs for color, shape, opacity, and alpha; group formulas add the distinction between the group's accumulated alpha and the complete alpha including its initial backdrop. §11.4.3 (physical 419–420, printed 404–405) names group, initial, and immediate backdrops, describes recursive stack/tree processing, and requires the backdrop's contribution to the final result be applied only once.

The current implementation has corresponding observable branches. `pdf-model` forms a nested `Command::Group`; CPU `groups.rs::draw_group` buffers the group and blits it once. An isolated group's initial backdrop is transparent; a non-isolated group is seeded from the enclosing surface. For the optimized non-isolated/non-knockout/Normal case, ADR 0237 reduces the two compositing steps to `(1−w)B+wE(B)` and CPU interpolates the original surface and buffer. Non-Normal groups instead remove the backdrop and compose the result as a single object. The non-isolated knockout case takes its separately constructed route, while `knockout.rs` maintains the initial and immediate backdrops separately when an element's shape is needed. This is not a blanket implementation of the general recurrence by one raster: each optimized branch has a restricted premise.

The existing §11.4 assertions are discriminating, not just mode-name coverage. `a_group_is_composited_once_rather_than_object_by_object` uses two opaque red rectangles under caller `/ca 0.5`; the overlap equals the single-covered region at `[255,127,127,255]`. An otherwise identical ordinary form (no Transparency `/Group`) is the control and has a different overlap. Other current tests distinguish non-isolated from isolated backdrop, knockout from non-knockout, and group opacity from group shape in a knockout consumer. The latter matters: ordinary alpha pixels do not prove the separately named unioned shape. Prior `transparency_groups_current` reviewed these cases, including shape-only consumption; this pass does not recertify every group formula or blending space.

## Soft masks

§11.5.1 (physical 429, printed 414) describes soft-mask shape/opacity as an independent source that can vary by position. NOTE 1 explains fractional intermediate values; NOTE 2 compares a shape mask to a generalized clipping path. The current `SoftMask` object is attached to commands and evaluated at raster resolution; both backend routes share the mask-value derivation. A CPU control uses a literal 0.75 luminosity mask and hand-computes the interpolation of a red object over grey. The image/soft-mask integration tests cover per-object use. `/AIS` determines whether a mask is shape or opacity under §11.6.4.3 and is deliberately outside this foundation clause.

§11.5.2 (same physical/printed page) requires the group be evaluated by the usual group formula over an arbitrary backdrop whose contribution is factored out; its resulting alpha is then transformed through the mask transfer function. NOTE 1 says the color need not be computed; NOTE 2 explicitly fixes empty-group shape and alpha at zero. The public PDF test `soft_masks.rs::an_alpha_mask_reads_the_groups_alpha_and_ignores_its_colour` uses two same-black regions whose group's own resources assign `/ca 0.25` and `/ca 0.75`; it expects remaining white values 191 and 64, and checks outside the group BBox where alpha is zero. A `/BC` is present to show it is irrelevant to `/S /Alpha`. This is a strong positive alpha-vs-color distinction. A separate valid luminosity-empty-group test covers `/BC`/§11.5.3 behavior, and therefore should not be counted as a direct assertion of this clause's empty-alpha NOTE.

There is a narrower assertion gap. I did not find a public PDF fixture that has an actually empty `/S /Alpha` group and asserts its alpha-derived mask is zero. The direct mask unit does test alpha extraction and `/TR`; the general PDF `/TR` test covers a luminosity mask. I drafted two source-derived PDF tests under `drafts/`: an empty alpha group with an unmasked black control, and a type-2 inverse transfer applied to a `/ca 0.25` alpha group through the public PDF path. For the latter `1−0.25=0.75` black opacity gives byte 64 inside the group's BBox, and the outside zero alpha maps to one, yielding black there. Both use the existing `soft_masks.rs` fixture builder, whose objects and classic xref are constructed exactly; draft tests additionally assert the parser did not recover. These are unexecuted candidates, not claimed failures or passing evidence.

## Errata, ledger, and limits

The clause inventory currently marks these rows `implemented`. The ledger's 11.3.1 and 11.6.1 notes describe introductory sentences; they state no standalone SHALL, so their `implemented` convention must not be read as certifying all child clauses from the named representative test. For 11.3.2, one valid isolated-group zero-alpha/recurrence test is appropriately targeted but leaves numeric bounds and backend coverage partial in evidence, even though the behavior is currently implemented. 11.4.1–.3 are backed by the specific overlap, group-backdrop, and knockout shape controls above; the assertions do not exhaust all general group formula combinations. §11.5.1 has a fractional-mask pixel assertion, and 11.5.2 has a strong alpha-vs-color test but lacks an empty public Alpha group assertion and a PDF Alpha `/TR` end-to-end assertion.

No errata listed in `doc/errata-read.md` directly amend the assigned clauses. EC3 #345 annotates Figures 72–73 on physical pp.407–408 (printed pp.392–393) as illustrative rather than pixel/color-precise; this audit does not use those images as numeric oracles. EC3 #688 corrects two alpha symbols in §11.4.8's later summary on physical p.428 / printed p.413; it does not alter the §11.4.2 recurrence reviewed here, but any summary transcription should use α. No equations were certified by comparing an implementation to a shared or second renderer.

Residuals are explicit: no full independent numeric walk over arbitrary group stacks, no cross-backend audit, and no exhaustive review of all shape/opacity factor combinations. Earlier §11.3.3 partial-alpha tests and B39 stroke-composition consumer coverage are not repeated. The two drafts address only the directly evidenced §11.5.2 test gap.
