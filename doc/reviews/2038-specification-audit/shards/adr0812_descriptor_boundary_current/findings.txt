# ADR 0812 descriptor boundary review

**Disposition: agree with the descriptor transport/confinement decision; qualify one test comment and treat partial-frame EOF as a transport-policy residual.** I found no PDF-conformance defect in this boundary.

ISO 32000-2 §7.5.1, §7.5.4 and §7.5.5 use byte offsets to locate file structures. Annex C.4 is informative guidance about traditional cross-reference offsets. §12.8.1 uses declared byte ranges for signature processing. None of these provisions requires a file descriptor, `SCM_RIGHTS`, a Unix socket, `pread`, a seccomp allow-list, an eight-descriptor limit, or a host-versus-worker split. ADR 0812 adopts those as local confinement and memory policies while keeping the parser's byte-addressed file view intact. The signature digest implementation is not re-certified here; the signature shards own that question.

The actual route is coherent end to end. The host opens the document into `FileBytes`; `command_descriptor` borrows that held descriptor for an on-disk Open and the wire payload carries its length. The host sends the frame header with `SCM_RIGHTS`; the worker receives the `OwnedFd`, consumes one descriptor only for the command that claims it, wraps it with the stated length, and drops leftovers. No worker path lookup or stat is involved. If the descriptor is missing, the decoder reports `NoDescriptor`; file-backed input on an unsupported route is reported `Uncarried`. The frame reader checks the budget before allocating the payload, drops descriptors for an unaffordable frame, and skips the payload to preserve framing.

Evidence is stronger than a protocol roundtrip alone. `viewer-confined/tests/confined.rs::a_document_open_on_disk_crosses_as_a_descriptor_and_draws_the_same_page` sends the real on-disk `FileBytes` through the sandboxed worker, checks five pages, compares every output pixel with the memory route, and requires visible ink. Kernel probes independently allow positional reads and kill metadata/stat access. `pdf-syntax::a_handed_file_is_read_to_the_length_its_opener_stated` checks exact, shorter, and longer declared lengths against a ten-byte file; a shorter stated length clips reads, and a longer length produces a short physical read rather than fabricating bytes. The protocol command test checks ON_DISK length encoding, no-document-bytes-on-wire, missing-descriptor refusal, descriptor consumption, actual content, and the memory-byte route. Worker code drops unclaimed/excess descriptors.

There is one narrow evidence wording issue: the protocol test comment calls its supplied FD the kernel duplicate of the held document descriptor, but the test independently calls `File::open` on the same path. That is not the same open-file-description identity check. The production encoder does return the held `FileBytes::descriptor()` itself, and the confined end-to-end route uses that encoder, so this does not undermine the design. A useful optional test strengthening is to hold `FileBytes::on_disk`, unlink its path, then send it through the existing confined rendering comparison; success would make it explicit that the opened object, not a re-opened path, crosses. I have left a tiny draft in `drafts/descriptor_identity_optional.md`; it is an assurance improvement, not a newly established normative failure.

`read_frame` maps `UnexpectedEof` while filling a fixed header to end-of-input. If the header is partially present this is indistinguishable there from clean EOF; payload truncation instead propagates as an I/O error. The host treats EOF on worker output as worker death. This is worth keeping visible as a transport-contract question, but I found no PDF rule requiring a different behavior and no evidence that it currently changes a PDF result or silently claims a valid document.

No tests were executed for this review. Parent should run any optional draft only if the stronger descriptor-identity demonstration is useful; no production change is recommended from this evidence.
