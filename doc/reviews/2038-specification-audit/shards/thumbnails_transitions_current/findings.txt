# Thumbnail images and page transitions

## Boundaries and source

This review covers §12.3.4, “Thumbnail images” and §12.4.4.1, “General” within §12.4.4, “Presentations”; it does not certify the whole sections or §12.4.4.2's sub-page navigation. The effective source is `doc/ISO_32000-2_sponsored_EC3.pdf`; `doc/md/ISO_32000-2_sponsored_EC3.md` is useful for navigation but its table conversion omits the `/Di` default row, so the PDF is authoritative for that detail.

§12.3.4 is at physical p.462 / printed p.447. It permits documents to omit thumbnails and permits an interactive processor to display a thumbnail and navigate when clicked. For a stated page `/Thumb`, it specifies an image XObject and names the five significant image dictionary entries; the rest of Table 87 is ignored. The source also constrains a stated `/Subtype` to `/Image` and the thumbnail color space to DeviceGray, DeviceRGB, or Indexed based on one of those. These are principally producer constraints. They do not authorize a reader to discard a valid thumbnail merely because a producer constraint was violated, and they do not require every processor to expose a thumbnails UI.

§12.4.4.1 begins at physical p.476 / printed p.461. It defines page `/Trans` and `/Dur` as optional entries describing presentation-mode behavior. `/Trans` specifies the effect for arrival at its page, and Table 164 NOTE 2 confirms that the destination page's transition controls the transition into it. `/Dur` is a maximum display time before the presentation advances; NOTE 1 allows earlier manual advance. The explicit omission rule says a page without `/Dur` shall not advance automatically. Page duration is not an always-on document timer: this implementation applies it only in presentation mode, consistent with the clause's context and description of those entries.

Table 164 spans physical pp.476–478 / printed pp.461–463. It defines `/S`'s twelve named effects, default `R`, `/D` default one second, the style-scoped `/Dm`, `/M`, `/Di`, `/SS`, and `/B` values/defaults. `R` is an immediate replacement and ignores `/D`. `/Di` has default zero in the primary PDF. EC3 Issue #36 changes its type from number to integer; the current model deliberately retains fractional angles as permissive behavior for non-conforming input, as `navigation.rs` documents. This is not a claim that fractional `/Di` is producer-conforming. Issue #75 is the recorded capitalization/spelling correction. The EC3 sweep recorded in `doc/errata-read.md` found these two issues and no other annotations against §12.4.4; I found no EC3 change to the thumbnail clause in the effective text.

## Implementation and assertion evidence

For thumbnails, `pdf-model::thumbnail::read` retains only Width, Height, ColorSpace, BitsPerComponent, and Decode from the image dictionary before decoding. Its `SIGNIFICANT`/`IGNORED` handling preserves stream-level Filter and Length. It separately records whether color space and any stated subtype are permitted instead of using those producer constraints to reject an otherwise decodable image. `viewer-core` answers `Query::Thumbnail(page)` from the page tree; `viewer-host::page_entry` consumes that query per visible row, and the page panel draws the returned raster. This is a real public host route, not just an internal decoder test.

The strongest independent pixel check is `an_ignored_soft_mask_does_not_reach_the_pixels`: a control thumbnail has expected opaque red/green samples; adding a zero-valued `/SMask` must not make them transparent, while adding significant `/Decode` must invert samples to cyan/magenta. `only_the_five_significant_entries_of_table_87_survive` checks significant versus selected ignored keys and verifies that Filter/Length remain. The Indexed color-space case is accepted; a CalRGB sample is decoded and flagged as outside the source's permitted set rather than refused. `viewer-host/tests/host_mappings.rs::a_page_stating_a_thumb_gives_its_row_the_image` reaches the public page-entry route and asserts the expected dimensions and red/blue pixels. The PDF.js corpus test is a sanity sample against the same document's page rendering, not an independent normative oracle. The UI panel test verifies that supplied miniature ink appears and that clicking a row maps to its page, but it supplies an already-decoded mock miniature; the host mapping test separately validates the actual query/decoder route.

The thumbnail reader does not surface a decode error through the public query. `ADR 0794` records that damaged thumbnails have no per-image report channel and are omitted on decode failure. That is a reporting limitation for malformed data, not a claim that the clause requires repair behavior or that corrupt producers conform. The bounded assertions give good evidence for the critical ignored-mask/Decode distinction and public pixel route; they do not individually prove every Table 87 entry is ignored, but the implementation enumerates those keys. I found no standards-backed need to add a broad mirror-of-the-list test in this shard.

For presentations, `pdf-model::navigation::transition` constructs Table 164 defaults and preserves the `R` special case. The example test reads the source's five-second page, 3.5-second vertical outward Split. Tests assert no inheritance of `/Dur` or `/Trans` from a parent Pages node; a public Viewer test checks a stated duration has no effect outside presentation, while another checks it advances at the maximum, resets the clock, and emits the incoming page's Wipe. `presentations_audit.rs` covers defaults and explicit style-scoped parameters, the `/R` duration rule, and many Table 165 interactions. The pure transition tests cover the actual effects; `ADR 1299` records the four former refusals superseded by explicit owner-selected quantities (8 Blinds lines, 40 long-edge Dissolve cells, Glitter band width .25, and Fly's changed-pixel rectangle). Those quantities and the intermediate frame curve are implementation choices, not numeric claims from Table 164. Host clock work (`ADR 0473`) and presentation gating (`ADR 0316`, `ADR 1702`) provide the elapsed-time route; native window rendering/execution remains the parent's gate and is not asserted here.

I found one narrow assertion gap: `display_duration` distinguishes an absent value as `None`, but I found no public runtime test proving that a non-final page with no `/Dur` stays put for a long presentation tick. Current runtime controls cover a page with a stated `/Dur`, a last page with a stated duration, and non-presenting behavior. A final-page test cannot prove the omission rule because the implementation has a separate end-of-document guard. The standalone draft `drafts/omitted_page_duration.rs` supplies a non-final missing-value case between two stated-duration positive controls. It uses a complete exact-xref four-page PDF with a trailer ID, so the expected absence behavior cannot pass only because parsing used recovery or because the document ended. The parent should compile/run it before treating execution as evidence.

## Selected ADR disposition and remaining scope

`decisions.json` records only directly relevant ADR reviews. ADR 0230's refusal of four styles is superseded by ADR 1299; do not revive that refusal from the historical text in 0230. ADRs 0316, 0473, and 1702 are consistent with presentation-mode timing and injected clock ticks. ADRs 0564/0576 concern the chosen thumbnail panel/API surface and do not create a source requirement for a list query or universal pane. ADR 0794 concerns malformed thumbnail reporting and does not change valid-image semantics.

Remaining work is to compile and execute the omitted-page-duration draft, and to complete the parent's Xvfb/native host gate for the host-window behavior. This audit did not independently validate every numeric/default branch of Table 164, every ignored Table 87 key on the public route, each native window under Xvfb, or all of §12.4.4.2.
