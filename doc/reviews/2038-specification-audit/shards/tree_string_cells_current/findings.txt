Table 35 summarizes context-qualified values. EC3 #322 annotates its type descriptions on physical p.130; the primary and its overlay show Table 35. The current `doc/errata-read.md` row for #322 says “Table 39,” a stale table number. The body of §7.9.2.1 remains clear that a PDF has one fundamental string object, further qualified as text, ASCII, or byte string by context. Current code keeps the bytes in Object::String and uses context-specific decoding; test bodies cover PDFDocEncoding, UTF-16 surrogate pairs, UTF-8 stream/string parity through a visible field appearance, and FDF Status's specifically PDFDocEncoded route. §7.9.1 separately says hierarchy strings are not content-stream glyph codes. Language escapes and the previously failing Alt/E consumer cases are outside this bounded review.

For dates, the effective §7.9.4 fields, defaults, offset sign/hour/minute, Note 2's recommended legacy apostrophe, and Note 3's Z/zero-offset rule are represented by named parser tests and the timezone suffix test. The example and the collection comparator test independently show that offset-bearing strings order by represented instant rather than lexical spelling. EC3 #251 at physical p.133 / printed p.118 replaces the absent-zone sentence with an equivalent explicit +0'00 formulation and deletes the separate local-time sentence. The code retains whether an offset was stated while using zero in instant arithmetic when absent. T01's writer-side regression no longer relies solely on the same parser to classify invalid examples. The remaining Gregorian month-day restriction beyond DD 01–31 is already classified as an interpretation question in current findings; this shard adds no new normative conclusion.
