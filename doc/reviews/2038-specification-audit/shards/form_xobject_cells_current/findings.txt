# Form XObject dictionary and resource cells (baseline b901326c)

The Table 93 mapping is complete at the cell inventory level. Primary-source footers put Table 93 on physical pages 287–288 (printed 272–273), immediately after §8.10.1 on physical 286/printed 271. Its current ledger rows 8.10 and 8.10.1–.3 are implemented; the aggregate has no extra clause text. I read the primary annotations rather than relying only on `errata-read.md`: EC3 #292 changes Resources, #291 points to Annex F, and #463 adds the StructParent/StructParents mutual-exclusion and content-item/container distinction. Physical p. 285 Issue #19 is unrelated to Table 93.

The important correction to a tempting fixture claim is the Resources version boundary. After #292, a form need not be independent before PDF 2.0; independence is strongly recommended, then required from PDF 2.0. The historical PDF 1.1-and-earlier page-resource statement is now informative note text. Therefore the existing PDF 1.7 fixture with missing form Resources is not invalid merely because the entry is absent. It demonstrates this reader's chosen compatibility fallback. That is a different claim from the mandatory PDF 2.0 producer-side independence condition, and no reader rejection duty follows automatically from that producer condition. In current `content/xobject.rs`, an absent Resources entry falls back to the page's resources; it never falls back to an invoking form's resources. An explicit Resources dictionary owns its namespace. Existing `missing_resources.rs` fixtures discriminate page versus invoker and explicit versus absent dictionaries. The exact nested-page disagreement test is the useful assertion; ADR 1055's corpus survey cannot substitute for it.

The core visible form path has concrete tests: state restoration, form Matrix placement, Matrix/CTM concatenation order, repeated invocation, inherited invocation color, and BBox clipping. The fixture helper computes stream lengths and xref offsets; the renderer helper asserts no xref recovery and complete interpretation. This supports the tested cases without certifying every affine transform.

I inventoried every Table 93 key in `features.json`. Rendering-affecting Group and OC, Ref, AF, metadata, structure, and the geometry entries have separate consumers or existing owner shards. The `/AF` and Metadata tests prove carrier reading, not a user-interface obligation. Measure/PtData and prepress OPI have no demonstrated screen-rendering obligation in this bounded review. Existing global B29 covers a distinct public accessibility propagation issue for Form StructElem attributes; I did not reframe it as a new Table 93 defect. Table 94 requires S and defines Transparency as the group subtype; current `transparency_groups.rs` contains exact subtype controls.

No new test draft is justified by this review. Specifically, I did not construct a PDF 2.0 missing-Resources failure case: it would violate the producer independence rule, and the source material reviewed does not require a reader to reject it. Annex F's additional rules are retained as a cross-reference for the Annex F shard rather than generalized into ordinary Form semantics.

Residual scope: this is not blanket §8.10 conformance. The metadata and geospatial fields were checked for mapping and current consumer scope, not for every specialized application interpretation. The Annex F resource ordering rule and full reference-XObject behavior remain with their dedicated shards.
