# Xref dictionary/table cell review

This bounded review maps the trailer, classic xref, object stream, xref stream, and hybrid-reference table entries through source, ledger, implementation, and current assertions. It uses the EC3 primary PDF directly, plus the current baseline code and global findings/gate records. It does not certify all of §7.5.

The effective table map is Table 15 (trailer, physical pp.73–74 / printed pp.58–59), Table 16 (object-stream dictionary, physical p.77 / printed p.62; associated member rules continue through physical pp.76–79 / printed pp.61–64; Note6 is physical77 / printed62 and Note7 physical78 / printed63), Table 17 (xref-stream dictionary, physical pp.81–82 / printed pp.66–67), Table 18 (stream-entry records, physical pp.82–83 / printed pp.67–68), and Table 19 (hybrid trailer, physical p.83 / printed p.68; explanatory text continues on p.84 / printed p.69). Classic xref records are §7.5.4 prose/examples, not a numbered table. Annotation positions were checked against the primary: #101/#149/#522 apply to Table15 wording; #246 broadens Table5 directness for xref streams and prohibits F; #720 strikes the old indirectness exception wording; #500 strikes the type1 offset default; #146 clarifies XRefStm's offset origin. #594 is “might”→“may” in explanatory prose, #110 adds an interoperability note, #114 permits indirect uncompressed ObjStm dictionary values, and #439 adds the encrypted-catalog prohibition.

The current execution record supersedes the older `xref_streams` scratch statement that parent execution was pending. Global finding T09 reports all `cross_references` tests passing after repairing the hybrid fixture to include the xref stream's own entry and after adding the object-number/member-order and valid incremental zero-width-first-field control. T72 reports the EC3 #114 indirect N/First/Length assertion passing with its direct control; T73 reports the /Size departure-specific current-entry test passing alongside the normal-size and older recovery-bound controls; T90 reports two stream-to-stream Prev tests passing. The corrected test bodies were reread in this worktree. `spec_xref_type0_defaults::type_zero_entry_without_next_free_or_generation_fields_marks_object_deleted` is only a parser-tolerance regression: its `/W [1 0 0]` violates Table17, which forbids zero width for the second field. It is not valid-producer conformance evidence. The simpler `cross_references::an_incremental_update_that_deletes_an_object_is_not_undone_by_the_older_section` also omits the free-list rehead and generation increment, so I do not rely on it as a conforming producer witness. `incremental_object_zero_spec_audit::incremental_object_zero_subsection_is_read_without_recovery` has a valid linked deletion for the classic-table case. A separate valid xref-stream type-0 update with `/W [1 4 2]`, a coherent free list, and exact xref entries is drafted at `drafts/type0_valid_width_free_list.rs`. No xref-specific active expected failure appears in the current global `expected-failures.json`.

The cell review found no additional runtime defect. It did find and correct two evidence qualifications: `/Info` may be direct after #106, and the existing short-W type-0 test is invalid producer input rather than a valid hybrid example. Some producer constraints are not enforced (for example sorted/non-overlapping `/Index`, directness, valid `/W` arity, object-stream collection DAGs, and the exact classic fixed-width serialization form). The source says how a conforming producer writes them; this does not itself impose a reader error/rejection behavior, so I did not turn those into mandatory-reader failures. `/Extends` describes collection organization; type-2 xref entries already name the containing ObjStm and member index, so this reader's object lookup does not depend on walking `/Extends`. The classic free-list chain is similarly writer/reuse structure; lookups need the explicit free marker and generation of a live object, not traversal of the chain.

ADR 2346 remains an explicit `/Size` departure. ADR 0100's explicit-deletion precedence is supported by current tests. ADR 0180 is correct under the observed newest-section → same-section XRefStm → older-section collection order. ADR 1004 matches the #500 deletion of the type1 offset default; the missing type2 index zero behavior is a corpus-based implementation policy and should not be mislabeled a printed default. ADR 0789 is recovery policy, not valid-input conformance. ADR 0842's writer decision is not contradicted, but this is not a complete writer audit.

Residual scope: no exhaustive check of every invalid xref/object-stream producer shape, encryption-specific object-stream combinations, every `/Extends` collection consumer, every trailer producer condition, or all writer output. These residuals do not imply that a reader must reject those files. A valid type-0 xref-stream deletion draft is retained because the existing short-W type-0 test is invalid producer input; the draft has not been executed by this reviewer. Other corrected global regressions supply direct/indirect Info, Prev, self-entry, size, and object-member-order controls. Parent reports the direct-Info exact-xref test `pdf-model::direct_info_spec_audit::table15_info_accepts_direct_and_indirect_dictionaries` passed, including `was_recovered` and chain-cut guards. The scratch direct-Info draft is superseded by that integrated test. No Cargo or test command was run by this reviewer.
