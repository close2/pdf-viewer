Bounded audit: destination geometry across inherited page rotation and non-origin page boxes. Effective source is ISO 32000-2:2020 with EC3. §12.3.2.1–.2 / Table 149, printed pp.441–443 / physical pp.456–458, says destinations specify page, window location and magnification, and all destination coordinates are in default user space. Table 31, printed pp.104–106 / physical pp.119–121, makes CropBox and Rotate inheritable and defines Rotate as a clockwise multiple of 90 degrees. EC3's embedded-GoTo correction is noted; no relevant Table149 coordinate erratum was found.

The relevant code path is coherent in the inspected sample. `Page` inherits Rotate and CropBox from page-tree ancestors. `pdf_model::content::base_transform` translates by the display CropBox origin, applies the effective clockwise rotation and scales UserUnit. `viewer-core::open::destinations::user_corner` uses `page_space_at` to put an explicit default-space destination point at the viewport corner. Existing public tests check non-origin CropBox coordinates for FitBH/FitBV and XYZ null retention on Rotate0; page geometry has separate unit assertions for rotation direction. I found no navigation test combining a named destination with the page's inherited Rotate90/270 and a non-origin crop transform.

`drafts/rotated_named_destination_xyz.rs` is a source-derived independent regression candidate. It uses a valid PDF 1.7 exact-xref document with MediaBox [20,30,620,830], CropBox [50,80,550,780], and inherited `/Rotate` on the Pages node. A one-key name tree points to an indirect explicit `/XYZ 150 680 0.5` destination. With CropBox lower-left subtracted, the point offset is (100,600); clockwise 90 maps it to (600,400) and clockwise 270 maps it to (100,100). The rotated display size is 700×500; at scale .5 it exactly fills the 350×250 viewport. Thus expected top-left origins are (-300,-50) at 90 and (-50,-200) at 270. A direct GoTo with the identical 90-degree target is the positive route control. Expected geometry is calculated in test comments from source coordinates rather than by calling the implementation's transform function.

This is an assertion-coverage gap only. The feature is implemented and existing ADR 0162/2814 reasoning is not contradicted by inspected evidence. The draft is not compiled or executed. It does not test remote/embedded navigation (B23), FitR/FitB centering (B24), all eight view forms under every rotation, UserUnit, or all page-box preferences. No production, ledger or source edits were made; parent handles promotion and execution.
