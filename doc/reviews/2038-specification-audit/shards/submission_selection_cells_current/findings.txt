Tables 239 and 241 distinguish an omitted `/Fields` key from a present array with zero elements. With `/Fields` omitted, the Include/Exclude bit is ignored: SubmitForm selects all fields except NoExport (then IncludeNoValueFields determines whether empty values are also included), and ResetForm resets all fields. With `/Fields []` present and the Include/Exclude bit clear, the array selects no fields. This is a valid empty PDF array, and neither table imposes a nonempty-array condition.

The reader currently erases that distinction. `action::field_targets` returns `Vec::new()` both when `/Fields` is absent and when it is an explicit empty array. `SubmitForm::fields` and `ResetForm::fields` cannot represent presence. `submission::selected_names` treats an empty vector as the omitted-entry case and selects all fields; `ViewState::reached_by_reset` does the same for reset. Thus a present empty include-list can export/reset all fields instead of none. A selected set remains subject to the independent NoExport and no-value rules; explicit empty selection does not become all fields merely because IncludeNoValueFields is set.

Existing coverage has good neighboring controls: SubmitForm name inclusion/exclusion, NoExport precedence, name-only empty-value output, and a public indirect-reference test for selecting a nonterminal field's descendants. A parser unit test verifies mixed field-name/reference entries. ResetForm has exact name and reference tests for both inclusion and exclusion, including descendants in the exclusion branch. Those tests do not distinguish an omitted Fields key from an explicit empty array. Errata #174 is effective: primary Caret object 5828 on physical571/printed556 is placed after “the Fields array” in Table242 bit 1’s set branch and inserts that descendants are also exempt from reset; the current reference-exclusion test asserts it. Errata #122 on physical567/printed552 strikes “inheritable” from Table239 Flags and CharSet, which current action-local parsing follows; prior shard has reviewed it.

Two standalone exact-xref test drafts are in `drafts/empty_fields_array_presence.rs`. The PDF 1.7 fixture has real form widgets on a page, AcroForm DA/DR and `/NeedAppearances true` for absent AP, two populated fields, a no-value field, and a no-value NoExport field. The SubmitForm pair compares omitted Fields with `[]`, exercises both IncludeNoValueFields states and Include/Exclude-ignored behavior, and checks that NoExport still wins over a name-only candidate. The ResetForm pair compares omitted Fields (reset all) with explicit `[]` (reset none) under the clear flag. They use no network and assert public `Action::read`, `compose`, and `ViewState` values; no Cargo execution was performed.

This is a specific selector-presence gap, not a claim that Table239/240 or ResetForm as a whole is unsupported. The standalone drafts remain unexecuted; the parent should decide whether to promote and run them.
