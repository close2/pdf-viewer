## Correct table identities and effective source

The task's table numbers require correction before mapping requirements. Table 146 is “Overprinting behaviour in the transparent imaging model” under §11.7. It is unrelated to viewer preferences. PageLayout/PageMode are catalog Table 29 (§7.7.2), printed pp.99–100 / physical pp.114–115. Table 147 is the §12.2 viewer-preferences dictionary, printed pp.437–440 / physical pp.452–455. Table 148 is the one-row list of names legal in `/Enforce`, printed p.441 / physical p.456. Tables 153 and 154 are collection and collection-schema dictionaries. The article thread and bead dictionaries are Tables 162 and 163, printed pp.460–461 / physical pp.475–476.

EC3 #275 is an operative overlay on physical p.453 / printed p.438: the inserted `/UseAttachments` entry is visible in the actual annotation text and lands after `/UseOC` in Table 147's `/NonFullScreenPageMode` list. Thus the catalog Table 29 `/PageMode` and Table 147 `/NonFullScreenPageMode` share `UseAttachments`, but only the former admits `FullScreen`. The non-fullscreen entry has the explicit condition that it is meaningful only when catalog `/PageMode` is `/FullScreen` and “shall be ignored otherwise.” Current source and code agree with that distinction.

Table 29 gives six PageLayout names and six PageMode names, with defaults SinglePage and UseNone, respectively. `/OpenAction`, if present, asks the reader to display its destination or perform its action at open; when absent, open at the first page/default magnification. These catalog requests coexist with but are not overwritten by the PDF processor's later user-selected layout or panel state.

Table 147 cells were read individually. The six window booleans default false; `/NonFullScreenPageMode` defaults UseNone; `/Direction` defaults L2R and has no direct effect on content or page numbering, but may inform relative arrangement in side-by-side/n-up views. ViewArea/ViewClip/PrintArea/PrintClip default CropBox; the first two select display and clipping regions, the latter two print rendering/clipping, and PDF 2.0 producer deprecation does not exempt readers. `/PrintScaling` defaults AppDefault, falls back to AppDefault for unknown names, and remains effective when a print dialog is suppressed. Duplex and PickTrayByPDFSize have implementation-dependent defaults; print range defaults are implementation-dependent; NumCopies is implementation-dependent, typically 1. The corrected model preserves these defaults as unspecified where appropriate rather than imposing Simplex/false/1. `/Enforce` itself is an optional array, but Table 148 permits only PrintScaling when its corresponding value is valid and not AppDefault.

## Actual consumers and assertions

`pdf-model/src/viewer_preferences.rs` parses Table 147, applies stated defaults and conditions, and reads catalog Table 29 through `Opening`. The current `viewer_preference_defaults_spec_audit.rs` checks the empty-dictionary defaults, every Table 147 entry with non-default values, unknown PrintScaling falling back to AppDefault and consequently not being enforced, PageLayout/PageMode valid and unknown names, and the FullScreen condition with `UseAttachments` on both sides of the erratum. This is a model/default assertion, not proof of every platform UI behavior.

The values flow through `Query::Preferences`/opening query and actual host consumers. `viewer-host/src/presentation.rs` applies PageMode on initial presentation and restricts the return mode to documents that opened FullScreen; `viewer-core/src/viewer/layout.rs` and presentation tests exercise multi-page arrangements; `viewer-ui` maps selected panel modes to actual sidebar panels. Durable `viewer_preferences_layout_current/parent-review.json` records prior exact-xref open-order controls and explicitly limits native UI/print certification. Its records distinguish source behavior from GTK/Qt chrome and placement policy. In particular `/Direction` is not a mandate to reorder text or override an explicit PageLayout, and HideMenubar/CenterWindow platform limitations remain disclosed departures rather than source reinterpretations.

Tables 162–163 were included because the prompt also named “article thread/bead” tables, but that parenthetical's numbers were incorrect. The current `outlines_threads_current` durable review and findings were checked. `Articles::read/read_thread` starts at required indirect thread `/F` and follows `/N` around the bead ring; model assertions cover wrap, cycle stop, bead/page association, and `I` title data. Public `viewer-core` and `viewer-ui` assertions activate/follow a thread and verify the bead rectangle rather than only landing on its page. `/V` is a producer-side reverse-link consistency field, not a separate traversal algorithm. The clause says interactive processors may provide thread-navigation facilities, so no particular next-bead button/panel is required. #320's reading-order correction is already reconciled in ADR 0746; no prior stale rationale is repeated here.
