Bounded review: explicit destinations and their local/remote/embedded Go-To action use: ISO 32000-2 §12.3.2.1–.2, Table 149; §12.6.4.2–.4, Tables 202–205. Same-key string-vs-name lookup precedence (B08) and file-spec `/UF` behavior are excluded. The source is the effective PDF with EC3. Printed pages are cited with the local +15 physical page offset.

Source evidence: §12.3.2.1–.2 and Table 149 are printed pp. 441–443 / physical pp.456–458. A destination comprises page, window position and zoom; its view is what shall be presented when the associated link/outline is opened or action performed. Table 149's eight forms are `/XYZ`, `/Fit`, `/FitH`, `/FitV`, `/FitR`, `/FitB`, `/FitBH`, `/FitBV`; coordinates use default user space. The `/FitB` family fits the content bounds clipped to CropBox. `/XYZ` null independently preserves current left/top/zoom; zoom zero has null semantics. `/FitH`/`FitV` fit page width/height, while `/FitBH`/`FitBV` fit content bounding-box width/height and retain the stated top/left placement. For GoToR/GoToE only, the first explicit array item is an integer page number in the target document, with the first page numbered zero. The effective paragraph's NOTE says the 2020 correction includes embedded Go-To as well as remote Go-To.

Tables 202–205: §12.6.4.2 Table202 is printed p.511 / physical p.526; §12.6.4.3 Table203 spans printed pp.511–512 / physical pp.526–527; §12.6.4.4 Tables204–205 are printed pp.513–514 / physical pp.528–529 (the Table204 header/footer is printed p.513 / physical p.528). Table202 `/D` is the local destination; `/SD` should take precedence. Table203 `/D` is the remote destination, explicit integer indexed from zero, and `/SD` likewise should take precedence. Table204 `/D` is the destination in target; `/F`/`/T` locate that target inside/outside the current root. No Table204 `/SD` exists. The same destination view clauses apply to each, not just the first page locator.

Local geometry is well covered by actual public assertions. `headless.rs::an_open_action_states_where_to_look_at_the_page_and_how_large` uses an independent 600×800 page with one painted 200×100 rectangle and a 300×400 viewport. It asserts `/Fit` scale .5, `/FitH` scale .5 plus top-coordinate scroll (using a shorter 300×200 viewport), `/XYZ` zoom 1 and 600×800 raster, `/FitR` 200×100 rectangle scale1.5 and origin(-150,-150), and `/FitB` equal to the independently matching FitR. Its assertions are about returned page geometry rather than parser enum presence. Local GoTo action assertions are thinner: `action_triggers_spec_audit.rs::catalog_open_action_executes_a_supported_non_goto_action` uses a GoTo OpenAction control and checks only the selected page; the three components of view are not checked through the GoTo action itself. The draft adds a separate local link GoTo geometry case as a control. The original `a_destinations_null_parameters_leave_what_they_do_not_state` opened separate documents, so comparing null zoom to default-fit did not prove retention from a known current nondefault scale. The current shared worktree contains `destinations_residual_audit.rs::xyz_null_coordinates_and_zero_zoom_retain_the_current_window_values`, which establishes scale2/scroll240×600, navigates between equal-sized pages, and checks null/all-null and zero semantics against stated-coordinate and positive-zoom controls. Its PDF1.7 fixtures use exact xref and assert the parser did not recover. `fitbh_fits_the_content_width_and_places_top_in_default_user_space` and `fitbv_fits_the_content_height_and_transforms_left_from_user_space` use a non-origin CropBox, hand-calculated independent zoom/origin and page-box controls, closing the former missing local geometry assertions for FitBH/FitBV. Their source exists in this worktree; I did not execute Cargo.

Important residual: the action integrations currently test page selection but do not prove the view travels to the target. `remote_go_to.rs::a_supplied_file_is_opened_at_the_page_the_action_names` asks for `/D [2 /Fit]`, supplies a four-page target, and asserts target opened and PageChanged index 2; it does not query target geometry, and `/Fit` on a same-sized blank 100×100 page in a 400×400 window cannot distinguish a destination view from default fitting. `embedded_go_to.rs::a_supplied_root_resumes_the_walk_and_shows_the_destination` likewise asserts the embedded child has three pages and final PageChanged index2 for `[2 /Fit]`, but not geometry. Static trace indicates this omission corresponds to a current behavior gap, not only a test gap: `pdf-model::RemoteGoTo::page_in` calls `Destination::read(...).page_index_in_target(...)` and returns only `usize`, dropping `Destination.view`; `viewer-core::interact::place_remote` sets only `replacement.page_index`. `interact::jump_into` similarly reads a GoToE destination, extracts its page index, drops its `view`, and only assigns `replacement.page_index`. The replacement `Open` is otherwise initialized from target document's own catalog OpenAction, so absent a target-side open action, the triggering GoToR/GoToE destination's specified zoom/coordinates are never queued for `Open::apply_view`. For GoToR `/SD`, `RemoteGoTo` keeps only the element ID bytes and `page_in` resolves the element to an index; the structure destination's Table149 view operands are also not retained/applied. This follow-up's draft uses explicit `/XYZ` and expects scale2, origin(-80,-200) at target page index2, while a direct target OpenAction positive control establishes those independently calculated geometry values. It has valid PDF1.7 exact-xref source, target and embedded-root fixtures, checks no recovery for each, asserts target page count and 0-based selected index, and uses separate local GoTo/GoToR/GoToE public Viewer flows: `drafts/remote_embedded_destination_view.rs`. Parent needs to run it before recording behavior as executed evidence.

Remote integer bounds: existing GoToR test's `[2 /Fit]` into four pages is a useful positive control: expected index2 distinguishes zero-based from 1-based. The embedded test does the same against a three-page embedded child. `Destination::page_index_in_target` converts nonnegative integer to usize; remote `place_remote` filters index against target page count and names a failure. This shard found no assertion for a negative or out-of-range integer. Those values violate the producer-side “page number within the remote document” condition; do not infer a normative reader rejection requirement. The current named refusal for an out-of-range index is a product/error-handling policy, not claimed as a shall.

ADRs: ADR 0162's local view model and formulas remain supported by local geometry tests, including the later residual test for bounding-box coordinate transforms. ADR 2814 corrected transformed `/FitBH` `/FitBV` and retains null coordinates when page navigation resets scroll; its evidence is local-window navigation and does not demonstrate replacement-document action views. Reopen only that cross-document gap. ADR 1227's remote file request/host boundary and ADR 0094's embedded file walk remain supported by integration tests that select the intended target page; revise neither target-security/file policy nor traversal conclusions on this evidence. The narrow missing/departing behavior is the action destination's complete Table149 view.
