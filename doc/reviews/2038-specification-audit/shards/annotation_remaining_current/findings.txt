Annotation remainder audit (baseline b901326c)

Scope completed: EC3 §12.5.6.4 Text, .14 Popup, .20 Printer's mark, .21 Trap network, .22 Watermark, .24 Projection; §12.5.1 and Tables 166–167 only as common rendering/flag context. Relevant primary locators use the source PDF's physical page and its printed page: §12.5.1 physical 480 / printed 465; Table 166 physical 482–491 / printed 467–476; Table 167 physical 485–486 / printed 470–471; Text physical 497 / printed 482; Popup physical 510 / printed 495; PrinterMark, TrapNet and Watermark physical 516 / printed 501; Table 194 and watermark algorithm physical 517 / printed 502; Projection physical 520 / printed 505; §14.11.3 physical 834 / printed 819; §14.11.6.2 physical 841 / printed 826.

Common display/print flags are actual reader behavior: `annotation::displayed` and `decide` distinguish screen from print, and `content::draw_annotation` consumes the result. `the_hidden_and_no_view_flags_draw_nothing_and_report_nothing` asserts Hidden and NoView (including combined) against a stored Square appearance and verifies both empty page commands and no report. `screen_annotation_audit.rs` supplies stronger per-purpose evidence for the specified prepress forms: the valid PrinterMark uses F=68 (Print+ReadOnly, all other bits clear) and a stored red normal AP; both View and Print yield red. The TrapNet positive fixture uses `/N << /Network 6 0 R >>`, `/AS /Network`, required `/LastModified`, and also asserts both purposes. A second test selects red versus blue `/N` states with `/AS`, independently for PrinterMark and TrapNet in View and Print. This is source-derived and directly tests appearance selection; it is stronger evidence than the Table 171 generic handler test.

That distinction matters because the reader/producer boundary differs by subtype. Table 166's AP obligation is a PDF-writer requirement with named exceptions, not a mandate that the reader reject documents missing AP. PrinterMark's §14.11.3 AP/F/AS and exact flags are producer rules; the reader draws the stored /N it can resolve. TrapNet's one-per-page, last-in-Annots, AP/AS/F, and print/read-only flags are producer rules. The renderer's `/Annots` iteration naturally paints a valid last TrapNet after prior page annotations; it does not sort or enforce a malformed order. TrapNet regeneration is prepress construction, not an implemented reader capability. PDF 2.0 explicitly deprecates both the trapping subsection and this annotation type, but existing PDF content remains accepted and the stored AP path remains observable.

One rationale needs continued scrutiny. ADR 1035 left the subject of §14.11.6.2's passive “Any trap networks found to be invalid shall be regenerated” open, and the current ledger calls every Table 403 field writer-side. The first sentence unambiguously directs a PDF writer generating a new trap network to check it; the next discusses detecting changes and regenerating traps but omits the actor. Since regeneration constructs marks along color boundaries, this is not a reader test to add here. The ledger's strong all-writer claim is more definite than the unresolved subject identified by ADR 1035. Retain that uncertainty for the owner/parent adjudication rather than treating the reader as required to update stale traps.

Popup's required no-appearance/no-actions behavior is implemented as `Decision::Nothing` for page rendering. Its window is queried and drawn by host consumers; `popup::popups` checks the Popup's own common annotation flags, and unit controls show a Hidden popup absent and a visible popup present even when its parent is Hidden. Public `headless.rs::a_document_that_opens_a_popup_window_says_so_before_anybody_clicks` checks `Query::Popups`, parent linkage, parent-provided Contents/T/C, and device placement. This covers the feature's public observation path without duplicating the prior independent-rectangle popup test. `Popup` is one of the Table 166 AP exceptions; an absent page AP is valid and should not be reported as a missing mark.

Text annotations' closed icon and open popup behavior are covered by seven icon shape tests, icon-color tests, and the popup module test. The subtype itself imposes NoZoom and NoRotate regardless of F; prior text_annotation_spec_audit reviewed this override/geometry, so I did not repeat it. The general flag tests are not in themselves the Text override oracle.

Watermark assertions directly separate page appearance from interaction: the appearance path is the same stored stream as other subtypes; `watermark_defaults_audit.rs` compares omitted Table 194 defaults with explicit identity/zero defaults and uses nonzero H/V as a displacement control; placement tests exercise media dimensions; the public print suite exercises printing; the popup and pointer tests assert no interactive window/hit target against a Square control. EC3 says a missing FixedPrint means ordinary annotation drawing, on-screen use MediaBox dimensions, and no popup or other interactive elements. The known limitation is tiled/n-up target-cell geometry: do not read existing ordinary media placement tests as certification of every print layout.

Projection's final paragraph in the base PDF says that a zero-width/height rectangle shall not have AP, but EC3 Issue #42 strikes that entire paragraph (annotation on physical 520 / printed 505). The surviving Table 166 separately exempts Projection from the general writer-side AP obligation. Issue #94 overlays “and thus an AP dictionary is not required” at the runtime-context sentence (physical 520 / printed 505); `doc/errata-read.md` records this addition. Current no-AP handling returns Nothing. The Table 171 guard includes Projection to prevent a false unknown-subtype refusal, but it is not an AP-present rendering assertion. No standalone Projection visual test was drafted: this clause says it is only valid in an associated runtime such as an activated 3D model, and a fixture with no runtime would be an invalid producer/context control; clause 13 is outside this shard.

EC3 annotation corrections found relevant: #42 strikes the old Screen no-AP sentence at physical 513 / printed 498 and strikes the entire Projection final paragraph at physical 520 / printed 505; #94 adds the Projection AP-not-required explanation. #42's Screen correction is background only. No direct change was found for the other assigned clauses. No new test draft is warranted by this bounded evidence; remaining uncertainty is the normative actor for TrapNet stale-network regeneration and a 3D runtime integration, not an observable assertion that can be validly isolated here.
