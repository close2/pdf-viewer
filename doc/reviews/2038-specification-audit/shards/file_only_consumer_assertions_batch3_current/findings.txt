# Supplemental file-only reference review: batch 3

Reviewed from `/home/cl/projects/pdf-viewer/.claude/worktrees/r2038-audit` (confirmed by `pwd` and `git rev-parse --show-toplevel`). The exact inventory pointers were `(7.3.7, crates/pdf-model/tests/damaged_char_procs.rs)`, `(7.7.2, crates/pdf-model/tests/optional_content.rs)`, `(7.7.3.3, crates/pdf-model/tests/page_geometry.rs)`, `(9.4.3, crates/pdf-model/tests/text_extraction.rs)`, and `(12.2, crates/viewer-ffi/tests/window_chrome.rs)`. The file-only pointer is not itself an assertion; I read the pointed files and the source-shaped assertions that make each behavior observable. This is a bounded review, not certification of the entire clauses.

`damaged_char_procs.rs` gives the clearest example of the source/reader boundary. EC3 §9.6.4(b) says that when a glyph name is not present as a key in CharProcs, no glyph is painted (physical p.334 / printed p.319); Table 110 describes the Type 3 font entries (physical p.332 / printed p.317). The test uses a deliberately truncated object without an xref to exercise object-header recovery. It compares an intact two-entry object, the damaged prefix, and an intact one-entry control, then checks that the surviving glyph stays in place while the absent/undescribed one contributes no glyph. It also verifies that normal `Document::get` still returns Null and that only the explicit named recovery access yields the prefix. The no-mark result is required consumer behavior for an absent key; using damaged-object recovery is a local reader policy. It says nothing about producer-validity of the malformed fixture or a general requirement to recover all broken dictionaries. ADRs 0018, 0439, 0784, 0858 and 0866 are relevant and consistent at that scope.

For optional content, `optional_content.rs` builds one-page xref PDFs and checks literal pixels, including a positive visible-group control paired with the off case. Its cases cover marked content, hidden graphics-state changes, membership dictionaries, single indirect group references, visibility-expression precedence, XObjects/annotations, absent group declarations, base state, intent, usage application and event/category behavior. The helper requires a complete interpretation before rasterization. This is useful rendering-consumer evidence for the selected rules in §8.11; it is not evidence that every host provides layer-editing UI or supports every possible usage category. Table 29 is physical p.113 / printed p.98; the catalog /OCProperties entry is physical p.116 / printed p.101; §8.11 starts physical p.291 / printed p.276. ADRs 0017, 0044, 0065, 0143 and 0178 were the relevant decision context; I found no conflict requiring reversal.

The page-geometry suite is independently numeric: Table 31 starts physical p.119 / printed p.104, and the tests assert explicit dimensions and rendered pixel positions for UserUnit, inches, crop bounds, inherited boxes and rotation. The unit-scaling case checks both resulting dimensions and mark placement; crop tests have margin-pixel controls. Separate transform tests distinguish allowed multiples of 90 degrees from a nonmultiple. This supports these concrete page-geometry features without certifying all page-tree or malformed-page behavior. ADRs 0038, 0097, 0305 and 0389 inform the tested boundaries.

The text-extraction pointer needs qualification. Its corpus/reference-extractor comparisons are broad corroboration and normalize text; they do not independently prove the numeric TJ adjustment rule. The direct sibling `text_state.rs::horizontal_scaling_reaches_a_tj_adjustment` is incomplete as a numeric oracle: it compares the total glyph-origin separation with the same `-1000` TJ operand at 100% and 50% horizontal scale, then asserts only a 2:1 ratio. Since glyph advance also scales 2:1, ignoring TJ entirely could pass. A scratch draft adds equivalent no-TJ controls and asserts the independent adjustment deltas are +10 and +5 points at 10 pt. I inspected the EC3 annotations on physical p.325 / printed p.310: #165 adds a cross-reference to literal-string syntax and #550 revises the quoted-string syntax exposition. Neither annotation changes the numeric TJ behavior under review. The source locator is §9.4.3, physical pp.324–325 / printed pp.309–310. The text pointer itself warrants no new corpus test; the separate targeted numeric assertion draft is recorded in the existing text-state scratch shard. Do not attribute #550 to TJ arithmetic.

`viewer-ffi/tests/window_chrome.rs` is a separate public FFI consumer test; it is not this selected `src/window/chrome_tests.rs` file. The latter tests C-window presentation synchronization, preservation of an arrived frame/action clock, and `/Dur` advancement, not Table 147 values or native chrome. Table 147 is physical pp.452–453 / printed pp.437–438. Keep that distinction explicit; do not count nearby tests as assertions in this file pointer.

No missing assertion or justified test draft emerged from these five references. No Cargo/test command or Git mutation was run. These notes review current test bodies and source; they make no claim about execution status.
