**Important validity boundary.** Table 166 says AP is optional in the dictionary syntax but requires a PDF writer to include at least one appearance dictionary for every annotation except degenerate-Rect, Popup, Projection and Link. Every listed subtype here with the nondegenerate rectangles in the construction tests is therefore a producer-nonconforming no-AP example. The tests are still meaningful as regressions for the reader's chosen missing-AP construction fallback, but must not be credited as source-conformance evidence that readers are required to synthesize the marks. When an AP is supplied, `annotation.rs::decided` routes through `stored_appearance` before `construct`; §12.5.5 and FreeText Table 177's explicit precedence support reading that producer-supplied stream. `variable_text.rs::a_free_text_annotation_the_file_states_is_retyped_redrawn_and_written_back` has an observable initial solid-rectangle AP against different DA text, then changes and reopens the annotation. This current coverage demonstrates FreeText AP handling. The general `annotation_appearance_audit.rs` checks stored APs for Square, not the selected stamp/caret cases. I added `drafts/stamp_stored_appearance.rs` as a subtype-sensitive stored-AP regression: it uses a complete exact-xref file, asserts no recovery, interprets through the public page route, and samples the red center from the supplied AP while asserting there is no unsupported note. It is uncompiled/unrun. This test closes the ambiguity between the policy to decline invented missing Stamp artwork and the obligation to show an AP actually supplied.

**FreeText.** The defining text is Table 177 at printed pp.484-485 (physical pp.499-500). It says the text is always visible and delegates variable text to §12.7.4.3. The distinct table entries have important conditions: required DA; AP precedence over DA; Q default 0; RC used to generate annotation appearance; CL only meaningful for FreeTextCallout; IT values/default and TypeWriter no-callout; RD left/top/right/bottom inset geometry; LE meaningful only with CL and named at the first CL point. Existing standalone exact-xref tests exercise Q with a Q=0 equivalence plus centered/right controls and independently move all four RD edges. Existing callout tests discriminate knee coordinate, end placement, IT condition, RD versus line and unsupported-value reporting. The source's AP precedence is tested by the saved-file retyping case's initial block; its latter generated-appearance checks are explicitly a reader-update path. An AP-less fixture remains fallback-choice evidence only. No behavior was added in this shard for XFA formatting outside the scoped PDF-to-layout route.

**Line.** Table 178 is printed pp.486-487, Table 179 p.489. The line geometry tests in `annotations.rs` are not just presence checks: the leader test checks line proper and orientation from signed LL; LLO/LLE check gap/extension; caption assertions test CP/CO placement and a control on line direction; Measure test checks unit conversion. `line_ending_endpoint_spec_audit.rs` has exact-xref/no-recovery controls for endpoint placement and LL; previous line-shard review found that its opening comment still recounts an ADR 0192 interpretation superseded in part by ADR 2818, while its current assertions match Table 178. #515's completed source annotation (physical p.504/printed p.489) is required to read RClosedArrow's filled phrase across the clipped table line; the current line tests cover line ends, but this pass does not independently census all ten ending shapes. Table 179 gives no shape size, so size parameters in code are choices. Popup clause behavior was excluded as requested.

**Square/Circle.** Table 180 and its paragraph at printed pp.489-490 require the rectangle/ellipse to be inscribed in Rect; the paragraph explicitly permits unequal dimensions. Tests compare the circle's ellipse silhouette with its rectangle and check cloudy variants, interior fill, and RD geometry. This supports implemented construction geometry; AP-less data are still invalid producer examples. `annotation_appearance_audit.rs` instead covers a supplied AP's placement/compositing and does not test a constructed circle.

**Polygon/PolyLine.** Table 181 at printed pp.491-492 is materially corrected: EC3 #444 makes /Vertices be ignored when /Path is present. The focused test uses a decoy `/Vertices` triangle and a PDF 2.0 `/Path` triangle, checks pixels absent at the decoy and at the PolyLine closing diagonal, then present at the Polygon closing diagonal. A separate focused test checks /IC fills a closed Square ending but not an OpenArrow; first endpoint test compares to equivalent Line geometry. These are good source-derived discriminators for #444, closure, endpoint mapping and subtype-specific IC. Path cubic operand coverage is not exhaustive. Table 181's Path-over-Vertices order is normative and distinct from Ink's table.

**Caret.** Table 183 at printed pp.493-494 describes /RD as differences and /Sy as a symbol to associate with the caret. #524 corrects /RD's type from rectangle to array; it changes the type cells in Tables 177, 180 and 183. #608 joins the symbol sentence (`. When` to `, when`) so it reads as displayed along with the caret. The current test checks /Sy absent, /P, /None, /RD and explicit refusal reason. It tests chosen fallback policy only: no shape artwork for the caret itself is defined here. A72 owner response ratifies the boundary; the source does not require the reader to reject a no-AP producer file. A supplied AP route remains separate and uses ordinary §12.5.5.

**Rubber Stamp.** Table 184 at printed p.494 names stamp icon states, defaults /Name to Draft, and recommends (should) predefined appearances for listed names. PDF 2.0 IT names StampSnapshot, StampImage and Stamp, default Stamp; the “Name shall not be present unless IT is Stamp” sentence is a producer constraint. The current test's missing-AP Stamp refusal is a product choice consistent with A72, not ISO conformance evidence. It pairs the legend with FileAttachment/Sound object-shaped recommended icons, but its comment's general group is broader than this shard. The selected stored-AP case was previously untested per-subtype; scratch draft supplies the needed positive control without asserting any invented stamp glyph or required note-window behavior.

**Ink.** Table 185 printed pp.494-495 requires InkList of disjoint strokes, leaves connection of input samples to straight lines or curves implementation-dependent, and adds a PDF 2.0 Path with m/l/c operators. EC3 #444 also amends Table 185: /InkList shall be ignored if /Path is present. The accepted Caret annotation is at physical p.510 / printed p.495; its Rect falls immediately after the “(Required)” cell in the InkList row and its Contents states the precedence. This correction was omitted from the current errata inventory. `ink_annotation_spec_audit.rs` checks consecutive segment joining with a corner/nonchord control and a cubic's midpoint with endpoint chord excluded. Its second fixture deliberately includes conflicting InkList and Path, so the Path-first branch tests the corrected precedence. The tests use no AP, and the missing-AP validity caveat applies. The source statement that paths are disjoint is part of represented geometry, not proof that each input element must connect via a fixed algorithm.
