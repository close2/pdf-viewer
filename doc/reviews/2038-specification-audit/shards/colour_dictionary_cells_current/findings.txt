## Existing coverage and boundaries

`features.json` enumerates cells rather than treating a table as one assertion. CalGray/CalRGB/Lab expectations include whitepoint, gamma, matrix, component range and anchor transforms (`crates/pdf-colour/src/colour.rs` unit tests, `calrgb_literal_samples_spec_audit.rs`, ICC paint-context CIE tests). The ICC profile tests use literal ICC ranges and current ICC profiles, and model tests exercise `/Alternate`, matching Lab/ICC ranges, and same-profile fill/image paths. #181’s effective header-version rule is reflected by `icc.rs` reading the profile header, with v2/v4 fixtures; Table 67 allowed profile class/signature combinations remain largely writer-side constraints. The previously drafted Table65 fallback test is now an executed confirmed failure, 2038-B25: `icc_alternate_range_spec_audit.rs::unsupported_icc2_profile_clamps_to_icc_range_before_wider_alternate` renders [255,0,128] where the literal clamped Lab control renders [255,0,126]. An unclamped control differs independently. Parent review records successful validation of the synthetic ICC2 v5 profile by ICC iccDEV2.3.2.5 and exact fixture provenance. This finding is specifically the unsupported-profile fallback’s lost ICC `/Range` clamp before the wider `/Alternate` range; it does not assert failure of supported-profile conversion or general ICC absolute accuracy.

Indexed tests cover the base/range mapping, lookup bytes, half-tie rounding, high clamp, initial index zero, Lab and ICC bases, images and paints (`indexed_rounding_initial_spec_audit.rs`, `indexed_lab_lookup_spec_audit.rs`, `icc_paint_context/indexed.rs`). The corpus-backed out-of-range test is supplementary; exact-xref tests provide controls independent of that corpus. Separation/DeviceN public tests cover initial tints, None/All, alternate/tint-transform routes, NChannel process mapping and CMYK subsets, Colorants matching, process/spot simulation (`special_space_initial_tints_spec_audit.rs`, `colour_paths.rs`, `spot_planes.rs`, `spot_press.rs`). They use source-derived literals and controls rather than comparing only two routes through the same implementation. Native direct colorant application depends on output device capability; display tests do not prove physical press availability.

Tables 70–72 do not impose one universal NChannel blend algorithm. The text permits custom blending and says processors need not use MixingHints. Therefore no generic Solidities, PrintingOrder or DotGain consumer is not by itself a missing MUST behavior. ADR 1103’s process mapping and ADR 1338’s Colorants key/name match are supported by current controls. ADR 1193 is historical; ADR 1229’s explicit separation-simulation preference is the current alternate path, distinct from the default display route.

## Verdict

I found no new distinct valid-input behavioral gap in the requested dictionary cells that merits another test draft. Existing color-space and special-space shards already supply the source-derived controls most likely to distinguish table interpretation. The ICC fallback `/Range` gap is now confirmed as 2038-B25; this shard does not create a duplicate test or finding.

This is not whole-colour conformance: chapter10 gamut mapping, all ICC tags/profile versions, actual subtractive device colorant availability, every process/spot ordering, every NChannel blend, and all image/operator consumer routes remain outside this bounded review. Table69 rendering intents are assigned to default-colour/BPC work; Table73 operators are not a dictionary table. Producer restrictions such as calibrated whitepoint constraints or forbidden NChannel names do not independently establish an obligation for a reader to reject the file.
