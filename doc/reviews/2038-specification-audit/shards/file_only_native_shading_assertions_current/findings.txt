Audit scope: the five exact file-only pointers in features.json. I inspected the current source and test bodies in the audit worktree; I did not run Cargo, dotnet-check, or Windows CI.

The 12.2 pointers do not all establish the same thing. `viewer-ffi/src/window/chrome_tests.rs` tests toolkit-free C-window presentation synchronization and clocks, not Table 147. `Quorra.Chrome.Tests/Program.cs` checks the host's `ChromeState.Apply` policy mapping, while `tools/dotnet-check.sh` runs that console against XAML stubs. The Windows CI `window` job is the actual-host evidence path, but its current probe covers window placement and fullscreen transitions, not actual HideWindowUI control visibility. Therefore the Windows UI wiring remains a bounded assertion gap if that behavior is claimed complete; the draft proposes a default/hidden valid-document pair with direct control-state readback. HideMenubar and HideToolbar are intentionally excluded from that candidate because of the documented permissions-menu policy and absent toolbar.

For §8.7.3.1, the directly read EC3 #428 Caret on physical p.235 / printed p.220 makes tile order implementation-dependent. The source permits filling the area with cell instances, while Table 74 on physical p.236 / printed p.221 supplies the relevant BBox and TilingType rules. `tiling.rs` uses valid exact-xref inputs and literal raster/geometry controls without ordering assumptions; its stream-once performance test is a project implementation choice. The separate exact-PDF Type 4 discontinuity test in `pdf-model/tests/shadings.rs` supplies a stronger literal consumer oracle. I found no uncovered source requirement in this pointer that merits a new test.
