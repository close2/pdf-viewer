Bounded audit of §12.7.8.3.3 (FDF pages) and the necessary adjacent Table 246/host bindings. I read the processed sponsored EC3 text and checked the primary PDF footer: Tables 251–253 are printed p.565 (physical PDF p.580); Table 246's FDF dictionary is printed p.560 (physical p.575). No directly applicable EC3 correction was found in `doc/errata-read.md`.

Table 251 describes each FDF `/Pages` array element as one new page, with required `/Templates` naming pages that serve on that page. `fdf_template_count_audit.rs` has valid exact-xref/no-recovery controls for two templates contributing one page versus two FDF page dictionaries contributing two pages. It asserts page counts, not paint. I drafted `drafts/multiple_templates_paint_one_added_page.rs`: a one-template control and a two-template target with disjoint red/blue regions, independent expected CPU pixels, exact xrefs and explicit no-recovery assertions. It avoids asserting any overlay order or transform that the source does not prescribe. This closes a useful assertion gap if promoted and run.

Table 252 `/Rename=false` is implemented and concretely tested: an exact-xref target with two same-named fields verifies both rendered values change. The omitted/default and explicit `/Rename=true` branches are a departure. The source requires uniqueness when true and sets true as the default; the note merely leaves the algorithm open. Existing tests ensure the reader reports the departure and does not incorrectly overwrite existing fields. The ledger correctly stays `departed`; no whole-clause claim follows from those tests.

Table 253's `/Name` and optional `/F` are mapped to an in-memory document callback. Existing tests distinguish an unavailable local name from a second-file question, then check supplied content is copied without references to the foreign document; viewer-core tests check the host event, refusal, decline and invalid bytes. No live path/network access is necessary. `Reference::read` appears to support both string and file-spec dictionary `/F`, using `/UF` before `/F`, but located Table 253 end-to-end tests use a string filename. `drafts/table253_file_spec_dictionary.rs` checks the dictionary form and `/UF` precedence via `ViewState::file_awaited` without opening anything externally. Cross-file page annotations are counted and reported, but are not carried into the composed page.

Two producer constraints require careful separation from reader behavior. Table 246 says an FDF writer shall not combine `/Pages` with `/Fields` or `/Status`; that does not itself require a reader to reject both. The code comment at `FormsData::read_within` says both incompatible combinations are named, but only `/Fields`+`/Pages` currently adds an `owed` entry while `/Status` is separately read and displayed. A draft with Pages-only and Status-only controls expects both values preserved and the contradictory combination named, not rejected. Table 251 `/Info` is represented only by presence and is named in `owed`, because the table defines no subentries.

There is also a cautious resource-reporting issue: `read_pages` and each nested `/Templates` array apply `.take(MAX_PAGES)` (4096) without an overflow signal in `FormsData::owed`. This is a project bound, not a maximum in ISO and not a reason to demand unbounded work. `drafts/pages_array_bound_diagnostic.rs` makes a 4097-entry exact-xref FDF with a distinct final `/Info` sentinel and asks only that the existing 4096 cap be surfaced. I have not promoted it as a normative conformance failure; parent should first check any repository-wide truncation/reporting promise.

A separate, accurately recorded departure is persistence: a template page is added to the current view but `save` does not write it into the page tree. The existing public test verifies `unwritten_pages == 1` and that the saved file still has one page. ADR 2154 correctly requires this shortfall be reported, and the ledger remains departed; reporting does not satisfy Table 251's shall.

Relevant ADR review is in `decisions.json`: ADRs 2816 (one-page cardinality with unspecified layering choices), 2154 (save departure/report), 1239 (external-file host hop), and 0907/1070 (field import and Rename branches). The earlier Before/After callback-order and sibling-default audits were not repeated.
