# Remaining multimedia controls applicability review

## Finding

No concrete defect was established in this bounded review. The important boundary is between an in-scope viability decision and the excluded behavior of selecting/operating a real media player. The viewer computes a viability report, applies the reader's media handoff restrictions, and emits the chosen file as `Event::Media`; it does not discover the OS player, assert that it launched, or carry a display target. This is consistent with the ratified scope and ADR 1960's unnamed handoff profile.

§13.2.7.2's MediaPlayers dictionary participates in viability, so its array conditions cannot be skipped solely because playback is excluded. The current algorithm reads MU/A/NU, evaluates media-player-info viability before considering array emptiness, and applies the four §13.2.7.2.2 conditions for the abstract, unidentified handoff player. Existing tests distinguish empty/nonempty MU, A, NU, and a known content type versus unknown type; a separate test covers removal of non-viable entries before MU emptiness. The viewer test proves that a viable clip is reported and handed off as the expected bytes. It does not prove which program the operating system starts. The previous `media_viability` source review already records the remaining MU-minus-NU interpretation question: the effective-removal sentence and the empty-array-as-absent sentence do not specify whether subtraction that removes every candidate makes an originally nonempty MU absent. That is not treated as a confirmed defect here.

§13.2.7.5 and Table 304 specify a monitor for a player window: values 0–6 correspond to window overlap, primary display, color depth, pixel area, height, and width; tied choices may be broken in an implementation-dependent manner. Table 294 uses `/M` for floating/full-screen media playback, ignores it for other window types, defaults to 0, and distinguishes unrecognized mandatory versus best-effort values. The current `Processor` input has no monitor state and the public `Event::Media` has no monitor destination. Thus physical monitor selection is correctly on the excluded playback side. As a viability criterion, an MH setting the handoff cannot tell a player to honor is reported as unhonorable; BE is best-effort and does not veto. Current `media_viability.rs::screen_parameters_must_honour_make_the_rendition_non_viable_and_best_effort_do_not` uses `/M 2` in a BE control and `/W` in the MH refusal. It does not isolate an `/M` MH diagnostic. Since the generic code handles any MH key this way and no false viability outcome was found, this is an assertion-specificity limitation, not a conformance finding. No test of actual monitor choice was drafted.

§13.5 is a separate optional legacy route. It is expressly deprecated, says processors are not required to support alternate presentations, and places the SHOULD to preserve a useful static representation on authors. The slideshow's `AlternatePresentations` name tree, virtual resources, and user-initiated playback need not be parsed or run by this reader. The ordinary PDF page remains rendered by the normal page path. A producer that fails to provide useful static content is not evidence of a reader failure under this source. The errata inventory's “untouched” labels are inaccurate for two annotations: primary #449 on physical p.648 moves a paragraph under the §13.2.7.2.2 algorithm heading, and #481 on physical p.656 rewrites NOTE 2 to describe AlternatePresentations as file specification dictionaries, typically with an embedded file stream. These clarify organization/storage and do not alter the explicit processor permission or establish slideshow support as mandatory. Table 304 spans physical pp.651–652 / printed pp.636–637, not p.651 alone.

## Source and implementation mapping

The primary PDF locators are in `features.json`: §13.2.7.2.1/Table 301 and §13.2.7.2.2 are physical pp.648–649 / printed pp.633–634; §13.2.7.5/Table 304 is physical pp.651–652 / printed pp.636–637; §13.5 is physical pp.655–657 / printed pp.640–642. I checked the primary annotations rather than relying on the inventory's untouched label for #449/#481.

Consumer path reviewed: `pdf_model::media::judge` produces notes and a chosen clip; `viewer-core/src/interact.rs` reports the notes and forwards the chosen non-Form clip; `viewer-core/src/viewer/media.rs` enforces `Operation::HandOverMedia` and emits the clip through `Event::Media`. No monitor selector or player identity enters this path. `viewer-core/tests/renditions.rs::a_viable_clip_is_reported_and_handed_over_at_the_default_level` is the public positive control; model-level `media_viability.rs` holds the dictionary branches. No tests were run in this shard.

ADR 1960, 2376, 2392, 2428, 1946 and the prior 1768 §13.5 finding remain consistent as qualified in `decisions.json`. The aggregate §13.2/§13.2.7 statuses combine in-scope viability readers with excluded player presentation; they are not whole-family playback certification.

Partial source/assertion review only. No tracked files or tests were changed. No alternate-presentation support or actual physical-monitor behavior is claimed.
