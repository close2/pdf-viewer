Type 4/5 mesh dictionary cells and stream records

Source checked directly in the effective primary EC3 PDF: §8.7.4.5.5/Table 81, printed pp.239–242 / physical pp.254–257; §8.7.4.5.6/Table 82, printed pp.243–244 / physical pp.258–259. I also inspected the actual pikepdf annotation arrays for physical pp.254–258. Relevant annotations on these pages are cross-reference links; no Caret or StrikeOut changes the mesh fields or topology. EC3 #682 appears later at Table 85 and does not alter these Type 4/5 rules.

Tables 81 and 82 both require BitsPerCoordinate in {1,2,4,8,12,16,24,32} and BitsPerComponent in {1,2,4,8,12,16}. Table 81 additionally requires BitsPerFlag in {2,4,8}; only its low two bits are used for edge flags 0, 1, and 2. Decode stores coordinate ranges first and direct component ranges afterward; if Function is used, one t range replaces the component ranges. Table 82 requires integer VerticesPerRow >=2 and sequential row-major vertex data. Each row pair/cell creates the two explicit Table 82 triangles. Type 5 has no flag field and refers back to Type 4 for its vertex data format, which includes byte-padding each vertex record independently.

The current code in pdf-colour/src/mesh.rs uses the allowed width lists in `bits`, applies Decode independently for coordinate and carried color/parameter values, masks Type 4 flag values with 0b11, and calls `BitReader::align` after every vertex in `read_vertex`. Type 4's `free_form` branch has the source-defined flag0/1/2 topology. Type 5's `lattice` branch reads complete rows and emits both triangles for every adjacent row-pair/cell.

Existing assertions have useful independent controls:

- The Type 4 base raster test checks literal corner colors and outside transparency. The promoted `type4_edge_flags_spec_audit.rs` test checks both continuation flags and ignored initial-triangle flags against Table 81's exact coordinate/color triples; parent review records PASS in mesh-crypto-wave74b.log. The Type 4 one-bit fixture uses seven meaningful bits per vertex, then independent pad bits, and checks all three corners.
- Type 5's single-cell raster test checks all four corner colors and area. The promoted 3×3 public display-list test matches eight literal Table 82 triangles, coordinates and colors and passed T97 in lattice-images-wave75.log. Its middle row is straight, but the points/values still distinguish multiple row pairs and both cells. It uses 8-bit fields, so it does not test the shared padding path.
- Function ordering is separately audited by shading_function_oracles_current, which has nonlinear Type 4/5/6/7 cases and an executed Type 5 function test. I do not duplicate that topic here.

One narrow assertion gap remains for valid input: a Type 5 vertex whose coordinate/component fields do not occupy a whole number of bytes. The existing Type 4 1-bit case confirms alignment for Type 4; the Type 5 3×3 test does not, because 8-bit fields are already aligned. The candidate in `drafts/type5_vertex_byte_padding.rs` uses a 2-bit coordinate and 1-bit DeviceGray component per vertex (five significant bits, three pad bits), with explicit bytes `00 C8 38 F0`, then compares two literal Table 82 triangles against an 8-bit encoding of the same four vertices. It asserts exact xref/no recovery, complete interpretation, geometry and decoded gray values. This is a valid file-level assertion gap, not a current implementation defect claim; the code already calls the shared alignment function.

The Type 4 stream prose says an error occurs unless the stream represents a whole number of triangles. I record that producer stream constraint without inferring a universal reader-rejection policy for truncated or malformed data. Likewise, no defect is inferred from lacking individual tests for every valid bit width. ADR 0292's parameter-first rule is reviewed in the function shard; ADRs 1217/2546 govern patch-specific tessellation and color lattices, not Type 4/5 bit packing. No broad ADR verdict is made.

No Cargo or Git commands were run. The draft is uncompiled and unexecuted, and this review does not establish all color spaces, all legal bit widths, device-edge raster behavior, patch record alignment, or malformed-stream recovery.
