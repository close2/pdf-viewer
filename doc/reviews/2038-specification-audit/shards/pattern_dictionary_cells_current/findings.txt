# Pattern dictionary cells: Tables 74 and 75

Bounded current-source review at `b901326c`. I verified the table captions and page footers in the held ISO 32000-2 + EC3 PDF and checked annotation objects on the table pages. Table 74 is **Additional entries specific to a Type 1 pattern dictionary**, physical pp. 236–237 / printed pp. 221–222. Table 75 is **Entries in a Type 2 pattern dictionary**, physical p. 243 / printed p. 228; its explanatory text continues on physical p. 244 / printed p. 229. Table 75 is a pattern dictionary, not the common shading-object table. Table 75 pages have links but no Issue-tagged corrections. EC3 #294 adds “stream” to Table 74’s caption, while #428 qualifies the tile filling order as implementation-dependent.

Table 74’s cells are already reviewed in `tiling_pattern_cells_current`. That source review records PaintType 1/2 semantics, TilingType 1/2/3 behavior, clipping BBox, signed nonzero XStep/YStep, required Resources, and optional Matrix/identity default. Its exact assertions include colored/uncolored controls, Separation tint arity, BBox clipping, cell phase, step spacing, and the Type1/2/3 lattice distinctions; the latest parent review reports T133 negative-step PASS and 35 tiling tests PASS. This shard does not duplicate those tests. It preserves two boundaries: B20’s degenerate BBox clipping failure remains separate, and Type1’s “shall” for consistent spacing is not automatically discharged merely because the optional snap adjustment is declined (the tiling reviewer left that fallback interpretation open).

Table 75 has five cells. `/Type` is optional and, when present, is `/Pattern`; `/PatternType` is required value 2; `/Shading` is required and may be a dictionary or a stream according to shading type, with common Table 77 plus a type-specific table; `/Matrix` is optional with identity default; `/ExtGState` is optional and supplies temporary graphics state, with unspecified eligible parameters inherited from the parent content stream’s initial state as modified by §11.6.7. Its following prose makes clear that shading patterns do not tile and that their gradient geometry is independent of the path, glyph, or mask being painted.

The current consumer maps Table 75 Matrix through `shading::matrix_of`, composes it with `Interpreter.base`, keeps the Shading object unresolved for the shading cache, and builds the pattern definition from the parent-stream initial graphics state augmented by the pattern’s own ExtGState. Existing public assertions cover the omitted identity Matrix (`a_shading_pattern_fills_only_the_path_it_paints` compares its interior color with direct `sh`), page/Form/annotation/nested-pattern parent coordinate spaces, ExtGState rendering intent and black-point behavior, and Table 77 BBox/background interactions. The Type2 pattern Matrix cases in those tests omit `/Matrix`; a Type1 pattern’s explicit translated Matrix test is a different dictionary and does not test this path. The cross-renderer `issue6769_no_matrix.pdf` oracle also has no explicit pattern Matrix.

I drafted a narrow Type2 pattern Matrix test in `drafts/shading_pattern_matrix_spec_audit.rs`. It uses an exact-xref PDF 1.7 with a required page resource dictionary, a required shading dictionary, a DeviceRGB axial function and explicit extend flags. Omitted and explicit identity cases are positive controls. At an interior sample, the Type2 function’s known linear rule predicts approximately `[126,0,129]` for identity and `[177,0,78]` after a +20 pattern-space translation. The expected values are source-derived, and the ±3 byte tolerance only covers raster rounding. Parent promoted the test as `crates/pdf-model/tests/shading_pattern_matrix_spec_audit.rs::shading_pattern_matrix_maps_pattern_space_before_sampling_its_gradient` and reports PASS. This agent did not run Cargo; no behavior failure is claimed.

No Table 75 Shading-as-stream pattern witness was found in the named PDF model pattern tests. Direct mesh-shading tests consume stream shading objects through `sh`; the Table 75 pattern examples I inspected use shading dictionaries. Current pattern code stores the Table 75 Shading object and delegates it to the generic shading builder, which handles streams elsewhere. This is an untested input-form combination, not an established implementation fault, and I did not draft a second test because the nonidentity Matrix gap is more discriminating. Likewise, ExtGState coverage is selected rather than exhaustive: rendering intent and black-point assertions exist, but this is not a re-audit of every §11.6.7 parameter or transparency combination.

No broad reader rejection duty is inferred from required writer fields. Table 74 Resources and the PatternType/paint/step constraints describe conforming pattern streams, while the missing-resource reader policy has separate prior ownership (ADR 1059/2820). The Table 75 Shading object’s requiredness does not itself dictate a particular recovery result for malformed PDFs. The nonidentity Table 75 Matrix assertion gap is closed by the parent-promoted passing public raster test. Remaining untested combination noted above is not a defect claim.
