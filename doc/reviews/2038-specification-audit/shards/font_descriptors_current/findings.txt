This bounded review covered ISO 32000-2 §9.8.1–§9.8.3, effective with Errata Collection 3, in the primary PDF and searchable `doc/md/ISO_32000-2_sponsored_EC3.md`. The PDF footer locators were checked in the source layout: Table 120 begins at printed page 343 / physical page 358 and spans through printed page 345 / physical page 360; §9.8.2 / Table 121 is printed pages 345–346 / physical pages 360–361; Table 122 and §9.8.3 are printed pages 347–349 / physical pages 362–364. Markdown source lines are named per feature in `features.json`.

The main reportable claim-coverage issue is EC3 Issue #453. It revises Table 120's `/MissingWidth` wording so predictable behavior is only promised if every character code outside `/Widths` maps to glyphs having the stated MissingWidth; otherwise behavior is implementation-dependent. `doc/errata-read.md` indexes this under the §9.8.2 heading, but it changes Table 120. The ledger's §9.8.1 narrative maps the zero default and width use without the #453 qualification. `metrics::missing_width` deterministically applies its value/default, which is a permissible reader choice; this is a ledger precision gap, not a claimed conformance defect. Existing direct tests independently assert an explicit width and the zero default. No new test is drafted because a meaningful #453 precondition test needs a font fixture whose actual widths for all uncovered codes are independently established; the current direct assertion covers parser policy, not that precondition.

Table 120 producer obligations (descriptor Type, FontName/BaseFont agreement, required entries, allowed FontWeight values/type, and one font-program key) are not automatically reader error obligations. `LoadedFont` reads descriptors on the simple-font route or the Type 0 descendant; no Type 0 outer descriptor is consumed. Absent descriptors/programs are routed through substitution, consistent with the clause's permissive 'provide information that enables' sentence and the standard-14 exception in Table 109. The newly changed unreadable-program path in the diff `4015a9ae..b901326c` removes only FontFile/FontFile2/FontFile3 on a copy and uses the remaining descriptor to select a substitute; this is a documented recovery choice, not a mandatory ISO behavior.

Flags are stronger evidence: the word must be an unsigned 32-bit integer and the reader should classify from Symbolic even when the writer violates the mutual-exclusion rule. `descriptor_flags` has direct positive and malformed-word controls (including negative, real and >u32). TrueType's symbolic path ignores Encoding; embedded name-keyed fonts do not let the bit replace the built-in encoding. A corpus integration test confirms the public report for a file setting both bits. Reserved-bit zeroing is expressly a producer constraint. ForceBold influences substitute style; the source permits thickening at small sizes but does not require every processor to paint extra pixels, so no missing raster-thickening behavior was found.

CIDFont-specific coverage includes Table 122 Style/Panose and Lang effects, and Table 123 /FD class overrides. The implementation's class table includes the PDF 2.0 Adobe-KR row and preserves deprecated collection rows for compatibility. Existing tests assert Panose-driven substitute choice, Language-Tag choice where Identity ordering leaves script unknown, class-specific substitute selection, valid disjoint classes, and refusal where the Unicode character cannot identify a class. EC3 #5 repairs the FD paragraph's allowed-key wording; tests do not establish an obligation to reject producer-invalid FD content. `/CIDSet` is deprecated in PDF 2.0; no stream parser for it was reviewed. No untested claim is promoted to a whole-subclause certification.
