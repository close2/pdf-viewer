# Appearance-state selection and widget-value consumer residual

I reviewed the effective ISO 32000-2:2020(E) source, not only the extracted Markdown. Printed footers establish these locators: Table 166 is printed pp. 467–470 / physical pp. 482–485; §12.5.5 and Table 170 are printed pp. 475–476 / physical pp. 490–491; §12.7.4.1 and Table 226 are printed p. 529 / physical p. 544; and §12.7.5.2.3 is printed pp. 535–536 / physical pp. 550–551. EC3 issue #170's actual annotation is physical p. 568 / printed p. 553; it adds the optional `/Off` appearance sentence to the radio-button subclause. I found no erratum in this slice that changes general `/AS` state selection or the check-box `/V`/`/AS` mismatch rule.

For stored appearances, §12.5.5 is direct: normal/rollover/down entries may be streams or state subdictionaries, and where `/N` is a subdictionary its appearance states are selected by the annotation `/AS`. Table 166 requires `/AS` if AP has one or more subdictionaries. If a present `/AS` designates no defined state, §12.5.5 asks the reader to attempt reasonable behavior and gives displaying nothing as an example. The implementation's exact-name lookup returns no appearance and no unsupported report in that case. Existing `annotations.rs::an_appearance_state_is_selected_by_as` tests both a defined state and the unmatched `/AS /Off` case; `annotation_appearance_audit.rs::rollover_and_down_state_subdictionaries_select_the_state_named_by_as` checks distinct N/R/D colors; `names_are_bytes.rs` tests that state names differing in non-UTF-8 bytes remain distinct. Those are meaningful output assertions, not only source-shaped helper expectations.

Table 170 sets absent R/D defaults to N, and existing raster tests assert the missing-D→N result and print→N behavior. `stored_appearance` also treats a present null R/D like absence; that is tolerant handling, not a claim that null satisfies the table's stream-or-dictionary type. A missing/null N is not assigned a mandatory reader fallback here: N is required by Table 170. Likewise Table 166 requires AS for a state dictionary. Missing or null AS in that case is invalid producer input. The renderer currently has no selected stored state and draws nothing; the form-model reader may fall back to inherited V for its `on` field. The standard's explicit reasonable-behavior sentence concerns a *present AS that names a missing state*, not an absent/null state selector. Any difference on this malformed case is a product/recovery-policy question, not a required-rejection finding.

For button fields, Table 226 makes `/V` inheritable. §12.7.5.2.3 states both that `/V` holds a name selecting the button's appearance and that `/V` shall equal `/AS`; if they differ, it explicitly directs the processor to use `/AS` rather than `/V`. Current `Field::read` obtains inherited V, while `Field::is_on` uses a widget's explicit AS first. During edits, code builds the replacement state from the new field value and feeds it to the picture path, keeping the page and host description aligned. Existing tests assert model state for an inherited parent `/V /Off` with child widgets `/AS /Yes`, and separately rasterize the new state after an in-view replacement. The editing/save path also checks V and AS are synchronized after save.

There is a small public assertion gap: no test I found combines inherited parent V, child AS, and actual loaded page pixels for the stored mismatch case. `drafts/inherited_button_value_as_pixel_precedence.rs` fills it with exact xref offsets, no-recovery guard, two matching controls, and both V/AS mismatch directions. Its red On and blue Off form XObjects provide independent literal outputs. The mismatch cases intentionally are not described as conforming producer examples; they test the precise reader instruction for unequal values. This draft is unexecuted and does not establish current runtime results.

Selected ADR review: ADR 0013's stored AP reading remains supported by the distinct-color AP selection tests and the reasonable unknown-state handling; ADR 0235's split between a stored file AS and a viewer-replaced button value follows the two sentences of §12.7.5.2.3; ADR 0346 correctly keeps the file's explicit per-widget AS precedence separate from mutual-exclusion behavior on a reader edit; and ADR 0439's byte-exact name lookup has direct non-UTF-8 positive/negative tests. None of these decisions supports using inherited V instead of a present, differing AS for the stored appearance.

Boundaries: this review does not audit button editing/host events, per-widget export values, all radio state generation, annotation R/D interaction policy, absent AP construction rules, malformed-state recovery, or appearance geometry. The draft is the only new regression proposal; no behavior failure was confirmed in execution here.
