The logical worked-example test is strong and should remain as positive evidence. The parent inspected `pdf-model/tests/logical_structure_example.rs::the_clauses_worked_example_reads_as_the_structure_it_describes`: it asserts the example's role mapping, class-vs-element attribute precedence, per-page ParentTree mapping (including repeated association), IDTree lookups, a paragraph spanning pages through a marked-content reference to another page, and the example's nonzero generation reference. Those assertions support only what the example illustrates.

The larger §14.7 aggregate is supported by prior focused reviews of root/element dictionaries, ID and ParentTree access, each content-item route, namespaces, attribute ordering, revisions and user properties. The traversal limits are now confirmed parent findings B03/B04, not pending candidates: `Tree::descend` has a depth stop and `children`/`identified_children` cap count, while only the element-count limit sets `Reading::truncated`. Deep/wide valid structure can therefore be exposed as a complete prefix. Parent findings/gate results are the authoritative current evidence; the earlier local draft itself was not executed by this agent. The aggregate ledger status does not resolve these confirmed defects.

For §14.8.2.2, the primary source is explicit: any content not included in the structure tree is artifact even if no `/Artifact` marked-content tag encloses it; NOTE 2 includes annotations. EC3 #484 changes the two explicit marked-content form statements into notes, not this by-absence rule. The existing artifact test family distinguishes declared/inferred spans and reported text. Do not invent a conformance failure merely because a PDF has page content outside the tree or lacks an explicit marker. MarkInfo `/Marked true` identifies a document claiming tagged-PDF status; the reader's classification policy and the source's producer constraints must remain distinct.

The major cross-family current finding is B43, already executed by the parent and recorded in `structure_layout_remaining_current/findings.txt`: a valid exact-xref parent `/K` array interleaves MCR text A, child Span text B, and MCR text C. The model and flat positive control return ABC, but AccessKit's public traversal returns ACB because it stores parent runs separately from child nodes. §14.8.2.5.1 gives depth-first logical order and §14.8.4.7.1 permits inline/actual-content ordering combinations. This is a consumer projection failure on that path, not invalid producer input. No duplicate draft is included.

Namespace framing was checked against §14.8.6.1–.3 (physical 809–810 / printed 794–795). Missing `/NS` defaults to the PDF 1.7 URI `http://iso.org/pdf/ssn`; PDF 2.0 is a distinct explicit URI `http://iso.org/pdf2/ssn`. MathML is a third, explicitly declared namespace with its own URI and is not the PDF2 standard namespace. Existing namespace/default/role-map and MathML controls are documented in `structure_types/findings.txt`. Producer requirements for namespace membership and map validity do not automatically impose rejection on readers; the current implementation reports outside-standard namespace findings at document scope.

The inapplicability boundary for §14.8.5.4.1 is also defensible but conditional. That subclause's SHALL concerns how a producer defines layout attribute objects. The current viewer interprets existing appearance and has no reflow/layout-export producer; it does not need to reject documents violating the producer constraint. Table 377’s effective applicability cells are the EC3 replacement on pp. 1013–1014. This finding does not say ISO forbids reflow or that the attribute has no meaning to another consumer. Existing ADR 1535 is a current product-destination boundary, not an absence-of-source-rule argument.

No standalone test was drafted: the only confirmed worthwhile public issue, B43, is already in the parent's execution queue/results; the worked example and namespace/artifact controls already have relevant assertions. No Cargo or Git command was run. Remaining source-specific gaps are listed in the per-feature JSON; this review does not certify every type, namespace dictionary, attribute owner, malformed structure tree, or consumer adapter.
