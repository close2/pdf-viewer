Bounded scope and source locators are in `features.json`. Printed-page locators are taken from the EC3 page footers; the annotation table in `doc/errata-read.md` uses physical PDF pages. For this shard, effective issue #257 is on physical page 636 (printed 621); issue #662 is on physical 643 (printed 628), but modifies §13.2.6.1 and is outside the assigned .6.2/.6.3 scope.

The reader-facing slice is the file's viability and hand-off. Clause 13's ratified exclusion still disallows the application from decoding/presenting audio/video. `CLAUDE.md` now admits §13.2.2 viability and hand-off to an external player; Q649 says the media-player surface and actual player await a separate decision. Thus `13.2.5` being marked implemented means viability under this product's handoff model, not that playback obeys volume, fit, duration, repeat, autoplay, freeze, or controller parameters. Likewise §13.2.6.2/.3 implementation refers to judging offsets/timespans and the viable decision, not performing a seek or timed playback.

§13.2.4.2: code reads `D`, `CT`, permissions, and embedded content; integration tests reach public activation/handoff and check exact type/data and policy behavior. Effective EC3 #257 makes CT conformance to RFC 2045 mandatory for the dictionary value. The inspected code does not validate arbitrary CT syntax; it passes/uses the string for container selection and media handoff. The source says the string shall conform but does not state a recovery rule that requires the reader to reject a malformed string. Record this as a producer-conformance limitation, not a proven reader defect. Filesystem/URL data are not fetched for viability; model and ledger should not imply that arbitrary external resources or players were opened.

§13.2.4.3 and §§13.2.6.2–.3 have unusually good discriminating tests: valid starts at time zero/frame zero, nonzero and negative starts, still-image offsets ignored, an end at/past the clip end versus just inside, a child-section range, marker present/missing/out of range, and malformed/unreadable source controls. The implementation derives facts only from supported embedded container headers (WAVE, MP4, SWF, ASF, MPEG-2 program stream plus listed formats) and reports when it cannot establish a timeline. These tests do not certify all container standards and do not test playback seeking.

§13.2.5 tests distinguish MH from BE and cover explicit duration /T routing. ADR 2472 follows Table 300's independent sentence that an unknown timespan subtype makes the rendition nonviable even when nested in a BE duration; other BE duration problems remain ignorable. Negative or missing values are distinguished from unrecognized subtypes. No source support was found for treating these viability checks as proof that media duration playback/freeze/repeat is implemented.

§13.2.7.3 checks required PID, unknown MH entries (none are defined in Table 302), partially recognized identifier, and negative version values. §13.2.7.4 tests do not check URI unescaping/case, OS matching, version range bounds, zero-padding, or empty-array-as-infinity. The module has no host-supplied player identity/version/OS; a viable PID is therefore not a match for the product's external handoff player. Existing tests correctly exercise the “unknown identity” path, but the ledger's `implemented` status is not evidence that the defined software-matching algorithms are implemented. Keep this row explicitly processor-scoped/inapplicable until the host identifies a player or the app becomes one.

One small test assertion gap is identified without claiming a defect: `player_info_set_aside` intentionally ignores media-player-info `/BE`, but current `with_players` tests that include such a BE entry conflate it with the external player failing the `/MU` identity match. `drafts/player_info_best_effort.rs` gives a focused assertion that a recognized PID with an unknown BE key remains in the array (no set-aside report), while the handoff still fails to match that required player. This is a model-level viability assertion and requires no media player or invalid fixture.

Selected ADR verdicts and remaining scope are in `decisions.json`. There is no source-backed defect found in the bounded media-data/timing behavior. The broader software-ID match comparator and playback parameter execution remain out of scope for this product state; future player work would reopen those rows.
