Bounded audit: ISO 32000-2:2020 §12.3.3 Document outline; §12.4.3 Articles; Tables 150–153 and Table 31 /B, plus EC3 Issue #320. This is a source-to-ledger-to-code-to-assertion review, not whole-clause certification.

## Source and section identity

The effective PDF headings/footer were checked directly, rather than calculated only from the assumed offset. The outline heading and Table 150 start on physical PDF p.459 with visible printed footer p.444; Table 151 continues on printed pp.445–446 (physical pp.460–461). Articles starts on physical p.475 with printed footer p.460; Table 163 continues to physical p.476/printed p.461. Table 31 begins physical p.119/printed p.104; its /B row is physical p.121 with printed footer p.106. The ledger rows are §12.3.3 (around line 3563) and §12.4.3 (around line 3635). §12.3.4 is Thumbnail images; articles are §12.4.3.

The original PDF and EC3 consolidated Markdown agree on the base outline and article structures. The outline clauses define a hierarchy using linked references, title/destination/action, item visibility counts, and limited style/color values. For article threads the catalog's Threads array is optional; a thread's /F begins a circular bead chain, with required /N and /V indirect links and each bead carrying /P and /R. The reader has to interpret these structures; producer obligations on /Prev, /Last, /Parent, /V, /P, and dictionary types should not be turned into a reader refusal rule without a separate normative processor instruction.

## Outline trace and assertions

`doc/conformance/ledger.toml` labels §12.3.3 implemented. `pdf-model::Outline::read` follows First/Next, preserves nesting/order/title/style/colour and count-derived open state, and caps excessive depth/item count or repeated references. It does not need the producer's redundant Last/Prev/Parent statements to reconstruct the linked list. The resulting outline is exposed by `Query::Outline`, rendered by the Read/outline panel, used by outline activation, and exposed to script bookmark reads after ADR 1934. `section_at` is an extra product mapping from the current page to an outline title; its own source comment correctly calls this a documented choice.

Current assertions cover model decoding/count/open/style and cycle termination; corpus/spec PDF coverage; the panel's visible hierarchy/close-reopen identity; a real specification PDF whose destination activation is compared against an independent raw page-tree walk; and URI action hand-off. The UI panel and script bookmark paths are actual consumers; the chapter does not mandate that a processor have a panel. ADR 1934 is the current script choice and supersedes ADR 1922's earlier refusal of outline reads. Its object projection does not create a new obligation to validate redundant producer links.

No substantial missing public behavior test emerged. Current tests split exact model decoding, public panel actions, and public core activation across fixtures, but together assert the visible/activated behavior named by the clause. The core specification-PDF activation test is not an exact-xref fixture; the panel/core synthetic fixtures are built with xref offsets. I did not add a test solely to assert recovery state: that would improve fixture hygiene but not expose a known missing behavior, and a separate exact-xref model fixture already exercises the relevant decoding. The fact that the clause says a visible item activates remains the substantive route test.

## Article trace and assertions

`pdf-model::Articles::read` follows `/F` then `/N` until it returns to an already visited bead; `/V` is not traversed because it is the redundant reverse chain. It reads `/I/Title` as a text string, bead page reference, normalized rectangle, and catalog array order. `Articles::next` wraps within the ring, and `locate` gives thread/bead indices. `Query::Articles` feeds the Read panel; `Command::Activate(thread_id)` composes the existing thread action and uses `/R` as FitR. `Articles::page_array_agrees` is a separate consistency helper with no caller outside its own model tests. No current host consumes the diagnostic or offers an explicit next-bead button; that is not a violation because the clause says interactive processors may provide navigation.

Assertions cover exact linked-ring traversal and wrap; invalid repeated-chain termination; `/B` membership, missing-array None, single-thread order and multi-thread membership; producer-origin pdfbox articles with decoded titles, page references, and closing rings; and public core activation/query/UI action. The public thread fixture has exact xref offsets and includes `/B` values, but does not currently make a `was_recovered` assertion. Its independent geometry check calculates that the bead's 320×160 rectangle in a 400×800 viewport yields 1.25 scale. Another core test checks the actual `/S /Thread` action. This is adequate evidence for the optional feature and reader route; adding a no-recovery assertion to the fixture would be reasonable hygiene, not a source-derived coverage gap.

## /B erratum and remaining source discrepancy

Direct annotation extraction confirms the correction: Table 31 physical p.121 / printed p.106 has Issue #320 StrikeOut object 2312 0 R (NM `adfe094b-a0a3-4b47-bc2f-04bfe55d8db7`, Review/Completed per the errata record) over “natural” with no replacement. The §12.4.3 sentence on physical p.475 / printed p.460 has StrikeOut object 4823 0 R (NM `ea2bfcb2-63de-4404-9bbd-9f9f8bc2a19d`) paired by `/IRT` to Caret object 4825 0 R (NM `ca02eed8-035d-46fb-a192-2fadd59cce6e`) whose `/Contents` is “reading”; the struck word is “drawing”. Thus the base printed clauses disagree on `/B` order: Table 31 /B row (printed p.106, physical p.121) says “natural reading order”; §12.4.3 (printed p.460) says “drawing order.” EC3 Issue #320 strikes “natural” in Table 31 and replaces “drawing” with “reading” in §12.4.3. ADR 0746 correctly changes the one-thread check to sequence: one thread's `/F`-to-`/N` order is the article reading order. Multiple threads on a single page still have no relative ordering rule, so set comparison is a local diagnostic choice. I found no downstream code that renders from `/B` or reports this comparison to users.

There is a distinct unclosed presence wording conflict: §12.4.3 says a page with beads “shall contain a B entry,” while Table 31 calls `/B` Optional and recommended if article beads are present, and says it can be reconstructed from `/Threads`. `Articles::page_array_agrees` treats a missing `/B` as no disagreement; the parser derives bead-on-page data from the threads. Given Table 31's explicit Optional/recommended descriptor and NOTE 2, I do not classify this tolerant reader behavior as a defect or impose a mandatory validation/UI warning. The project should keep this source discontinuity explicit if it describes `/B` semantics later.

## Decisions and residuals

Reviewed ADR 0746 (erratum/order diagnostic), ADR 0200 (optional Article tab), ADR 0405 (producer corpus witness), and ADR 1922/1934 (current outline script exposure). See `decisions.json` for focused verdicts. I found no reason to reverse current runtime behavior. ADR 0746 correctly records the former published order conflict and the resolution it adopts using Issue #320 as evidence under ADR 0601; the remaining ambiguity is only inter-thread order and Table 31-vs-clause presence wording. Keep the historical source conflict visible rather than silently rewriting the published clause.

Unreviewed: exhaustive producer-conformance checks for each outline/thread link and every invalid-type recovery path; digital annotation/rendering consequences for outline colors beyond existing panel assertions; thread switching between beads in native Qt/GTK hosts (the UI permission does not require a specific next control); writer-side serialization/preservation of article threads; and broader script API semantics outside ADR 1934's current tests. No standalone draft is included because the candidate checks either duplicate existing public behavior or test a private diagnostic with no consumer; the only noted candidate is a fixture `was_recovered` hygiene assertion, not a meaningful independent regression test.
