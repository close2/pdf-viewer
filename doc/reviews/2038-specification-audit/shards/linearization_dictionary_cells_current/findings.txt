Annex F parameter dictionary and hint-table audit (effective EC3)

Source and amendments. Annex F begins physical 894 / printed 879. Table F.1 is physical 899–900 / printed 884–885; Table F.2 is physical 902 / printed 887. Table F.3 and remaining Tables F.3–F.12 occupy physical 907–915 / printed 892–900. These were mapped from local extracted page text and visible footer labels. Actual annotations on physical page 899 matter: Issue #331 pairs a StrikeOut of “1.1” with a Caret containing “1.2”, changing F.3.2's minimum writer input version; Issue #153 adds the Table F.1 /Linearized version-number semantics and says the current value is 1.0. Issue #403 adds a NOTE beside the direct-parameter-dictionary requirement: Metadata streams and Associated Files cannot be included in the linearization parameter dictionary. Thus the earlier Annex F shard's generic assertion that no Annex F-specific erratum alters rules is stale. `doc/errata-read.md` puts #331 under F.3.2 and #153 under F.3.3; both are writer rules, not a new requirement to reject a file that claims a bad linearization marker.

Table F.1 has eight cells: required `/Linearized`, `/L`, `/H`, `/O`, `/E`, `/N`, `/T`, and optional `/P` defaulting to zero. The current `every_value_of_the_parameter_dictionary_is_where_the_file_says` inspects the file's first object location, first-1024-byte bound, exact `/L`, `/H` stream object and extent, `/O`, `/N`, `/T`, and `/P`; the support fault verifier checks `/E` against the first-page range. Classic tables and exclusive cross-reference streams have separate raw `/T`/`/Prev` assertions. It does not assert the exact numeric `/Linearized` version. Current writer code emits `/Linearized 1`, which is numeric 1.0, consistent with EC3 #153. The assertion should be added to this existing test alongside the other raw parameter assertions, rather than as a separate test identity. EC3 #403 also means the direct-object construction path must not attempt to embed Metadata streams or Associated Files in this parameter dictionary. The generated H has two values and a direct stream Length, so overflow H pairs and the indirect-Length special calculation are not exercised; those conditional forms are not a current writer feature.

Table F.2 conditions were read cell-by-cell. `/S` is required always. `/T` requires thumbnails; `/O` an outline; `/A` threads; `/E` named destinations; `/V` AcroForm; `/I` Info; `/C` structure tree; `/R` Renditions; `/B` embedded streams. The feature-rich writer fixture covers each condition positively, and the test support `faults` compares relevant catalog/trailer state against required table presence. It checks absent conditional items only insofar as the producer doesn't include unsupported required data; absence conditions are not explicit tests. All current linearization fixture builds include trailer Info and indirect PageLabels, so `/I` absence and `/L` without a label object are not represented.

`/L` is the source-specific ambiguity. F.2 calls it “(PDF 1.3) Page label hint table”; neighboring cells explicitly say “Required only if…” for their conditions. F.4.5 says hints should be provided for document-wide categories and lists Page label hint table “if needed.” The writer emits `/L` when PageLabels contributes a nonempty object group, and comments that a direct catalog dictionary contains no objects for the table. Existing tests verify the positive indirect-label case only. I do not call omission a producer defect, and I did not draft a no-label test asserting a normative result; the source leaves requiredness less explicit than other cells.

Tables F.3–F.12 are summarized in `features.json` with their actual table designations, source-page ranges, current tests and limits. In particular, support code independently decodes hint bitfields and checks asserted ranges against object offsets from the actual cross-reference chain; it does not merely parse or round-trip the writer's output. The independent check is partial: `Read::open` gets `Parameters` via production `state()`, while hint data is decoded by a test-local `Bits` reader. The whole-file verifier catches a planted page-0 location mutation, not a mutation for every field. `qpdf --check` is useful foreign evidence, but its test returns early if the executable is unavailable and it is not the specification oracle. No production reader uses the hint tables; the file opens correctly by ordinary xref processing, which F.1 explicitly permits for readers without the optional optimization.

The current version-floor tests are present and specific: `linearizing_pdf_1_0_refuses_or_raises_the_header_to_the_ec3_floor` and the 1.1 sibling allow refusal or a raised header; the 1.2 fixture is a positive control. This is the effective #331 floor, unlike older source summaries that retain 1.1. The incremental-update test checks the resulting file still opens as ordinary PDF and `NoLongerLinearized`, consistent with `/L` mismatch behavior.

No hint-table reader performance behavior or HTTP range-request integration is claimed. Overflow streams, optional table payloads absent from features, nonempty extended generic shared IDs, one-page thumbnail corner cases, and zero-member embedded-file groups remain unverified; these are bounded optional/conditional optimization cases rather than established reader defects. ADR1225/1622's ordinary-reader choice remains appropriate. ADR1328's item-run alignment is an accepted owner interpretation and has a focused writer assertion; this audit does not turn that decision into a requirement on a reader that ignores the hints.
