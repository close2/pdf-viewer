# Structured-reference errata: metadata and media

This bounded pass checked the primary EC3 annotation objects for all 17 assigned issue IDs, their target text on the named pages, and the current source/assertion reviews cited below. Page references are physical PDF page / printed page. The issue inventory was used only to locate candidate annotations; it was not treated as coverage evidence. No new executable tests are proposed: the effective changes either have a current scoped consumer review, affect producer metadata or excluded runtime behavior, or do not define a reader response to nonconforming input.

One correction to existing records is material. EC3 #218 is not a Table 264 change. Its Caret is on physical p.608 / printed p.593, inside Table 263's `/UR3` permissions-signature description; its contents add that `/Reference` is an array with at least one entry and exactly one UR transform reference. Table 264 starts on physical p.609 / printed p.594. Both `doc/errata-read.md` and `signatures_transforms` currently attribute #218 to Table 264, so those locators should be corrected. `pdf-signature::usage_rights` walks `/Reference` and takes the first recognized UR/UR3 transform; viewer-core uses those rights in notes and revision comparison. The current tests use a single UR transform and do not assert exact-one cardinality. The erratum states a producer structure requirement but does not prescribe reader recovery for a signature with multiple UR references. I therefore record this as an assertion/policy boundary, not a confirmed defect or a reason to grant/revoke rights by an invented rule.

The media and geospatial corrections are already reviewed in narrowly matching shards. #58 on physical p.726 / printed p.711 edits Table 343's `/Asset` relationship and adds a NOTE explaining that a RichMedia asset can reference secondary named assets that should be included in the Assets name tree. That note bears on a complete presentation package; the in-scope reader extracts/list-hands off named Assets, while active RichMedia package execution remains excluded. #142 on p.658 / printed p.643 fixes a 3D cross-reference. #163's p.715 StrikeOut/Caret has a mismatched title (`/Subj` #163, `/T` #162); the additional p.716 Carets clarify that a present Settings entry is unique to each annotation. This is a producer/runtime constraint, not active settings support. #166 makes RichMedia `/Configurations` required and non-empty; the existing Assets extraction fixture is intentionally incomplete as a full producer-valid active object, a limitation already recorded by `legacy_media_annotations_current`.
