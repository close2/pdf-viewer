Source and errata checks
------------------------

The effective ISO PDF locates §8.4.3.2 at physical 175 / printed 160, Tables 53 and 54 / §§8.4.3.3–.4 at physical 176 / printed 161, and §8.4.3.5 at physical 177 / printed 162. Fill rules are at physical 190–191 / printed 175–176. EC3 #154 is a Caret in the §8.4.3.5 page and inserts a minimum `miter limit >= 1.0`; it is not merely an inferred mathematical floor. EC3 #103 on physical 188 / printed 173 changes §8.5.3.2's dash/subpath qualification to apply in the opaque imaging model. #434 adds a NOTE only. No Table 53/54 or fill-rule amendment was found in the effective source or errata inventory.

The source's line width is a distance-set definition for positive width. It also expressly allows up to two device pixels of actual line-width difference depending on pixel-grid position; tests of exact boundaries need to honor that allowance. The existing wide-curve suite is particularly strong because its independently calculated distance sets distinguish a disk from a reversed-outline ring at high widths. Zero-width behavior and negative values are separately covered and are not generalized here into an unbounded raster-accuracy requirement.

The cap tests assert each Table 53 shape: a no-projection butt end, a semicircle, and a projecting square. They distinguish line cap shapes in the shared geometry and separately exercise subpixel area. The join geometry test draws a right-angle stroke and compares the outer corner to a quarter-disc or right-triangle area, with an explicit assertion that the answers differ. The large-miter test derives angle, ratio, wedge area, and tip from the fixture coordinates and checks three backends; its expected shape does not come from another renderer. The below-one parser test is now a test of how invalid producer input is clipped, because #154 makes that input nonconforming.

Two narrow draft cases go beyond the current examples. First, the §8.4.3.4 sentence that only consecutive connected segments get a join is not established by the existing round/bevel area test. `connected_join_and_pentagram.rs` compares two identical right-angle segment bodies, connected versus separate subpaths; a pixel inside the connected miter wedge but beyond both butt-capped bodies must be black in the first case and white in the second. Second, the nonzero and even-odd tests already have excellent source-derived area oracles for nested contours, matching the standard's concentric-circle example, but do not sample the standard's additional self-intersecting-star example. The same draft asserts the central pentagon differs by rule while an arm and exterior serve as controls.

The material unresolved point is transparent degenerate strokes. Current `degenerate.rs` quotes §8.5.3.2 in its pre-errata form, then acknowledges #103 but says there is no behavior change because §11.6.2 makes the stroke one object. In the CPU renderer, `draw_stroke` calls `split_degenerate`, strokes the remaining geometry, then fills extracted circles separately with the same paint/blend. That separation is necessary for the opaque-model special handling, but it may composite overlapping portions of the same transparent Stroke command twice. Existing `degenerate_subpath.rs` assertions concern opaque output; I found no partial-alpha overlap assertion. The draft `degenerate_subpath_one_transparent_object.rs` places a round-capped zero-length closed subpath fully inside a width-8 line, both in one Stroke operation at alpha .5. The sampled point is already inside the ordinary line. Regardless of whether transparent processing includes the circle under #103's qualified rule, §11.6.2's one-object rule says this portion cannot be composited a second time. One composite produces alpha about 128; two SourceOver draws produce about 192. This is a static candidate and has not been executed; it should not be promoted as a confirmed failure until the parent runs it and checks the backend path.

The existing ADRs relevant to these claims are ADR 0398 (large miter wedges), ADR 0290 and ADR 1857 (subpixel caps/dots), ADR 0396 (winding direction), ADR 0226 (even-odd/shape overlap), and ADR 0420 (EC3 #103). ADR 0420's conclusion about no behavior change should be revisited against the same-object alpha test; the discussion quotes the one-object rule but does not cite an overlapping partial-alpha degenerate-path regression.

Residuals
---------

- The two drafts were not executed; no Cargo command was run.
- The line join and star samples are model/backend tests, not exact-xref PDF fixtures. They isolate geometric rules without involving syntax or recovery.
- No blanket certification is made for all angles, dash configurations, transforms, backends, antialiasing choices, or invalid producer input.
- The transparent degenerate candidate remains conditional pending execution and source/API review. #103 narrows the special circle rule to opaque imaging; the draft relies only on single-object compositing inside the ordinary stroke body.
