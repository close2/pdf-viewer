# Legacy media and static media annotation audit

## Verdict

No runtime defect is established in this bounded pass. The project implements the admitted static/poster and file-handoff surfaces. The most concrete source/documentation mismatch is ledger §13.7.2.3.1: its prose says Table 341 makes `/Configurations` optional, but EC3 #166 changed that row to required and non-empty. The feature status may remain narrowly `implemented` for Assets; the note must distinguish the effective producer requirement from the excluded interactive presentation behavior.

## Source and effective reading

Primary EC3 §§13.3–13.4 are printed pp.637–640 (physical pp.652–655). Both subclauses are deprecated with PDF 2.0. §13.3/Table 305 describes self-describing `/F` or embedded samples and the sample serialization rules; its portability recommendations speak to sound players. The code's file handoff and RIFF/WAVE bridge are not an in-process sound player. §13.4/Table 306 distinguishes a stream poster (image XObject), `false`/absent (no poster, false default), and `true` (retrieve a frame from media). The last is playback and is refused under the owner boundary. The format of the external movie is expressly left unspecified.

§13.6.2 is printed pp.643–645 (physical pp.658–660). The controlling sentences require a normal `/AP`; inactive is the default and displays it; active state renders 3D artwork. EC3 #142 on physical p.658/printed p.643 repairs only the cross-reference `0 "Rich media"` to `13.7 "Rich media"`. The code’s normal-AP branch and missing-AP refusal correspond to the in-scope initial display. It does not implement Table 309 geometry, views or activation, nor active U3D/PRC rendering. Existing `annotations.rs` explicitly checks the no-AP refusal for 3D and RichMedia; generic AP tests establish shared placement behavior. The tracked `multimedia_annotations.pdf` golden is only a self-regression detector, not an independent color/geometry oracle. I found no valid subtype-complete 3D fixture in this pass and drafted no test whose nominal 3DD would use fake/nonconforming model bytes.

§13.7.2.1 is printed p.700–701 (physical pp.715–716): a RichMedia annotation shall provide a normal AP, and inactive/default state displays it; active rendering is runtime. EC3 #163 at physical p.715/printed p.700 changes the settings-uniqueness sentence to “if present, shall be unique.” That is an effective producer/runtime constraint, but not a reason to extend static AP scope into activation. The ledger's feature-narrow status does not assert whole-subclause support.

§13.7.2.3.1/Table 341 is printed pp.708–709 (physical pp.723–724); §13.7.2.3.2 Assets is printed pp.709–710 (physical pp.724–725). `/Assets` is an optional embedded-file name tree and is read/listed/extracted. Configurations and views control active presentation. Effective EC3 #166 on physical p.724/printed p.709 makes Table 341 `/Configurations` required and nonempty. Treat that as producer conformance for the active RichMedia construction; the viewer's scope exception is only Assets handoff, not a claim that the active object is valid. EC3 #58 changes Table 343's `/Asset` relationship at physical p.726/printed p.711, outside the assigned rows. #127's renumbering note touching `.3.2` does not change the assets reader rule.

## Assertions and consumers

- `pdf-model/tests/movie_poster.rs` asserts exact red/blue pixels for a two-sample image and checks blank/outside geometry, false/absent controls, and true refusal. This independently discriminates poster drawing from no drawing. Fit/center is explicitly the program's policy because Table 306 does not state poster layout.
- `viewer-core/tests/movies_and_sounds.rs` covers sound/movie public `Event::Media` handoff and sound sample route. `pdf-model/src/media/wave.rs` tests the bytes it writes (including bit-packed cases). These prove conversion/handoff, not actual player execution or user-level device behavior.
- `pdf-model/tests/annotations.rs::no_table_171_subtype_is_refused_with_the_catch_all_s_sentence` separately asserts subtype-specific no-AP refusal for `3D` and `RichMedia`. Its no-AP fixtures are narrow behavior probes and not producer-valid complete annotation examples. Shared annotation AP placement has many literal geometry tests; the corpus golden contains a page with 3D/RichMedia APs but cannot independently validate their exact marks. No positive-control draft was added because the available bounded fixture would either repeat the generic AP path or use intentionally incomplete 3D/RichMedia producer dictionaries; a useful positive subtype test should start from an independently verified, source-valid annotation fixture.
- `pdf-model/src/attachment/rich_media.rs` covers Assets extraction from RichMediaContent, excludes Configurations/Views from file extraction, empty-assets control, and wrong subtype. `viewer-core/tests/rich_media_assets.rs` is an exact-xref, two-page public-route test: page-scoped list, direct byte extraction, pointer-click handoff as `Event::Extracted`, no `Event::Media`, and a filename-rule report. The fixture is a deliberately narrow consumer probe and omits `/Configurations`; under #166 it should not be called a source-conforming full RichMedia annotation. The test's reporting-plus-extraction behavior correctly treats name restrictions as producer-side rather than inventing a mandatory rejection rule.

## Scope and remaining work

The owner ratified A254 on 2026-10-08: still appearances, movie stream poster and media handoff are in scope; in-process audio/video and U3D/PRC active rendering remain excluded pending named triggers. A631 admits saved/handoff media. Q649 and ADR 2428 keep the player trigger unmet. ADR 1946's implementation boundary remains sound. Nothing here revisits §13.2 player viability (covered in `multimedia_data_current`) or other RichMedia runtime tables.

Remaining limited concern: the assets public test exercises Assets consumer behavior but omits the Table 341 `/Configurations` now required of a complete conforming RichMediaContent producer. Keep that explicit in fixture comments/documentation; do not add configurations merely to test unrelated extracted-asset behavior unless a full-producer validity claim is intended. No ledger correction is indicated for #166 in this row; preserve the producer-rule/reader-scope distinction.
