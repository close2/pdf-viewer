Actions and action chains current-spec audit

Effective source checked

I read doc/ISO_32000-2_sponsored_EC3.pdf directly. §12.6.2/Table 196 and NOTE 1 are printed p. 506: Next is a dictionary or ordered array, each action is followed recursively by its own Next, and self-referential actions ought not be executed more than once. The words describe occurrences and a recursive tree; they do not instruct a global visited-set deduplication of repeated siblings. Table 210's IsMap and click-coordinate rule are printed p. 518. Table 214 Hide is printed p. 521. Table 217 Set-OCG-state and its repeat-group examples are printed p. 523. §12.6.4.8's URI dictionary/Base scope is additionally corrected by Errata Collection 3 #256 (doc/errata-read.md): relative-URI Base text applies to all PDF relative URI references; that does not change IsMap's click-only condition.

Next handling

The current `pdf-model::action::read` is a depth-first flattening. Since 4015a9ae it changed from a global set of all visited ObjectIds to a path-local set, so a sibling reference can execute in each array slot, while a recursive back-edge is skipped. `MAX_ACTIONS` and `MAX_VISITS` bound the amount of work. This matches the source's order and self-reference advice; the exact numeric bounds are a product safety limit, not a source threshold.

One unresolved boundary is a chain containing more than one action that replaces the current/embedded document. `interact::resolve` stores only the last `Request::Remote` and last `Request::Embedded`, opening them after request collection. Table 196 requires the sequence, but NOTE 1 recommends terminating when an earlier action makes the next impossible; the standard does not spell out how to proceed after each remote open in one source-document chain. I reported this as a question for a focused owner/spec ruling, not a proven source defect.

Tracked parser tests currently cover a nested array order (`a_next_chain_is_flattened_in_execution_order`), termination of a two-action cycle (`a_cycle_of_next_entries_terminates`, which checks two parsed actions), and exponential malformed/non-action traversal bound. The nested parser assertion is useful but does not exercise execution. In the current worktree `mixed_action_order_audit.rs` drives a link through a public Viewer, and checks a JavaScript runner's state snapshot on the far side of SetOCGState; its reverse-order control catches moving every script to a separate pass. This is meaningful cross-kind observable evidence. It does not prove duplicate indirect reference semantics. The scratch test `drafts/next_repeated_and_cycle.rs` builds exact-xref public link fixtures, then observes `root, leaf, leaf` for `/Next [7 0 R 7 0 R]`, compares it with two independent equivalent child objects, and checks a 6↔7 path cycle emits `root, leaf` only. It was not compiled or executed in this read-only shard; parent owns execution.

URI IsMap

Table 210 defaults IsMap to false; it applies only when a user clicks an annotation. The following paragraph requires device-to-user conversion, offsets from annotation Rect's upper-left, rounds fractional results, and appends `?x,y`. `pdf-model::Uri::at_position` unit tests the arithmetic and false behavior. `viewer-core::interact::activate` obtains the link Rect and converted pointer coordinates, resolves the URI, and emits Event::OpenUri. Outline and OpenAction code paths provide no position, consistent with the explicit source exclusion. The test gap is end-to-end observability of the pointer transform, not the arithmetic alone. `drafts/uri_ismap_click.rs` proposes a valid five-object PDF with exact xref, `/Rect [10 10 30 30]`, and a public click at default user-space `(20,24)`; it expects `https://example.invalid/map?10,6`. Absent and explicit false controls expect the bare URI. This isolates the IsMap behavior from host/browser policy. Draft not run.

Hide and SetOCGState

Table 214 allows an annotation reference, fully qualified field string, or array; H defaults true. `pdf-model::action` checks parsed target shapes/default, `view::actions` applies a state overlay to annotation IDs resolved through field-tree lookup, and `content::interpret_with` consumes that overlay. The integration test in `pdf-model/tests/actions.rs` compares drawing command counts for page content plus a constructed Square appearance before and after hide; a separate test starts with file Hidden and checks `/H false` restores its appearance. `view.rs` also exercises field-name resolution and multiple widgets. These are discriminating render-list/state assertions; they do not claim native-host pixel output.

Table 217 makes State processing ordered, allows a group repeated within State, and defaults PreserveRB true. Parser and ViewState tests cover OFF-then-Toggle, a layer toggled back, radio-group sibling behavior, and explicit PreserveRB false. The render-list action test checks an optional-content marked rectangle disappears while unmarked page content remains, and a fresh ViewState restores file state. Query::Layers is also read at the viewer boundary in the mixed-action ordering audit. The reviewed evidence supports the current state model at the next-render/model boundary. No extra test draft is warranted for these already discriminating paths.

Launch and selected adjacent types

Table 207's `/F` can identify an application or a document to open/print. It gives no general file-name rule for distinguishing one from the other. The current project explicitly declines to start programs (ADR 1358, owner confirmation); a PDF from `/F` opens as a document, and non-PDF classification/handoff is host policy (ADRs 2171 / owner policy), not a source mandate. `viewer-core/tests/remote_go_to.rs` asserts Purpose::LaunchDocument, opened-PDF behavior, and non-PDF/unavailable outcomes. This separation is better supported than a broad statement that the standard requires all launched targets be opened or handed off.

The requested selected action clauses are accounted for but not broadly re-reviewed: GoToDp (§12.6.4.5), Thread (.7), and Transition (.15) belong to prior completed shard work; Movie (.10) is deprecated and its playback falls under the declared clause-13 multimedia exclusion; GoTo3DView (.16) is out-of-scope under the declared 3D rendering exclusion. The present review does not certify all trigger events in §12.6.3, action kinds, JavaScript execution, native host rendering, or every URI/Launch host configuration.
