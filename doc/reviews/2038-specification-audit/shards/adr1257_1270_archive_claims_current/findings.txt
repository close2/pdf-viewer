# ADR 1257 / 1270 archive-output review

This review is limited to the archive writer's public outcomes for form flags, XFA removal and attachment, and original packet preservation. I read the live code and test bodies in `/home/cl/projects/pdf-viewer/.claude/worktrees/r2038-audit`; I did not run Cargo or edit tracked files. The separate Annex I/K shard already records Annex K source pages as physical 959–961 / printed 944–946 and finds no direct K erratum. I rely on that source read for Annex K and do not claim an independent full XFA 3.3 or ISO 19005 audit here.

The strongest live discrepancy is project scope. Root ADR 1257 defines the archive gate's “dynamic” case by `/NeedsRendering true` alone, and `sites::xfa_form_is_dynamic` implements exactly that predicate. The current owner ratification (A840, 2026-11-13), ADR 2876, `scope-ratifications.md`, and `CLAUDE.md` broaden the accepted dynamic-XFA class to include template grammar outside XFAF even when the deprecated flag is absent or false. The current test `a_dynamic_xfa_form_is_refused_until_the_configuration_says_otherwise` covers only `/NeedsRendering true`; there is no test for a grammar-dynamic form with a false/default flag. The archive output requirement to remove XFA at PDF/A targets remains separate from this application’s extra default `dynamic = stop` policy. I classify the mismatch as stale policy predicate/rationale and a coverage gap, not an ISO violation: the owner’s dynamic layout is accepted but scheduled, and Annex K K.1 permits processors to omit schema-driven page generation.

NeedAppearances has a meaningful public output assertion: after the conversion the flag is absent, the widget names an `/AP /N` stream, and the report records one constructed widget appearance. A contrasting button case refuses and names the field; a preexisting AP case checks its decoded bytes survive. This is a solid one-widget slice, not a proof for every widget subtype or every visible widget. The archive test's generated AP assertion checks existence, not the drawn appearance’s literal content; appearance-specific tests elsewhere must supply that evidence before any broader claim.

For XFA attachment, `an_xfa_resource_written_as_packets_is_kept_as_one_file_where_the_target_holds_one` reopens a PDF/A-4e output, confirms the XFA entry is gone, compares the concatenated decoded XML bytes exactly and in packet order, checks `application/octet-stream`, and checks the report row. Its input includes `/ModDate`, but its output assertions do not inspect embedded `/Params /ModDate`, `/AFRelationship /Source`, or that catalog `/AF` names the same specification. The generic XMP attachment test does verify original payload byte equality, Source, Size, ModDate, and catalog AF; both sources call the same generic attachment writer, so the implementation path is shared. The clean improvement is to add those already-supplied output predicates to the XFA test rather than infer their XFA-specific coverage from the XMP test.

One integrity caveat is in `attach::xfa_resource`: a packet-array item that resolves to a non-stream is skipped with `continue`, so an otherwise partially readable malformed array may be attached as a truncated resource. The adjacent `XFA_NOT_READABLE` reason says malformed shape refuses, but that code path can instead produce bytes. This is a defensive archive-preservation inconsistency for malformed input, not a valid-producer rule and not an ISO rejection mandate. It deserves an isolated robustness probe only if archive product policy requires all-or-nothing preservation.

ADR 1270’s core mechanism is supported: XFA resource bytes are decoded from stream(s), concatenated in array order, attached only for the operator-selected preserve route and target configuration; generic code writes the associated file stream and spec, sets `/AFRelationship /Source`, includes source Info `/ModDate` where available, and adds the spec to catalog `/AF`. The XFA-specific public test could prove more of that contract with almost no fixture expansion. MIME fallback is supported by the currently tested unknown-type value; whether `application/xml` would be preferable is not established as a requirement here.

No test draft was made. A grammar-dynamic test would encode a current owner policy expectation that should be confirmed against the intended archive stop behavior before promotion; the XFA attachment assertions are a small extension of an existing public test and can be added directly by the parent without a new fixture. No Cargo commands were run.

## Follow-up: concrete dynamic-XFA boundary and malformed-array integrity probe

I tightened the dynamic-XFA candidate using `pdf_model::xfa::Template::dynamic`'s own tested source marker: a subform `/occur min="1" max="-1"`, paired against the same valid XDP wrapper with fixed bounds `1..1`. The owner ratification names varying occurrence bounds as outside XFAF, and XFA 3.3's page 333 is the source used by both the ratification and `Template::dynamic`. The two generated small PDFs have exact classic xref tables, one ordinary page, a whole-stream XDP resource, and no Catalog `/NeedsRendering`. `qpdf --check` passed for both and pikepdf opened them without repair, confirmed the flag is absent, and read the stream. The XFA XML is well formed and uses the same template/dataset grammar as the repository's existing authored tests; this shard did not run the Rust parser or full external XFA schema validation.

The test draft `drafts/dynamic_xfa_archive_policy.rs` uses the archive test builder and adds a runtime `Resource::read` / `Template::dynamic` guard, a fixed-occurrence output control, and the grammar-dynamic `dynamic=stop` expectation after explicit `Loss::XfaForm` authorization. Current code should let the grammar-dynamic case through because `xfa_form_is_dynamic` reads only `/NeedsRendering`; the assertion is an owner policy test following ADR 2876, not a claim mandated by ISO. Existing `/NeedsRendering true` test remains the catalog-flag control. Parent should decide whether the separate dynamic option intentionally applies to all scope-ratified dynamic cases or only the producer-set flag before promoting this expectation.

The malformed array draft `drafts/malformed_xfa_array_refusal.rs` uses a valid exact-xref PDF wrapper whose XFA array has a readable opening packet followed by a non-stream packet value. Current `xfa_resource` skips that value and can return the opening bytes alone; the archive path may attach truncated XML. The local contract is explicit: ADR 1270 §2 says a malformed/unreadable resource refuses rather than attach a part, and `XFA_NOT_READABLE` promises that behavior. The existing valid five-packet XFA test is the positive control. This probe is intentionally about the writer's all-or-nothing preservation promise for malformed input, not a normative PDF/XFA rejection requirement. No Cargo commands were run.

Parent qualification: ADR2876 changes supported layout scope but does not explicitly set the archive refusal predicate. The statement that the file offers no distinguishing information is stale; whether default stop must use grammar is a policy decision, not an established implementation breach. The proposed dynamic test remains unexecuted and is not in the failure manifest.
