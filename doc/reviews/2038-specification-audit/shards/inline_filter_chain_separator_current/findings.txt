EC3 Issue #20 is on primary physical p. 283 / printed p. 268. I read the actual annotations: the StrikeOut removes the old “only filter” condition and the Caret /Contents inserts “its final or only filter.” In §8.9.7 NOTE 2, this qualifies the optional procedure (“To skip an image a processor can…”); it is not a SHALL to build or use a whitespace-skipping fast path. The separate operative rules still require the appropriate decoding filters and frame the image data.

The encode/decode direction matters for the multi-filter case. The primary §7.4.1 Example 3 says a stream compressed with Flate and then encoded in ASCII85 uses `/Filter [/ASCII85Decode /FlateDecode]`. Thus ASCII85 is the final encoding stage but the first decoder, and its `~>` marker belongs to the outer encoded bytes. `inline_image::data_extent` uses `Document::filtered_extent`, which looks at the first filter's delimiting marker. Existing inline-image test `a_base85_end_of_data_marker_ends_the_data` covers only a single `/A85`; `pdf-syntax/tests/filters.rs::a_filter_array_is_a_pipeline_decoded_in_the_order_written` tests a chained stream but not inline-image extent. I found no existing assertion that combines both.

The scratch test uses a valid PDF 1.7 page/content stream with exact xref offsets, a real `/Length`, `/Resources`, and no recovery/cut chain. Its literal 16 sample bytes were independently zlib-compressed and ASCII85-encoded; the stored decoder list is `[/A85 /Fl]`, matching the primary example. The encoded alphabet naturally contains `EI`; adding white-space around those existing letters makes a false standalone EI token while retaining valid ASCII85 data, since ASCII85 ignores white-space. A positive control without that token is asserted first. The test then checks the scanned extent includes the actual `~>` marker and that both decoding stages return the literal sample bytes. Python's standard zlib/base85 routines independently verify the constants. The draft is unrun.

I did not turn the note's optional skip recipe into a reader requirement. The current scanner consumes the required one-character post-ID delimiter but leaves further white-space among the encoded bytes; the decode pipeline accepts that. The test covers valid multistage inline data and a meaningful chain-boundary assertion, not whether an unused skip optimization strips whitespace. It also does not certify all inline filter chains or claim a known runtime defect.
