This is a bounded assertion review of four exact file-only ledger references, not a full audit of §11.7 or §11.7.5.3. I read the current test bodies and cross-checked their consumers and cited clauses. No Cargo tests were run in this shard.

The primary source puts §11.7.5.3 at physical 450–451 / printed 435–436. It says rendering intent is current at painting for a CIE-based elementary object converted into a different-space parent group, and current at `Do` for a group converted into a different-space parent. For DeviceRGB-to-DeviceCMYK, it separately requires the current BG/UCR pair at elementary painting and at the group `Do`; those functions apply only to DeviceRGB→DeviceCMYK. Physical 451 also says the page-default pair is used for DeviceRGB page output only when the page group is DeviceRGB and the output device is DeviceCMYK. This tree's screen raster is RGB, so that last conditional is not exercised by these screen-render assertions. The NOTE expressly places halftone/transfer use after compositing and at rasterization; those are not colour-selection-time operations.

`black_generation_paint.rs::solid_selection_order_matches_image_and_clause_arithmetic` is the strongest selected witness for the first BG/UCR route. Its generated PDF has explicit xref offsets and paints source RGB (0.2, 0.4, 0.6) into a DeviceCMYK transparency group. The test applies the same pair before or after selecting the solid, stroke, stencil, or image, then asserts the visible literal [52, 62, 79, 255]. Independent §10.4.2.4 arithmetic gives C/M/Y=(0.8,0.6,0.4), k=.4, BG(k)=.6, UCR(k)=.2, hence CMYK=(.6,.4,.2,.6). The literal is specific to this implementation's assumed press output policy, not a unique ISO-mandated RGB pixel. Repeated-state and q/Q tests in the same file additionally check cache/state behavior; some of those compare paired routes rather than independently pinning each route to a literal. The earlier shared-oracle shard separately documents the identical inline-image literal control.

`pattern_tint_context.rs::selected_pattern_tint_uses_current_black_generation` applies that same source arithmetic to a DeviceRGB uncoloured-pattern tint in a DeviceCMYK group and asserts [52, 62, 79, 255]. Further tests distinguish pair-at-paint from pair-at-selection with a later-pair/q-Q sequence, and compare pattern output to solid controls across nested target spaces. The literal shares the selected assumed-press policy with the solid witness; it is still an observable public raster assertion. `ADR 2199` documented the former loss of tint conversion inputs and prescribed retaining source/components through selection, applying current pair at painting, and including conversion dependencies in cache identity. The current test family checks those selected state boundaries; it does not itself independently derive every nested-target output.

`icc_paint_context.rs` has substantially stronger intent oracles than its file-only citation implies. Its local three-table ICC fixture deliberately encodes different A2B intent midpoints. `expected()` quantizes the fixture's midpoint values and applies a separately written D50 XYZ-to-sRGB matrix and transfer curve; tests then assert intent changes, late intent state, q/Q restoration, separate fill/stroke sources, stencils, forms, patterns, groups, and BPC precedence at the visible CPU raster. That expected computation does not call the production profile parser or `Profile::to_rgb`. However the generated profile headers omit fields required for a full ICC-profile validity certificate. These tests are meaningful regressions for this parser/renderer fixture path, not proof that every input is a fully conforming ICC profile. Relevant separate public group/Do assertions named in the 11.7.5.3 ledger row remain outside these four file-only pointers.

`colour_paths.rs` is a broad file-only pointer under aggregate §11.7; the matching ledger row's named test is `a_cmyk_colour_is_the_same_however_it_is_drawn`. That assertion checks equivalence between a CMYK fill, `cs`/`scn`, and an 8-bit CMYK image, with a small image-quantization allowance. It is useful cross-route conversion coverage, but it does not isolate the §11.7.5.3 DeviceRGB→DeviceCMYK painting-time pair. Other tests in the file cover ICC/default/output-intent and spot paths, so its whole-file citation cannot be treated as a single assertion or as aggregate proof. The corpus-backed `a_cmyk_jpegs_samples_are_the_colour_spaces_and_not_the_decoders` skips if `doc/pdf.js/test/pdfs` is absent and panics if that directory exists but `cmykjpeg.pdf` is missing; this is a test availability condition, not a product skip. The audit checkout has the pdf.js corpus directory, but this shard did not execute that test.

EC3 #640 is on physical 377 / printed 362 and changes spelling in §10.4.2.2/.3 (`grey`→`gray`); it does not change §10.4.2.4's RGB-to-CMYK formula. I found no effective annotation on physical 450–451 altering the clauses exercised here. Table/Errata review is limited to these specific source locations.

The selected ADRs remain bounded: ADR 1207 ties explicit BG/UCR behavior to the stated conversion cases; ADR 2549 chooses the profile B2A as this renderer's default when no explicit pair is stated and supersedes ADR 1242's historical output-intent/profile departure. The current implementation removes `Unsupported::BlackGeneration`; do not present ADR 1242 as a live exception. ADR 2276 distinguishes CMYK family resolution at paint from space selection; ADR 2199 covers the pattern-tint state/cache repair. ADR 1266 addresses transfer timing after compositing and is a separate channel from these BG/UCR tests. The files reviewed do not certify the rest of those decisions or every clause requirement.

No missing valid-input assertion was found that justifies a duplicate test draft for these four pointers. The clearest direct behavior is already asserted by literal source-derived pixels and controls. Remaining limits are the synthetic ICC fixture's profile-header completeness, selected rather than exhaustive paint kinds/state combinations, the implementation-specific pixel mapping, and the corpus test's optional root.
