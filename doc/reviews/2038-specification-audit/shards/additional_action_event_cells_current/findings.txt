# Additional-action event cells: bounded source and consumer review

This pass cell-indexed selected portions of ISO 32000-2 §12.6.3 Tables 199–200. It did not recertify Tables 197–198 or every event route. Source identifiers below are physical/printed page pairs checked at the actual table and footer.

Table 199 is on physical p.524 / printed p.509. Its four optional `/AA` entries are all typed as ECMAScript actions: `/K` for character edits in text/combo fields or selection edits in scrollable lists; `/F` before formatting for display; `/V` when a field value changes; `/C` when another field changes, ordered by the form's `/CO`. The current code has corresponding field event dispatch, and the assertions provide more than parser recognition: `pdf-script/tests/hook.rs::a_supplied_runner_is_handed_the_keystroke_and_the_format` records the exact K/K/K/F event sequence, rejected/accepted edits, and displayed `<12>`; `viewer-core/tests/script_levels.rs::at_run_the_total_is_computed_by_the_script` enters two literal amounts and checks the resulting total; `viewer-core/tests/field_commit.rs` checks actual field value/commit outcomes. This supports the sampled edit, format and calculation paths. It does not certify every choice control, possible `/CO` graph, or every host typing sequence. The commit-level validate policy and event sequencing include owner/RFC decisions (ADR 1603/1579), so those details should not be presented as if the four ISO rows alone specify them.

Table 200 begins on physical p.524 / printed p.509 and its `/DP` row continues on physical p.525 / printed p.510. Its five optional ECMAScript actions are `/WC` before close, `/WS` before save, `/DS` after save, `/WP` before print and `/DP` after print. Current consumer paths place calls at those operations. The public test `viewer-core/tests/document_trigger_timing_audit.rs::catalog_document_triggers_bracket_public_viewer_operations` checks WS's changed value in serialized bytes, DS's different live-only value, and WC report before `Closed`; `print_triggers_follow_a_successful_start_and_active_finish` verifies WP's field edit reaches actual print-page ink, DP runs after Finish, and no trigger occurs for a no-op finish. `pdf-script/tests/document_events.rs` tests all five names/sites and the engine-enabled WS script/write path. `viewer-core/tests/document_trigger_timing_residual_audit.rs::catalog_save_triggers_follow_xfa_cancellation_and_public_save_outcome` and `print_triggers_are_absent_until_a_permission_denied_job_is_admitted` add the relevant held/refused controls: DS only follows an actual write, and WP/DP require an admitted print job. These are present source assertions; this shard did not run Cargo or make fresh execution claims.

ADR 1614's five lifecycle call points are supported by these public tests. ADR 2763's distinction between catalog DS and XFA cleanup postSave is separately exercised. These decisions include project policy around `event.rc`, script levels and reader restrictions beyond the narrow timing text of Table 200. No Table 200 DocOpen event exists; the catalog's open behavior is a different Table 29 `/OpenAction` rule.

Table 198 is cited only to keep B22's context straight: its page `/O` ordering text is on physical p.524 / printed p.509 and Table 197 `/PO` on physical p.523 / printed p.508. The durable B22 finding already has an exact public-order test and controls; this pass neither duplicates nor resolves it. The widget/page trigger test `viewer-core/tests/script_triggers.rs` likewise already checks the Table 197 pointer/focus and page C/O ordering routes. Field-AA inheritance defect B62 is a separate dictionary-resolution concern and is not a missing Table 199 trigger call point.

## Boundaries

I inspected two tables deeply (199–200), and checked Tables 197–198 only as cross-reference context. I did not certify action sequences beyond the relevant supported script chain, all form field types, continuous-layout visibility variants, every keyboard/pointer path, all native host lifecycles, or full ECMAScript behavior. Public test bodies and implementation call sites were read; no test was run during this shard.
