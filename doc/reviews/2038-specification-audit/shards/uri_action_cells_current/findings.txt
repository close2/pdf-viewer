# URI action and common action-table review

This is a bounded source-to-consumer review of §12.6.2/Table 196 and §12.6.4.8/Tables 210–211. I read the actual primary table bodies and their own footers: Table 196 is physical p.521 / printed p.506, with its Note 1 continuing on p.522 / p.507; Tables 210–211 and the IsMap text are on physical p.534 / printed p.519. Physical p.535 starts §12.6.4.9, so it is not a Table 211 continuation.

Table 210 specifies three separate behaviors: the URI reference, optional IsMap (default false), and a strict trigger condition. For a click-triggered link, the click point is transformed to user space; `x` is measured from Rect lower-left x and `y` downward from Rect upper-left; each fractional offset is rounded before `?x,y` is appended. It explicitly says IsMap applies only to annotation-click-triggered actions and “shall be ignored” for outline items and catalog OpenAction. The primary page's #256 Editor Note says the Base/URI-dictionary text applies to all relative URIs in the PDF rather than only URI actions; it describes a future relocation and does not rewrite Table 210's IsMap rule. The annotation is Issue #256, with a completed status reply attached. `doc/errata-read.md` records the point at line 583, and current file-spec URL reading cites the same scope extension.

Current model and host paths are separated appropriately: pdf-model resolves a relative URI against Catalog `/URI /Base`; the host resolves remaining partial references against the opened document's location where known; the core emits an `OpenUri` event; the host applies its Links policy. These paths do not themselves authorize an external fetch. Existing tests independently cover Base/absolute/no-Base behavior and the opened-location fallback. `uri_ismap_click_spec_audit.rs` has public Viewer checks for exact click coordinates, default/false, fractional rounding, and OpenAction ignore. However, the current public outline URI test only asserts that some URI is handed to the caller; it does not place `/IsMap true` on that action or verify the required bare URI.

The scratch draft `drafts/uri_ismap_outline_spec_audit.rs` proposes a valid exact-xref PDF 1.7 and a caller-visible comparison using the same `/URI` action object for an outline item and a Link. Its independent expected outputs are the bare `https://example.invalid/map` on outline activation and `https://example.invalid/map?10,6` for a click at user-space `(20,24)` on Rect `[10,10,30,30]`. It asserts no parser recovery and never follows the URI. This is a proposed assertion-quality improvement, not an observed failure; it has not been run.

Table 196's `/Next` order/cycle behavior has already been executed and reviewed in `actions_chains_current/parent-review.json` (actions-wave19b.log), so I do not duplicate it. The remaining small boundary is Note 1's sentence that applications “need also provide some mechanism for the user to interrupt and manually terminate a sequence of actions.” `action.rs` instead caps the flattened sequence at 256 and visits at 1024, silently truncating; `viewer-core` performs the synchronous chain without a cancellation input. This pass did not establish whether an outer native event loop offers a mechanism satisfying the sentence, so it is a qualified owner/source question, not a proven defect or a claim that ISO mandates a particular UI.

Separate preserved discrepancy: `doc/errata-read.md:1985`'s #618 rationale says Table 199's ECMAScript entries are excluded as a whole. That rationale is stale against current accepted bounded script support and current K/F/V/C consumers/tests, documented in `additional_action_event_cells_current`. Do not confuse that historical rationale with #256's Base clarification, and do not edit the tracked errata-read record in this scratch audit.

No test was run, and no external request or handler was invoked. This pass does not certify every URI scheme, all page transforms, every host path, or interpretation of `/IsMap` on a URI action nested under `/Next`; the latter retains the distinction between direct click-triggered actions and actions triggered by an earlier action in the chain.
