No new test is needed. Do not equate producer-invalid header handling with a mandatory reader rejection.

The concrete candidate is Table 246 `/Encoding`. The table calls for the named encoding to be used for non-U+FEFF string field names, values and options, and lists `utf_8` as an allowed value. `Encoding::read` recognizes `utf_8` as the `Unicode` variant, but `Encoding::decode` delegates to `pdf_syntax::text_string`. That PDF text-string routine uses PDFDocEncoding for non-BOM data; it only takes the UTF-16BE path on a FE FF marker. Therefore a valid non-BOM UTF-8 `/T` string is not decoded as the name it represents, and the same issue affects non-BOM string `/V` values. The existing Shift_JIS test is a refusal/owed-path test, not a positive witness for the explicitly listed utf_8 encoding.

Table 249 makes `/T` the required partial field name and imports corresponding entries by fully qualified name. This puts the Table 246 decoding result on a real path: a misdecoded name fails to match the target field. `/V` is typed by field type, and Table 246's encoding still applies when it is a string. The parent-written `fdf_utf8_import_spec_audit.rs` drives a valid `%FDF-1.2` FDF with catalog `/Version /1.4`, exact xrefs, `/Encoding /utf_8`, a UTF-8 `表` field name and value, a UTF-16-BOM override control, and an ASCII control through `ViewState::import` and `save`. Parent execution wave119 found the two ASCII/BOM controls pass and the no-BOM name/value tests fail as described above. The fixture’s `/ID` values are matching 16-byte identifiers, every xref is exact, and the reader reports neither recovery nor a cut chain. Its Table 249 value case uses a text field; this proves field-data semantics, not rendered glyph appearance.

Table 246 also expressly applies `/Encoding` to `/Opt` strings. The current `options()` reader calls the same `Encoding::decode` path and `ViewState::import` exposes imported labels via the public choice control; `ViewState::save` writes option labels as ordinary PDF text strings. The parent has integrated this review’s `/Opt` case into the same tracked test file and is running the combined seven-test target. It uses a choice target with disjoint old options; ASCII, U+FEFF UTF-16 override, and non-BOM UTF-8 `<C3A9>` cases check U+00E9. In the UTF-8 option case, `/V` is the equivalent BOM-prefixed text string `<FEFF00E9>`, isolating the non-BOM `/Opt` decode while keeping the selected value equivalent. Assertions compare live public option labels/selection with saved semantic `/Opt` and `/V`, and verify the original target remains unchanged. The focused scratch duplicate remains available at `drafts/fdf_utf8_choice_options_spec_audit.rs` as source/reproduction evidence; it has not itself been run. These assertions concern form data, not rendered pixels or font availability.
