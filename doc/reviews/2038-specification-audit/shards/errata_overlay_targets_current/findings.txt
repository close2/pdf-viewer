# Errata overlay target audit (bounded sample)

I checked the actual EC3 annotation dictionaries and rendered source pages, then compared each strike QuadPoints against the words on the page using the page text/bounding boxes. The sample contains eight strike/caret replacement pairs across six issue IDs (#10, #12, #216, #239 twice, #292 twice, and #732). It also checks #474 as a caret-only insertion. Locations below are physical PDF pages with the printed footer number.

The clearest wrong-target claims concern #10. On physical 47 / printed 32, the strike quad lies over `should` in the Table 5 `/F` row sentence “the Length entry should still specify the number of those bytes”; its linked caret supplies “shall.” The adjacent sentence requiring embedded bytes to be ignored is not struck. Yet `stream_dictionary_cells_current/findings.txt` says #10 inserts `shall` into that ignore-bytes rule. `stream_external_file_cells_current/findings.txt` then calls a reader-refusal test evidence for the #10 correction; that test exercises the external-stream read path, not the corrected Length requirement. The corrected attribution is producer-facing: Length must give the number of external-data bytes. The independent ignore-bytes rule remains in force.

Issue #216 spans physical 49–50 / printed 34–35 and has two replacement pairs. On physical 49, the strike covers `are` in the opening §7.4.1 sentence about where the choice of decoding filters is specified; the caret changes it to `shall be`, a producer-side dictionary requirement. On physical 50, a second strike covers `files` in `PDF files support a standard set of filters`; its caret inserts `processors shall`, making the standard-filter support rule explicitly reader-facing. Thus `stream_dictionary_cells_current` is correct to connect #216 to both the filter-language changes and Table 6 support tests. My first pass read only page 49 and alleged that this test link was unsupported; I withdraw that allegation after checking the second linked pair on page 50.

The other sampled overlays are correctly mapped in the current source records, with these scope qualifications:

- #732 (physical 157 / printed 142) replaces `Optional` with `Required` in Table 49's URL row. A distinct caret on that page recommends a unique URL; it is not part of the row replacement. Table 49 versus §7.12.6's surviving “optional URL” remains a separate source tension.
- #239 (physical 158 / printed 143) has two linked replacements in §7.12.5: `they shall be ordered` becomes `they should be ordered`, and `numbers shall be a monotonically increasing sequence` becomes `numbers should increase`. Existing summaries of the monotonicity change are accurate but not exhaustive of both overlay targets.
- #292 (physical 287 / printed 272) changes both the §8.10.2 paragraph and Table 93 Resources cell: independence is strongly recommended generally and required from PDF 2.0; the cell changes `Optional but strongly recommended` to `Sometimes required`. The version boundary and writer/reader distinction in the current Form XObject review are sound.
- #12 (physical 395 / printed 380) targets the Table 132 Type 5 halftone default text, replacing “The value shall not be 5” with “The halftone shall not be a Type 5 halftone.” This is separate from #311's deleted Type 5 paragraph.
- #474 is a caret-only insertion on physical 359 / printed 344, not a strike/caret pair. It adds “be between 1 and 1000 inclusive, and should” to the FontWeight row. It supports the current interpretation that 1–1000 is the required range while canonical hundreds are recommended.

I inspected the page footer as well as the annotation placement for each cited page. The source images used during review are in this scratch directory's `pages/`. This sample does not certify other errata or every annotation on these pages, and it makes no new implementation-defect claim. It confirms the already-promoted #10 correction (D66), withdraws a false positive about #216 after checking both affected pages, and notes that #239 summaries omit one parallel edit without contradicting it.
