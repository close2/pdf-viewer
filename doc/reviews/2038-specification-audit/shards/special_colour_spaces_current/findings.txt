# Special colour-space audit (bounded)

The source-backed implementation for Indexed, Separation and DeviceN/NChannel has substantial, discriminating model and public-consumer coverage. I found no demonstrated valid-input defect in the sampled Separation/DeviceN paths. The narrow discrepancy is in the EC3 #309 description in `doc/errata-read.md`: its clause and physical-page locator are correct, but it describes an amendment about `/Colorants` rather than the actual `/None` wording. The row's “untouched” label is historical round 418 context, not treated here as the current review verdict. The actual PDF annotation changes the NChannel `/None` producer rule. Two small public exact-xref drafts close avoidable assertion gaps: one makes the Indexed 0.5 tie/initial index reproducible without an optional corpus file, the other checks public Separation and DeviceN initial tints against explicit full-tint controls. Both are unexecuted; no Cargo was run.

Primary source locations were verified against PDF footers: §8.6.6.3 printed pp.199–200 / physical pp.214–215; §8.6.6.4 printed pp.200–202 / physical pp.215–217; §8.6.6.5 printed pp.203–211 / physical pp.218–226. EC3 #309 is correctly listed under §8.6.6.5 at physical p.221 in `doc/errata-read.md`; the annotation is on DeviceN text spanning printed pp.205–206 / physical pp.220–221. Its StrikeOut on physical p.221 / printed p.206 removes “which may be present only for DeviceN colour spaces that do not have the NChannel subtype”; the Caret on physical p.220 / printed p.205 supplies “The special name None shall not be used in DeviceN colour spaces that have the NChannel subtype.” The discrepancy is the description's subject (Colorants versus None), not the page or clause locator. The PDF footer is ISO 32000-2:2020(E). Annotation fields and rectangles were inspected in the supplied primary PDF.

The current `doc/conformance/ledger.toml` rows for all three clauses say `implemented`; the 2038 clause inventory still has each review `pending`. §8.6.6.3 lists four tests, including `indexed_out_of_range.rs`, whose test returns early when the optional corpus is absent. That corpus test does include a 6.5 tie. `crates/pdf-colour/src/colour.rs::an_indexed_space_reads_its_table` covers lookup and high clamp at unit level; the Lab scaling draft uses a public exact-xref PDF and direct Lab control. The new operator draft adds an exact two-entry palette: implicit selection and explicit 0 are red, 0.49 rounds down to red, and 0.5 rounds up to blue, with index 1 control. Invalid `hival`/lookup lengths are producer constraints; this review does not infer a reader rejection obligation.

For Separation, `colour_paths.rs::the_none_colourant_marks_nothing` and `::the_all_colourant_is_a_complemented_tint` are public render tests with valid alternative parameters and asymmetric expected pixels. All/None are recognized before alternate/function parsing in `parse_separation`; the extra unreadable-function test is only recovery tolerance, not normative evidence. Ordinary Separation colors on a display go through their tint transform as §8.6.6.4 requires. The current tests do not publicly select Separation and paint at its initial tint without `scn`; the draft supplies this and a tint-zero control.

DeviceN/NChannel has stronger coverage: component order and `/None` transform input, all-None suppression, process-space component mapping and missing CMYK components, spot Colorants key/name validation, alternate fallback, process-space ICC, and model-level simulation. `parse_separation` prioritizes all-None suppression and requested simulation, then a fully covered NChannel process mapping, then alternate/tint transformation. Tests read raster results and wrong-key or wrong-colorant controls. Table 72 mixing hints may be ignored, so their lack of generic mixing implementation is not a defect. Producer constraints (forbidden `All` in DeviceN, uniqueness except `None`, required attributes/table lengths, etc.) do not by themselves require reader rejection. After EC3 #309, `None` in NChannel is forbidden for producers; this does not impose a new reader-side rejection requirement.

ADR 1103's process-only route is supported for sampled complete component maps; its unread-transform test is invalid-input resilience only. ADR 1193 is a prior display/default interpretation, not the current sole behavior: ADR 1229 provides an explicit separation-simulation mode and tests alternate and simulated routes. Their NChannel spot-on-display semantics involve a sanctioned custom-blend and host preference decision, so this is policy/interpretation rather than a demonstrated normative defect. ADR 1338's Colorants key/name equality follows Table 70 and is tested with mismatch controls. Whole §10.8.3 simulation quality and desktop host preference exposure are not certified.

Unreviewed: actual subtractive hardware availability, every special-name and attribute recovery case, all Tables 70–72 optional behavior, every decoder/mesh consumer, and host UI exposure across all frontends. Drafts are under `drafts/`; parent execution is required.
