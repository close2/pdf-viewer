# Button fields and choice fields, bounded source/assertion audit

Effective ISO 32000-2:2020 EC3 headings are §12.7.5.2 “Button fields” and §12.7.5.4 “Choice fields”; the assigned prompt's §12.7.4.2 is “Field names.” Button tables are at printed pp. 535–537, radio-specific text at p. 538; choice Table 233 and Table 234 Opt/TI entries are printed pp. 541–542, the I row and value discussion are printed pp. 543–544. EC3 errata #468 is recorded for Table 234 /I at physical PDF page 558 / printed page 543 (`doc/errata-read.md:116`). #170's radio Off-state change is separately treated in the existing radio-off exact-xref test. Locators above refer to the primary PDF's printed footer, not physical page unless said.

## Concrete finding: duplicate display labels can collapse a valid multi-selection

The corrected #468 reading in `doc/errata-read.md:116` says Table 234 `/I` is no longer limited to MultiSelect fields and the former “value is an array” condition is deleted. The source's remaining last sentence says `/V` controls only when the options it identifies differ from `/I`. This fixture gives `/V [(Twin) (Twin)]`, where both displayed names are deliberately equal, and `/I [0 1]`, which identifies the two matching options; these entries agree about two selected items. The options are distinct export values with duplicate display labels: `[(x)(Twin)]`, `[(y)(Twin)]`, `(Other)`. Both values in `/V` are valid option names, MultiSelect is set, and the selected item indices are ascending. The standard does not impose unique labels or exports on `/Opt`.

`crates/pdf-model/src/form.rs::selected` first collects each string in V, then for each identical label finds matching option indices and independently `.find`s the first matching index present in I. For each `Twin` it therefore chooses 0, and the later `out.contains` removes the duplicate; the public control answers `[0]`, dropping index 1. The adjacent source comment still calls `/I` the tie-break only for duplicate labels, but that rationale derives from the old table wording; the current EC3 correction must govern the effective interpretation. Existing tests do not isolate this pair: `text_choice_fields_spec_audit.rs::choice_value_wins_when_the_stated_index_disagrees` tests distinct labels where `/V` overrides a contradictory `/I`; `saving.rs` tests distinct values; `headless.rs::a_host_can_select_several_items_of_a_list_box_and_save_them` starts with distinct labels. None checks an array of repeated V labels resolved by two matching indices.

`drafts/duplicate_choice_labels.rs` proposes a standalone public `Viewer` → `Query::Fields` assertion with classic xref offsets and a `Document::was_recovered() == false` guard. Its second test is a distinct-label multi-select control. The fixture and test have not been compiled or run in this audit; parent must validate them and observe the current outcome before recording an execution finding.

This calls for revisiting the narrow conclusion in ADR 0248 and the #468 reading in ADR 0253/doc/errata-read, not rejecting those decisions wholesale: index-valued selections and V-over-I on genuinely conflicting selections remain supported. In particular, ADR 0248's claim that `/I` disambiguation is only needed for duplicate labels should not be used to narrow the amended Table 234. The final normative resolution depends on reading the complete #468 overlay as well as the printed table, which still exposes the pre-correction prose; owner source notes report the correction and its state as Accepted.

## Boundaries and remaining work

This is not a full audit of §§12.7.5.2/.4. Producer-only flag restrictions (for example, Edit without Combo or DoNotSpellCheck without both Combo and Edit) do not imply a mandatory reader refusal. Table 233 does not expressly say MultiSelect is forbidden on a Combo; the current public host mapping represents a combo selection as `Option<usize>`, and this audit did not settle how a multi-selected combo is to be exposed or whether a narrow host/product policy applies. Editable combos do accept and preserve arbitrary typed values in the model/save path; the headless public source test checks an editable combo's flags and selection, while the saving test checks an out-of-list typed value. Native widget typing and re-read synchronization were not separately exercised here. This shard did not re-audit push-button captions/icon fit, choice commit timing, accessibility semantics, or all button host pointer interactions. No test execution claim is made.
