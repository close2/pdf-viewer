# Shading dictionary cell review

This pass maps common Table 77 and Type 2/3 Table 79/80 cells to current consumers and named assertion bodies. It does not certify every shading type or every malformed-input rule. I directly checked `doc/ISO_32000-2_sponsored_EC3.pdf` table headers, printed footers, and annotations: Table 77 physical 245–246 / printed 230–231; Table 79 physical 249 / printed 234; Table 80 starts physical 250 / printed 235 and continues physical 251 / printed 236. Pages 245–246 and 249–250 have only internal `/Link` annotations in the relevant table span; p.251 has none. No issue/StrikeOut/Caret amendments alter these cells. I also checked the effective errata index and found no related correction.

Table 77’s `ShadingType` and `ColorSpace` cells are required and routed through `pdf-colour::shading::kind_of` and color-space resolution; the ordinary type/device/CIE/special-space paths have separate public evidence in the shading and color-path shards. The producer prohibition on Pattern and Indexed spaces is not treated as a reader mandate to reject. `Background` is conditioned on an appropriate component array and shading-pattern use. The existing public tests cover pattern fills and direct `sh` omission, so the cell distinction is materially tested. `AntiAlias` is optional/default false, and the table describes it as a flag indicating filtering; the associated note emphasizes that aliasing depends on function frequency/output sampling and filtering may be expensive. This pass found no useful source-derived independent pixel oracle for that flag and makes no failure claim.

For `/BBox`, `crates/pdf-model/src/content/pattern/shading.rs::paint_shading` reads the shading’s Table 77 BBox and combines it with the current clip via `rect_clip`; the pattern route has a corresponding BBox clip path. `shadings.rs::a_shadings_bbox_clips_what_it_paints` checks an ordinary, nondegenerate direct-`sh` clip and path intersection. Separately, B20’s `degenerate_tiling_bbox_clip_spec_audit.rs` checks a zero-height tiling-pattern cell BBox. That is a different dictionary/consumer route and cannot substitute for Table 77’s shading BBox. CPU `render-cpu/src/mask_cache.rs` scan conversion preserves one-pixel geometry, but code presence is not a public shading assertion. Table 77 NOTE 2 explicitly says a zero-height/width shading BBox still paints one pixel, referring to §10.7.4. The exact-xref direct-sh draft `drafts/degenerate_bbox_one_pixel.rs` uses an ordinary-BBox red pixel control, fractional zero-width and zero-height boxes, bounded painted-pixel count, and distant transparency. Parent execution reports CPU and all three real Vulkan modes PASS. The first draft had a normal-control sample outside its `[29,31]` box; the scratch copy now samples x=30. Parent’s passing run remains the execution evidence.

Type 2’s required Coords, Function, optional/default Domain and Extend, and endpoint semantics map through `coords/domain/extend/ramp/axial`. Current named tests include `an_axial_shading_runs_from_its_first_colour_to_its_second`, `a_shading_that_does_not_extend_paints_nothing_beyond_its_ends`, and the current `indirect_shading_values_spec_audit.rs::axial_indirect_coords_domain_extend_bbox_and_array_members_match_direct_control`. The last test has now closed both asymmetric Extend directions, including direct and indirect values, so the earlier residual claiming no asymmetric axial case is stale. It also checks a non-unit Domain and BBox against literal samples. The table’s coincident-endpoint no-paint branch remains a narrower assertion gap; `drafts/degenerate_type2_type3_geometry.rs` now adds an exact-xref public `sh` case with both Extend flags true, a transparent page assertion, and a nondegenerate red-axis control. It is unrun.

Type 3’s Coords/radius constraints and the same Domain/Function/Extend shape are handled by `coords/domain/extend/radial` and the renderer’s radial-family solver. The current radial public test checks nondegenerate ramps and nonextension; background tests cover nested-circle/cone bounds; the current indirect-values test checks both asymmetric Extend directions, non-unit Domain, and BBox. The radial private unit test `a_family_of_zero_radius_circles_paints_nothing` verifies the both-zero mathematical case, including `Extend [true true]`; it is not an end-to-end paint assertion. The table says both-zero paints nothing and a single zero radius means a point. A second test in `drafts/degenerate_type2_type3_geometry.rs` checks the entire transparent raster for both-zero radii at coincident and distinct centers, both with Extend true, then controls with a valid zero-to-positive radius and constant-red function. It is unrun; the private unit test alone is not treated as public-paint evidence.

No runtime test was run in this agent pass. Parent independently reports the degenerate-BBox test PASS on CPU and all three real Vulkan modes. The Type 2/Type 3 zero-geometry drafts are unrun. Remaining bounded items include `AntiAlias` filtering interpretation and shading BBox behavior through the shading-pattern consumer. No mandatory-reader failure is inferred for producer-invalid data or from untested table cells.
