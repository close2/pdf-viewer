# ADR0082 determinism/tolerance review

Scope: project raster contract only, not a PDF normative clause audit. Baseline b901326c in the explicit audit worktree. I read ADR0082, CLAUDE's current determinism note, ADR0072, and assertion bodies in the selected `m1.rs`, `compute_lane.rs`, `compute_coverage_determinism.rs`, `lane_bound.rs`, and shared per-pixel bound helper. No Cargo/build/GPU suite was run in this shard.

ADR0082 is internally coherent: same scene/viewport/adapter remains byte-repeatable; CPU remains the correctness reference; cross-adapter and CPU/device byte identity is relaxed. The sampled executable tests support that boundary. `m1::repeated_renders_are_byte_identical` renders twice on one Device and again on a fresh Device. `compute_lane::a_replayed_compute_frame_draws_the_same_bytes` checks retained replay. `compute_coverage_determinism::ported_coverage_is_reproducible_and_reports_cross_adapter_identity` repeats each dispatch and then tests shader-vs-CPU mirror and adapter pairs, but it currently asserts exact equality only on the enumerated Mesa adapters. `compute_lane::the_compute_lane_is_within_one_level_of_the_cpu_lane_on_glyphs` and `lane_bound::the_lanes_agree_to_one_coverage_step` make the known arithmetic-sensitive lane difference explicit and numerically bound for their stated fixtures.

The fixed-function comparison is not the same tolerance as the compute coverage tolerance. `m1` routes golden CPU-reference and cross-adapter differences through `common/bound.rs`; the former derives the allowed channel difference per pixel from counted stores and alpha, exact at pixels with no stores. The adapter-pair gate doubles store counts because it composes two conversions. This is a color conversion bound, not a generic geometry allowance. Any geometric shift still manifests as a different per-pixel coverage pattern and should remain visible in the disagreement location, even if the numeric color bound elsewhere is large.

One small policy wording concern: `compute_coverage_determinism.rs` calls a hypothetical future divergence on a vendor compiler “this test doing its job ... rather than an inconvenience.” That test currently exact-compares, as ADR0082 allows while it passes. The code comment should be read together with the ADR requirement that a new divergence be measured and converted into a stated, derived bound; otherwise the comment sounds as if failing CI were itself the intended relaxed contract. This is a documentation/policy clarity concern, not a behavior finding.

No new test draft is justified from the sampled assertions: direct same-adapter/replay checks and meaningful per-pixel comparisons already exist. Explicit limits: this review did not run adapters, measure new compiler deltas, inspect every raster test/backend, or certify geometry under all scenes.
