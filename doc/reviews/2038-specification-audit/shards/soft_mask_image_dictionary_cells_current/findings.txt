# Soft-mask image dictionary cells: Tables 143–144

Table 143 starts on physical page 435 (printed 420) and continues onto physical page 436 (printed 421); Table 144 is on physical page 436 (printed 421). The main §11.6.5.2 prose begins on physical 434 / printed 419. I checked the actual table captions and cells in `doc/ISO_32000-2_sponsored_EC3.pdf`, then inspected the source annotations on both table pages. Page 435 has only links to Tables 143 and 144. Page 436 has two Issue #619 Caret annotations on Table 143's ID and OPI entries, saying “Deprecated in PDF 2.0”; other annotations on the page are navigation or unrelated. No annotation changes the Matte formula or the dictionary conditions reviewed here.

Table 143 mostly states how a producer forms the auxiliary image: optional `/Type` must be `/XObject`; `/Subtype` must be `/Image`; the image must state `/ColorSpace /DeviceGray` and `/BitsPerComponent`; it must not be a stencil and must omit `/Mask` and `/SMask`. Its Width/Height rule is conditional: when `/Matte` is present both dimensions equal the parent image; without Matte they are independent, while both images still map to the unit square. `/Decode` is optional with default `[0 1]`; `/Interpolate` is optional; `Intent`, `Alternates`, `Name`, `StructParent`, `ID`, and `OPI` are ignored. The forbidden producer forms should not be turned into mandatory reader rejections absent reader-directed language.

Table 144 makes `/Matte` optional. If present, it describes the parent's preblend, with a component count and valid component values from the parent image's space (Indexed uses its base space). Without it, image samples are not pre-blended. The surrounding prose says to compute with actual color component values after Filter and Decode, invert the preblend before color conversion, preserve the results as if the original unblended image data and no Matte had been used, and invert Indexed palette entries rather than indices.

Coverage is substantial and often independent. `image_masks.rs` has literal RGB black-matte, CMYK inversion-before-conversion, and Indexed-entry pixels; `matte_routes.rs` compares literal DCT samples with their raw equivalents; `matte_reduced.rs` covers a parent decoded at reduced JPX resolution. The Table 143 grid condition is represented by the finer mask with no Matte, and same-sized masks in Matte fixtures. `hostile_budgets.rs::a_soft_mask_carrying_an_explicit_mask_is_refused_by_name` exercises a nested explicit-mask departure for recursion containment; it does not make that refusal an ISO reader requirement.

I found one narrow source-defined assertion gap: none of those public matte fixtures uses a non-default `/Decode` on the parent image or mask. The source explicitly fixes Filter and Decode as already applied before inversion. Current code appears to do this correctly: `sample_rgba` obtains decoded parent values before restoring Matte, and the mask opacity plane is decoded during unpacking. The standalone draft `drafts/matte_after_decode_public.rs` uses a hand-derived DeviceGray case with parent `/Decode [0.25 0.75]`, mask `/Decode [0 0.5]`, and `/Matte [0.25]`. Its preblended sample 64 and mask sample 128 each decode so the recovered original is 0.75; over a black page the expected pixel is 48. A no-Matte stored-sample decoy yields 24, and the unblended-original positive control yields 48. The exact-xref fixture states valid dimensions, values, color spaces, and depths, with complete-interpretation and recovery guards. The draft is not run and establishes no behavior failure.

ADR 1268’s current color-domain and inversion decisions remain sound; ADR 1324’s reduced-grid branch is independently covered and does not duplicate the candidate. ADR 0399’s nested-mask refusal is a malformed-input recursion guard, not an ISO mandate to reject all Table 143 producer departures. The ledger row 11.6.5.2 is `implemented` and names this test family. I found no reason to challenge the status from this bounded sample; this is a missing independent assertion for a specific ordering sentence, not evidence of missing implementation or a whole-row certification.
