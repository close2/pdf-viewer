The current ledger marks O.1, O.2, O.2.1 and O.2.2 implemented. The direct fragment search integration test is not listed in O.2.2’s test array (which instead lists the broader selection census); this is a ledger witness-reference gap, while the test itself exists. O.2 and O.2.1 ledger lists do include the comment ordering and embedded-file continuation witnesses. The coverage is substantive rather than just symbol presence. `pdf-model/src/fragment.rs` splits separators before percent decoding, keeps order, names unread parameters and preserves the suffix after ef as its original substring. Its tests exercise the grammar and reserved separator decode. `viewer-core/src/open/fragments.rs` applies the parsed vector in order. The `comment` test is a strong witness: page 5 then comment focuses the /NM on that page, while comment then page 5 checks page one and yields no focus. The ef test checks that page/search after ef do not affect the parent, that the untouched suffix travels in `Event::Extracted`, and that opening the embedded bytes with the suffix navigates/searches that child.

The positive structelem tests also have real semantic controls. `structure_identifiers_audit.rs` assembles exact xrefs and checks document interpretation is complete; reversed nested-child order selects the first MCR page each time, while an empty matching element and page=2 control demonstrate fallback to page one. `destination.rs` tests `/Pg` absence and child hierarchy. Parser tests separately prove URI percent decoding. The missing seam is one public open test combining a URI-encoded reserved character in `/ID`, IDTree matching and structure page resolution; `drafts/annex_o_structelem_uri_id.rs` adds it. This is a test-depth proposal, not a known implementation defect.

Coordinate assertions cover important simple cases. `fragments.rs` checks zoom percentage 200 equals Table149 XYZ factor 2; viewrect tests a page-top-left quarter and expected fit; highlight checks a four-corner device quad against independently stated page dimensions, plus a second-page/control. These use `vertical.pdf` pages with zero-origin boxes, no rotation and default UserUnit. The conversion path itself calls `in_default_user_space`, then destination application passes through `content::page_space_at`, which applies display-box translation, /Rotate, and /UserUnit. The static route appears coherent for a default-user-space point. I drafted a crop-origin, Rotate=90, UserUnit=2 public-query geometry case with a no-rotation control in `drafts/annex_o_coordinates_exact_xref.rs`; the expected values are arithmetic from the PDF page boxes and transformation definition, not another renderer. Since the Annex combines default-user-space units with a page-top-left origin, and rotation's relationship to that page-relative origin merits source interpretation, do not promote any apparent failure as normative until the parent reviews that ambiguity. No current defect is claimed.

Destination parameters interact with page viewing as follows: `view` defers directly to §12.3.2.2/Table149; `viewrect` maps to FitR; zoom maps percentage to factor and maps offsets into user-space coordinates. The underlying destination tests cover eight Table149 forms, null preservation per component, zero zoom, page-object vs remote integer, and structure destination traversal. This is not a recertification of Table149 or the separate known FitR-centering B24 issue. The named destination consumer uses `Destination::read`; earlier navigation shard reviewed the two destination containers and identical-byte collision, so it is not duplicated here.

Reader requirements versus UI policy remain distinct. Annex says a comment is selected, but doesn't define a focus ring. Highlight is mandatory as a rectangle outcome for a supporting processor, but nature is implementation-dependent: `Query::Highlight` exposes geometry and hosts choose color/opacity. `fdf` specifies request then import from relative or absolute URI; tests prove the NeedFile purpose/name and FDF/XFDF data import. A host owns filesystem/network resolution and consent. The ef table has a shall to open the named embedded file and to apply the tail there, but security text only says should consider and may prompt/prevent. Viewer host presentation/security is not a fragment parser requirement.
