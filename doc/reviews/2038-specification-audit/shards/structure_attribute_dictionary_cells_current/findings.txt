# Selected §14.8 structure-attribute table review

Baseline: b901326c. Scope: Table 381 (column attributes), Table 382 (list attributes), and Table 384 (table-cell attributes). The EC3 primary PDF was checked at the caption/row locations, with physical pages distinguished from printed footers. This is a partial current-source/assertion review, not certification of §14.8.

The three selected tables are at physical 803–804 / printed 788–789 (Table 381), 805 / 790 (Table 382), and 807–808 / 792–793 (Table 384). The adjacent §14.8.5.5 lead-in at physical 804 is not Table 382; Table 383 begins at physical 806. The effective Table 377 replacement is appended at physical 1013–1014, not the superseded table earlier in the standard.

Table 381 specifies ColumnCount, ColumnGap and ColumnWidths for column-divided grouping elements, including their defaults and short/excess-array rules. The prior `structure_layout_remaining_current` audit already checked the full table continuation and the #223/#226 effective Table 377 applicability mapping. Current code has no consumer that uses these values to reflow or reposition the authored page; tests likewise do not forward them to a consumer. Under the current display-only scope this absence does not establish a reader defect. Do not create parser-only tests that would imply a supported reflow contract. If such an output path is adopted, the residual cases are the default, short/excess arrays and ColumnGap-versus-ColumnWidths wording.

Table 382's `ListNumbering` remains a qualified issue, D17. The table says values are applied and separately classifies a list as unordered unless ListNumbering is Ordered, Decimal, UpperRoman, LowerRoman, UpperAlpha or LowerAlpha; its note only says extraction tools may autonumber and warns that Lbl may already contain explicit marks. Current code and viewer accessibility carry list continuation but project all List elements as a generic list, with no list-kind signal. This distinction is not resolved by the existing continuation tests or ADR 0748. It remains an API/owner disposition question: no required label generation or platform representation is inferred here. EC3 #346 changes inheritable status on ContinuedList/ContinuedFrom, not ListNumbering.

Table 384's entries are wired through the current table model and public accessibility route. Existing assertions include explicit and implicit header relationships, recursive order, spans, Scope, Summary and Short. The newly promoted #200 control is a real public consumer test. Parent's current run reports its Row-with-Headers case failing: the answer contains Named but omits eligible Middle/Far headers, while three controls pass. This is B53: the algorithm is optional, but once adopted the #200 correction says a scope-conflicting header should not terminate it. It is not a universal implicit-association requirement. The witness leaves open whether Named also contributes and what happens after a later TD; it does not justify expanding the finding beyond that behavior.

Table 383 PrintField is intentionally out of this selection because B29 already records valid-PDF public consumer loss for Role, Checked and Desc; its parser test alone is not treated as end-to-end evidence. B01/B02 language/ActualText findings are also distinct and are not reused as evidence for these attribute cells.

No new test draft is warranted: Table 381 has no consumer contract; Table 382 needs an owner decision before a public assertion can assert representation; Table 384's B53 regression already exists and is parent-run. Parent-reported B53 execution is cited as such; no Cargo execution was performed in this shard.
