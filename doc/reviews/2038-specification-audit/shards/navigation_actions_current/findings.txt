Bounded review of selected navigation/action features

This pass sampled the EC3-consolidated primary PDF, the current conformance ledger, current code paths and actual assertion bodies for §12.4.4.2, §12.5.6.3, §12.6.4.5, §12.6.4.7 and §12.6.4.15. It did not certify the whole clauses or reopen general action ordering, page transitions, threaded-comment UI, annotation appearance-state behavior or DPart-associated-file handling.

The §12.4.4.2 implementation is supported by the public presentation tests, including EC3 Issue #304's adjacent-page behavior when Next/Prev is absent and edge behavior when a page turn cannot continue. `presentations_audit.rs::random_access_arrival_runs_primary_action_then_selects_next_node` tests the more discriminating random-arrival path: it observes the primary NA and then exercises the selected Next node through its PA. Existing coverage does not assert `was_recovered == false` for that particular fixture, so the remaining concern is fixture evidence, not a demonstrated state-machine failure.

For §12.5.6.3, the current chain model follows the source's Text reply/state placement, and an exact-xref public model test checks that a state-less Text reply does not hide a later state. EC3 Issue #479 corrects only the IRT table references. The state API has no non-test consumer in the current tree, and this subclause does not impose a review-state display UI. Missing StateModel alongside State and missing T are malformed producer cases; current inference behavior is tolerance policy. `annotation_state_model_defaults.rs` is an unrun valid-input draft for the Table 175 default values when StateModel is present and State is absent.

The §12.6.4.5 action path is implemented from `/Dp` to a DPart page selection, and unit tests cover first-page resolution for leaf and node targets. No existing public viewer assertion connects activating a GoToDp annotation to the resulting page. The draft `goto_dp_node_viewer.rs` distinguishes an interior node's first descendant leaf (page 2) from an independent direct-page destination control (page 3). It uses a computed exact xref, a PDF 2.0 trailer ID, and explicitly rejects recovery. Its DPart hierarchy follows the corrected effective source: `/DPartRoot` is an indirect catalog entry, the node and leaf references have parent links, and page order matches depth-first leaf order. Physical/printed locators were corrected against the primary PDF: §14.12.2 begins on physical 850 / printed 835; Tables 408 and 409 are on physical 851 and 852 / printed 836 and 837.

For §12.6.4.7, model tests exercise thread reference/index/title spellings, duplicate-title selection and bead reference/index forms. Public viewer tests already establish local first-bead FitR navigation and the external-file handoff. The gap is specifically the nonzero `/B` integer index through the viewer. `thread_bead_index_viewer.rs` uses a two-bead circular thread on different pages, checks omitted `/B` as the first-bead control, then checks `/B 1` reaches page 3. The fixture uses exact xref offsets and checks no recovery. This does not imply a required thread-navigation panel or next-bead UI.

For §12.6.4.15, parsing and host routing exist, but existing public transition assertions exercise page `/Trans`, not a triggered `Action::Trans`. `transition_action_viewer.rs` is an unrun exact-xref link-action test that independently asserts the Wipe/180 transition event and unchanged page. The action text does not add a presentation-mode condition; the selected ADR interpretation is supported. EC3's `/Di` integer correction is a producer/type correction and is not treated as a mandate to reject non-integer values. Transition timing and visual quantity remain implementation choices.

The four drafts are proposals only; none was run in this scratch review. Parent integration and execution should decide whether to promote them. The existing tests were read as assertion bodies; ledger row completion alone was not taken as evidence of public behavior.
