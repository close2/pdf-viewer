ADR1617 and ADR1615 deliberately separate the live realm from the PDF's stored dictionaries: a runner returns Property edits, the view holds them, and save writes selected properties back to their standard entries. The model also derives the form description handed to viewer-core/native controls and the SubmitForm diagnostic from the current ViewState. Those latter readers currently appear to bypass the live overrides.

For Required and ReadOnly, the discrepancy is directly observable at public model seams. `apply_property` records both in `ViewState.scripting.overrides`; `ViewState::field_state` applies them for later script events; `ViewState::set_field` reads the live ReadOnly override. By contrast, `pdf_model::form::fields` calls `Field::read` on the original document and uses its `field.flags` for `FormField.required` and `.read_only`. `submission::chosen` independently calls `Field::read(document, ..., view.annotation(...).value)` and consults only stored `field.flags & FLAG_REQUIRED`. Thus a script-set Required may be known to a later script and save path but absent from the form descriptor and export diagnostic; a script-set ReadOnly blocks the model edit while the host descriptor still advertises the control as editable.

The live `required` and `readonly` setters are accepted by the JS bridge (`realm.rs::every_property_write_is_an_edit_by_member`) and by the view edit handler. Existing `script_properties.rs::required_is_table_227s_bit_two` asserts saved/reopened `/Ff`, while `forms_data.rs::a_read_only_field_refuses_a_person_and_not_an_import` is for the stored flag. T121 verifies static Required-empty reporting plus host policies. None checks these downstream public consumers after an unsaved dynamic property edit. `drafts/live_field_flags_downstream.rs` uses an exact-xref PDF 1.7 with AcroForm DA/DR, `/NeedAppearances true`, a page Widget, and a fake ScriptRunner returning an OpenAction Property edit; it makes no JavaScript-engine or native-window claim. Separate assertions cover Required metadata, Required export diagnostics in both override directions, and ReadOnly metadata plus the already-enforced `set_field` refusal.

`NoExport` is not exposed as a script Field property: it is absent from `FieldProperty::ALL` and from `Property`. The action composer correctly reads its stored Table227 bit and existing submission tests prove it outranks named Fields/IncludeExclude. No dynamic NoExport issue is claimed. Four text flags (`multiline`, `password`, `doNotScroll`, `comb`) are writable, but ADR1615 records them as retained in script state and not drawn; the bridge and `FieldState` preserve them for the realm, whereas the native form descriptor reads the stored Ff. This shard treats that as a project boundary needing owner clarification, not as a new mandatory-rendering claim. MaxLen and its existing B67 evidence are excluded.
