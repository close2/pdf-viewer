Scope and method

I read the effective ISO 32000-2/EC3 source for §7.3.8.1–.2 and §7.4.1–.5, then mapped each inspected obligation to the granular existing entries in `doc/reviews/1983-specification-audit/features.json`, current syntax/filter code, and assertion bodies. Table 5's entries are split by what their values do; Table 6 support and Table 92 abbreviations are represented under §7.4.1. Predictor dictionary/default/row rules (§7.4.4.3–.4), fax/JBIG2, DCT/JPX, and Crypt were left to their existing owners. The no-tests-run limitation is explicit: I did not run Cargo or infer execution from a test's presence.

The strongest effective-source corrections are EC3 #319/#527 for encoded length including the EOD marker (the corrected Example 3 has 449 rather than 447 ASCII85 bytes) and EC3 #98/#293 for ASCII85's numeric upper bound and its mandatory two-byte `~>` marker. Current exact-value assertions exercise these amendments. I saw no unowned top-level ledger gap in the requested range. Distinct Table 5 values are represented, but several are code-supported/reporting boundaries rather than separate reader rejection guarantees.

One narrow candidate remains: `ascii85()` in `crates/pdf-syntax/src/filter.rs` breaks on `~` when the following byte is absent, returning a whole successful decode; the pump's `marker_end(None, true)` instead reaches `Marker::Truncated` and reports `Damage::Truncated`. The normative source calls `~>` a two-character marker, and current comments themselves call a final missing marker truncation, so this is worth a public-contract check. However the general clause leaves recovery/reporting for malformed producer data to the processor, and ADR 0587 deliberately permits route-specific damaged-prefix behavior. I therefore label this an ambiguous decode-report policy difference, not a confirmed mandatory-reader conformance failure. The standalone candidate has a valid `z~>` positive control first and compares both routes on the same `z~` bytes.

The checked source distinguishes producers from readers throughout: `/Length` must state encoded bytes; EODs participate in the encoded extent; writers should not put extra bytes before `endstream`; ASCII85 partial groups produced by an encoder are immediately followed by `~>`; RunLength 128 is its encoded EOD. Those statements constrain valid inputs and serialization, but do not automatically require this reader to reject malformed input. Existing code often retains a prefix plus a typed damage/refusal, a local recovery decision.

Reviewed decision slices: ADR 0464's inline-image marker extent, ADR 0587's bounded filter chain and route-specific corruption handling, ADR 2679's no-sniffing of unstated filters, and the external-stream API boundary associated with ADR 1199. None is certified wholesale. No ADR change is recommended from this bounded sample.

Remaining limits: this was a source-to-ledger-to-assertion review, not a fresh test execution, full decoder proof, or review of each external codec. Existing inventory rows for sampled image/function inferred lengths and filter aliases were read by body; their consumers were not re-run. The ASCII85 unfinished-marker candidate should remain unpromoted until the parent decides whether whole and pump reporting is intended to align.
