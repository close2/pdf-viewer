# Signature framing review — effective EC3 at b901326c

This bounded review covers §§12.8, 12.8.2/.2.1/.2.2/.2.2.1/.2.2.2, 12.8.3/.3.1/.3.3/.3.3.1/.3.4/.3.4.1, and 12.8.4/.4.1 and 12.8.5. Source locators below use the official `doc/ISO_32000-2_sponsored_EC3.pdf`; PDF physical page is printed page +15. The effective text was checked against the actual EC3 annotation layer and `doc/errata-read.md`, not only the inventory. §§12.8 and 12.8.3 are aggregate headings, with no independent requirement before their subclauses.

**The in-scope transform finding is B18; adjacent signature findings remain separately recorded.** Table 257 printed p.574 (physical p.589) permits a P=1 incremental update that contains only the data needed to add DSS and/or a document timestamp. The timestamp’s field-based discovery rule is in §12.8.5.2 printed p.590; §12.8.5.3 printed pp.590–591 also says DocMDP evaluation ignores the timestamp and/or DSS. The current public comparison path does not recognize all of the required registration objects as validation material. The promoted exact-xref test has an independently valid P=1 certification signature, an authenticated DTS over the complete later revision, and a mixed page-change control with its own valid timestamp. Parent ran it: DTS-only returns `NotClassified { level: None, objects: 7 }`; the mixed page-change control does not receive `NoChangeToRank`. This is current finding `2038-B18`, not an inference from source or test presence. Its source and execution evidence are in `doc/reviews/2038-specification-audit/findings.json` and `signatures_transforms/`.

The operational checks and comparison/report check are distinct. `restriction::asserted` and `certification_permits` answer whether a requested operation is allowed; `revision::Comparison` / `viewer-core::notes::modifications` assess changes already present. Therefore ADR 0907’s rationale that operation checks omit DSS/DTS remains accurate for that path, but does not establish the separate comparison consumer. ADRs 1043/1049 remain sound for prefix reconstruction and ordinary object ranking, with this narrow exception now evidenced. No whole-ADR rejection follows.

For CMS framing, the parser test `cms::a_detached_signature_states_its_algorithm_and_its_message_digest` asserts literal detached SignedData facts; this does not alone prove signature authenticity. Corpus mutation tests and key-to-certificate binding tests exercise separate cryptographic/identity behavior. For PAdES framing, `Signature::pades_departures` is limited to ETSI.CAdES.detached; the non-PAdES control and PAdES ECDSA integration assertion substantiate that scope and a real verification path. These do not certify the detailed PAdES subclauses .4.2–.8. DTS tests cover token members, authority, ranges, and a chained timestamp/material case; B18 is the specific DocMDP interaction witness. The current signature inventory also contains B41 (TSA keyCompromise and trusted-time selection under .4.8), B44 (current-time CRL applicability under .4.7), and B47 (historical OCSP `producedAt` under .4.8); these are prior, separately scoped findings, not re-audited here. B42 is a separate §12.8.2.4 FieldMDP-name finding outside this shard. They do not extend this framing review to every timestamp, revocation, or transform condition.

EC3 #152 corrects Table 257 `/P` to integer. The real-number test verifies fallback for malformed input, not a conforming `/P` value. EC3 #55 records a producer order rule that a DTS follow a certification signature when present; I found no basis in the correction alone to require a reader rejection or warning. Table 255 changes #121/#219 and Table 256 #117 are adjacent and were not audited as full feature rows here.

§12.8.4 and .4.1 framing was also reviewed: physical p.600 / printed p.585 states LTV uses DSS and DTS dictionaries; .4.1 itself has no modal reader duty. The DSS/VRI and timestamp details live in later rows, whose current inventory and assertion owners are discussed in `signatures_transforms/`; this limited framing check does not add an LTV finding.

Residual scope: no broad PAdES conformance claim; no review of .3.2 PKCS#1, .3.3.2 archival revocation attributes, .4.2–.8 detailed PAdES rules, .5.2–.3 full DTS chain/LTV conditions, VRI/DSS lookup, revocation status policy, all malformed dictionaries, all key families, or external trust.
