# Marked-content property dictionaries: selected cross-consumer audit

This pass is deliberately bounded to Table 352's DP/BDC property operands and §14.6.2's named-resource rule, plus a reconciliation of Table 97 OCMD cells. The effective primary source places Table 352 on physical p.736 / printed p.721 (the preceding clause prose starts physical p.735); §14.6.2 is physical p.737 / printed p.722. Table 97 caption and rows are physical p.293 / printed p.278. These locations were checked at the actual caption and footer. Tables 96 and 98–101 already have a current cell matrix in optional_content_cells_current and are excluded from fresh review.

Table 352 gives DP and BDC two property operand forms: an inline dictionary or a name resolving through the current resource dictionary's Properties subdictionary. Section 14.6.2 further says an inline list is permitted when all values are direct; when any value references an object outside the content stream, the property list must be a named Properties resource. Its note that values should be used consistently is a recommendation. This producer-form sentence does not itself prescribe rejection of malformed inline references.

The implementation uses `content::marked::property_list` for inline dictionaries and named resource dictionaries. The existing `text_render_modes::an_inline_property_lists_booleans_are_not_operators` is a parser-boundary assertion, while accessibility tests use inline dictionaries for ActualText/Alt/Lang/E and optional-content public raster tests use named Properties resources for OC/OCMD. Associated-file public tests also use named resources. I did not find a text extraction/accessibility assertion where BDC uses a named property resource whose property value is indirect. That combination is valid and reaches a separate public consumer.

The scratch test addition `drafts/named_property_actualtext.rs` uses the existing exact-xref PDF 1.7 accessibility fixture helper. It names `/AFile` through page Resources/Properties; the resource dictionary in object 30 contains `/ActualText 31 0 R`, and object 31 holds the string. The content stream contains no indirect reference. A direct inline `/ActualText (replacement)` case is the control. Both use the test helper's real glyph check and assert literal extraction `replacement`; the named case also asserts the public speech run. This narrows the assertion gap without changing the reader's form policy. Parent owns execution; the draft is unrun.

Table 97 was checked against optional_content_cells_current rather than re-audited wholesale. Its single OCG dictionary route and policy are tested through `/Properties` and raster output; VE-over-P precedence has opposite-outcome controls. Current parent review confirms null/deleted references are neutral. Older optional_content_current notes that described those null cases as uncovered are stale; they are not carried forward. No Table 97 defect or duplicate draft is proposed.

ADR 0060's two property-list forms remain consistent with the source; ADR 1894's cross-piece state is already witnessed by the Contents-array public test; ADRs 2304/2406 reorganize operator dispatch without a discovered semantic difference. ADR 2684 is limited to archive handling of an undefined optional-content resource and is not a general `/Properties` rejection rule. See decisions.json for the selected premise review.

No Cargo command, Git operation, tracked/production/ledger edit, or nested agent was used. This is not certification of every marked-content operator, all OC tables, or logical-structure behavior; no malformed-stream rejection duty is inferred.
