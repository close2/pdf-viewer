# Security-oriented sample of supplemental file-only test references

The inventory has 69 file-level references, and each same-row ledger entry also names tests. The parent shard sampled §7.3.8.1, §8.6.4.2, and §9.3.6. This pass samples five other rows where parser robustness, decoding, evaluation, image consistency, or signature trust matters. The file pointer is supplemental metadata; the named assertion and its actual body determine whether the claim is supported.

The clearest linkage is §12.8.1. `pdf-signature/src/verdict/tests.rs` contains a test-key-signed CMS PDF, a supplied-anchor positive control, and separate wrong/no-anchor, changed-document, unchecked-revocation and policy-constraint controls. The positive carries path length, revocation state, time and timestamp state instead of asserting that a digest alone means valid. The primary source at physical 582–583 / printed 567–568 requires signature-handler validation and digest recomputation. ADRs 0229, 0472 and 1067 preserve those distinctions. This does not certify every signature algorithm/profile; default refusal when revocation was not checked remains explicit.

For §7.3.7, `damaged_page_dictionaries.rs` is specifically about malformed page-dictionary recovery. Its intact/damaged/reachable/unreachable fixtures assert the guard and exact recoverable prefix; it is not a generic dictionary parser test. Named parser tests directly assert null-as-absence, duplicate-key policy, and stopping at an object-ending keyword. The primary text is physical p.45 / printed p.30. ADRs 0784/0786 bound recovery; ADR 0858 explains first-duplicate retention as a local recovery choice because source order is irrelevant. No generic conformance claim follows from the recovery file.

For §7.4.7, `fixed_documents.rs` is a corpus-reproduction harness and may depend on machine-local witnesses. Named tests decode explicit JBIG2 modes, an extended-template witness, and T.88 streams against bitmaps. The primary source at physical pp.60–61 / printed pp.45–46 states bitonal/page-one and stream-organization constraints, including shared globals. ADRs 0014, 1459, 1485 and 2102 tie the confined decoder and extended-template path to bounded witnesses. This is evidence for tested decoding, not complete JBIG2 producer validation or a security certification.

For §7.10.5.3, the model file reference supplies input-dependent wrong-output-count, type and stack-fault tests across tint, image, transfer, black-generation, mesh and shading consumers, each with a non-faulting control. Unit assertions separate errors provable on every run from runtime faults. The primary source at physical p.146 / printed p.131 requires a stack of at least 100 entries and explicitly does not require larger stacks. The implementation's 1000-entry limit is an implementation bound above that minimum, not an ISO maximum. ADRs 2833/2848 explain deferred fault reporting.

For §8.9.5.1, the `image_masks.rs`/`image_dimensions.rs` file pointers are broad. The named dictionary-consistency tests make the source rule concrete: an exact-xref valid DeviceRGB control paints red, while too-short and too-long Decode arrays must be incomplete. The mask suite separately asserts asymmetric stencil pixels and masking behavior. This directly tests the rule that inconsistent image entries cause an error, without using another renderer as oracle.

No test draft or implementation defect emerged. No tests were run. The other 64 inventory references remain outside this shard; their presence does not imply semantic review.
