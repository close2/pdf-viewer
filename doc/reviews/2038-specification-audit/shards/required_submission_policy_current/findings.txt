Table 227 bit 2 is not a parse-time rejection flag. It says a Required field shall have a value at the moment it is exported by a submit-form action. The current compositor checks that condition when a selected field lacks `/V` and adds the sentence to `Submission::owed`.

The same invocation may explicitly include that field without a value. EC3 Table 240 bit 2 says that, when `IncludeNoValueFields` is set, selected fields shall be submitted regardless of value and a valueless field contributes only its name; with the bit clear, it shall not be submitted. §12.7.6.2 does not say to abort a submit action when the Required condition is unmet. Consequently, it would be an overclaim to turn “shall have a value” into a source-mandated host network block, particularly when Table 240 specifies the name-only output shape.

The owner has made the local decision explicit in accepted ADR 1198: the compositor reports Required+empty in `owed`; it does not refuse, and a reader decides at `viewer_host::policy::may_submit`. ADR 1062 separates composition from host transmission. Current code follows that split: `viewer-core::interact` adds owed to report notes before it creates the Submit event, and host policy considers scheme/reachability plus the selected Refuse/Ask/Warn/Send level, not `owed`.

Existing assertions are narrower than the whole route. The model Required test checks the diagnostic against flag/value controls, but uses a minimal fixture and does not check the body or host. The IncludeNoValueFields test checks name-only versus omitted output for a nonrequired blank field, not a Required blank one. Host tests check the policy levels without an owed diagnostic. The scratch draft combines these through a valid PDF 1.7 AcroForm/widget (DA and DR Helvetica, `NeedAppearances true` for absent AP, exact xref), composes with the flag set and clear, parses the FDF, and asks the policy seam without sending anything. Its one deliberate content condition is the absent value on the Required field under review.

No product failure or ISO nonconformance is asserted. The useful residual is assertion coverage of the Submission::owed diagnostic, serialized body, and host-policy combination. The scratch draft checks the diagnostic field and policy result directly; core’s subsequent conversion of owed into Event::Reported is traced in code but not executed by this draft. The result must preserve the report and expose the configured policy outcome; it must not silently claim that `owed` forces a refusal. The draft uses an otherwise structurally valid PDF 1.7 form, but the absent value deliberately violates the Required condition being tested; it is not a conforming-producer fixture for that field. Table 240 does not cancel Table 227. This is a scratch draft, not executed here.
