Bounded review: marked-content operator context and property-list plumbing (§§8.2, 14.6.1–14.6.2). This is not a certification of all behavior in those clauses.

The effective text is the 2020 primary PDF plus EC3. The relevant primary footer locations are physical pages 735–737 (printed 720–722); §8.2 Table 32 is physical 177 (printed 162). EC3 #335 permits marked content at content-stream level or within a text object; do not repeat the superseded base text's broader prohibition. EC3 #302 adds q/Q and BX/EX to the operator pairs that producers must separately nest with a marked-content sequence. EC3 #85 fixes Table 32's Table 352 cross-reference. These are not reader mandates to reject malformed streams.

There is one explicit §14.6.1 reader requirement: a page's Contents array is one stream for marked-content sequence boundaries. `ContentReader::for_page` composes its parts, and `optional_content.rs::a_marked_content_section_may_span_two_parts_of_the_contents_array` tests a BDC in part one, enclosed drawing in part two, and a visible control after EMC under both ON and OFF configurations. This is an observable, discriminating assertion. The test checks interpretation completeness but lacks an explicit `was_recovered()` assertion; record that test-quality limitation without treating it as proof of recovery or a behavior bug.

`run_marked_content_op` pushes BMC/BDC and pops the innermost section at EMC. It dispatches irrespective of BT/ET state, matching the amended valid placement allowance. MP and DP are point operators and are ignored by drawing; DP's separate optional-content reference consequence is tested by `a_group_named_only_by_a_marked_content_point_is_still_referenced`. `appearance::spliced` depth-counts BMC/BDC/EMC to locate the matching close for `/Tx`; under #302, valid input ensures q/Q and BX/EX do not straddle that splice boundary. No additional marked-op rendering draft is justified.

§14.6.2 permits an inline property-list dictionary only when all values are direct; if a value is indirect the producer must use a named resource in `/Resources/Properties`. The reader handles both forms through `content::marked::property_list`. The inline test confirms booleans/null remain dictionary values rather than operators; the optional-content and accessibility consumers exercise named lookups. These form restrictions are producer constraints and do not create a requirement to reject inline indirect-reference content. A missing Properties name is tolerated. §14.6.2 also says consumers should use entries consistently, a recommendation rather than a general display mandate.

EC3 #334 removes a NOTE claiming marked-content tags have no relationship to Tagged PDF and gives guidance on second-class names for undefined tags. It does not convert arbitrary content-stream tags into reader-side structure roles: logical structure and its tag mappings have their own §14.7 consumers. The ledger's §14.6 row correctly focuses on state/consumers; its detailed §14.6.1/14.6.2 notes record the relevant rules. The ledger lists tests by name; reviewed bodies of the named tests exercise their stated observable behavior.

Selected decisions: ADR 0060 introduced direct inline dictionary handling and named Properties lookup; current code retains both. ADR 1894 concerns split-read/join state and does not supersede the explicit page Contents-array test. ADR 2304/2406 split Table 50 dispatch into operator-family modules without an apparent semantic change. ADR 2684 concerns archive handling of an undefined optional-content property resource, not general marked-content rejection. No defect found in this bounded pass; no new test draft is included.
