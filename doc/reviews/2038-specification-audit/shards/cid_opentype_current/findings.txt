This shard reviewed the CIDFont/CMap mapping spine through §9.7.6.3 and the OpenType rows in §9.9.1/Table 124, not all of §9.7 or all of the font-program specifications. The sponsored ISO source was checked through the EC3 PDF and the searchable `doc/md/ISO_32000-2_sponsored_EC3.md`: §9.7.3/Table 114 at roughly 8000–8020; Table 115 and §9.7.4.2 at roughly 8030–8095; §9.7.4.3 metrics at 8070–8125; §9.7.5 and Table 118 at 8129 onward; Table 119 and §9.7.6.2–.3 at 8295–8340; §9.9 Table 124/125 at 8500–8570. The primary PDF physical-page labels are checked against its printed footer; searchable text line numbers are navigational locators, not whole-clause conclusions.

EC3 changes reviewed: Issue #518 removes array-valued CMap `/CIDSystemInfo` (the current implementation did not accept this producer structure; `doc/errata-read.md:109` records it). Issue #106 relaxes indirect-reference constraints in §9.7.4.2; indirect resolution is handled by the document/object reader paths but this pass did not target each relaxed edge. Issue #278 in §9.7.5.3 is punctuation only. The Table 119 and Table 115 text was read with EC3 in force. Producer constraints (e.g. stream mapping type/cardinality, CMap syntax, matching CIDSystemInfo, font number zero, required OpenType tables) were not converted into required reader refusals.

CID implementation reviewed: `pdf-font/src/cmap.rs` carries code value, byte length, codespace membership and separate character/notdef tables; `composite.rs` resolves predefined/stream CMaps, CFF charset, and Type 2 map streams; `loading/glyphs.rs::composite_selection` applies mapped CID, notdef CID, then CID 0. `metrics.rs::composite_widths` and `Vertical::read` consume W/DW and W2/DW2. Tests include source-derived Type 0 fixtures with mixed code lengths, predefined `90ms-RKSJ-H`, W/W2/DW2 examples, duplicate W first-entry behavior, cmap notdef unit tests, and a corpus-based independent `/W` vs manually-read `hmtx` check. The corpus check can skip without those optional corpora. `ocr_text_layer.rs` provides a deterministic remapping-stream public page fixture, but its embedded outlines are intentionally hollow and its generator computes related width/map values through shared test-scenes helpers.

The implementation's most source-sensitive CID stream behavior was readable directly in code but not anchored by a compact fixed-GID ordinary-reader integration assertion: Table 115's big-endian byte pair and §9.7.6.3's short-map fallback to the glyph selected by CID 0. A self-contained exact-xref draft is in `drafts/cid_map_big_endian_and_short_fallback.rs`, with CID 5 mapping to GID 37 from bytes 10–11 and CID 6 absent from the stream falling back to CID 0/GID 36. It includes a valid embedded TrueType, nonempty outline checks, public page interpretation, and `!was_recovered()`. This is an unexecuted test draft, not a reported failure.

OpenType selection review: current `loading/opening.rs::type1_cff_in_opentype` handles name-keyed CFF in a Type1/MMType1 dictionary using glyph names; `composite.rs::cid_to_glyph` handles CFF charset vs name-keyed CFF and explicit CIDToGIDMap; `program.rs`/`sfnt.rs` parse wrapper tables. The changed OpenType test file uses exact xref and asserts actual distinct GID indices plus nonempty outlines. The paired CFF names `two.sups` and `two` and conflicting cmap make name-based selection discriminating; glyf fonts swap A/B in the PDF Encoding. The set covers Type1+CFF, Type1+glyf, CIDFontType0+CFF name-keyed, CIDFontType2+glyf, and a bare Type1C control. It does not prove ISO/IEC 14496-22 conformance or all table-presence rules.

Current baseline diffs in the targeted implementation show OpenType Type1/CFF selection added in `loading/opening.rs`, plus standard-font published-metric changes in `metrics.rs` and its tests. The latter is scoped to Table 109's Standard 14 no-Widths allowance and has a Helvetica A numeric assertion and a standard-14 control; `doc/questions/Q859` remains a stated policy question for non-Standard14 substitute widths and was not adjudicated here. Existing `opentype_selection_audit.rs` assertions were inspected; no test changes relative to baseline were needed for this review.

ADR 2817's selection premise is supported by §9.9.1/Table 124 and the discriminating selection tests. ADRs 0029 and 0140 remain consistent with separate code-to-CID/CID-to-glyph routing and mandated carried CMap data. ADR 1092 is explicitly a choice for a CMap violating producer syntax, not a normative reading requirement. ADR 0350's hollow-font geometry fixture supports its scoped claim. ADR 2870 is permissive substitute policy under §§9.5 and 9.8.1, not an obligation. No Cargo/tests were run; the parent must promote and execute the draft separately.
