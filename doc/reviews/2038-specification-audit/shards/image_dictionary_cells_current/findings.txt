# Effective image XObject dictionary cells (Table 87)

I verified the table number and page footers in the held primary PDF: Table 87, “Additional entries specific to an image dictionary,” spans physical pp. 273–275, whose footers read printed pp. 258–260. The cell matrix in `features.json` lists all 19 Table 87 keys, their type/condition/default, indirectness treatment, current consumer, exact available assertions and a scoped verdict. Table 5 contributes the common stream dictionary keys; Table 88 contributes the per-colour-space Decode defaults. The image XObject `/AF` relationship is a separate §14.13.7 producer rule, not a Table 87 cell (and not the marked-content MCAF table).

The physical-page annotation review found #13's pointer to additional Table 143 limits for soft-mask use; #14 emphasizes the `/Mask` condition without changing it; #215 provides material reader-side behavior for stencils and SMask priority; #366 is a grammatical “the” insertion; and #619 labels `/Name` deprecated in PDF 2.0. The later cross-reference annotations on #13 do not turn soft-mask producer restrictions into general image-read errors. I checked the annotation objects and their page locations, not only the nearby transcription.

The highest-risk decoding/mask boundaries have owner shards: dimensions and required positive-grid reporting (`image_dimensions.rs`); sample depths and filter output (`bit_depths.rs`, predictor and codec shards); Decode defaults/maps and pair-count checks (`decode_arrays.rs`, `image_dictionary_consistency_audit.rs`, `jpx_decode_array.rs`); mask precedence and color-key behavior (`image_masks.rs`, image-masking/JPEG/JPX tests); image intent (`rendering_intent.rs`); interpolation (a hint, not an exact kernel) and alternates (effective EC3 #79) in their own shards; and code 0/1/2 embedded JPX opacity in `jpx_ordinary_opacity_audit.rs`.

Two concrete reader failures are already globally recorded. 2038-B11 (`decode_pairs_must_each_be_numbers`, waves6/8) confirms a correctly-sized base-image `/Decode` array with a non-number member is filtered/shifted. 2038-B14 (`ordinary_rgb_jpx_smask_in_data_two_unpremultiplies_color`) confirms a valid premultiplied-alpha JP2 cdef type-2 channel with `/SMaskInData 2` is refused before rasterization, while code 0 and code 1 controls pass. Keep both entries tied to their exact witnesses and bounded scopes; the cell review creates no duplicate finding.

The base-image Decode member-type issue is no longer a candidate: B11 has already run as an expected failure, with numeric positive control and exact-xref no-recovery guard. Table 87’s `array of numbers` plus §8.9.5.1’s express error sentence are the reader hook; the optional/writer constraints elsewhere are not.

Metadata, OPI, Name, ID and conditional StructParent do not all imply ordinary paint behavior. Name is deprecated for PDF 2.0 while actual XObject lookup comes from the resource key; ID is a Web Capture identifier; OPI is deprecated prepress data; Metadata routes to the generic metadata subsystem; StructParent applies only when the image is a structural content item and is read by the structure subsystem. No standalone render failure is claimed from their optional or conditional status. No broad §8.9 certification is made, and no additional test draft was justified in this pass.
