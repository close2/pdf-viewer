ADR 2870 / unreadable embedded font substitution review

Source locators verified against the effective EC3 primary: §9.5 physical 326 / printed 311; §9.8.1 physical 358 / printed 343; Table 125 physical 368 / printed 353 under §9.9.1. The effective passages retain a permissive meaning. Section 9.5 says a font dictionary contains information usable to provide a substitute when its program is not available. Section 9.8.1 says descriptor metrics enable a processor to synthesize/select a similar face in that situation. Those passages do not require substitution for a stream that is present but unreadable, nor define a mandatory recovery algorithm. Section 9.9.1 and Table 125 describe embedded program formats and stream metadata; a malformed program may be refused, but the producer-side font-program conditions do not dictate the reader's fallback. ADR 2870 is therefore an owner-directed product choice, accepted by Q837/A837, not a mandatory ISO reading result. I found no checked erratum changing that permissive wording.

The current implementation keeps the cause and recovery separate: only `FontError::Malformed` for an embedded program reaches `LoadedFont::substitute_for_unreadable`; a copied descriptor without its program keys is read through the absent-program path. The source refusal stays in the page report and the page remains incomplete. A successful parse that reaches no glyph is excluded from substitution, preserving the authored no-glyph behavior. Composite route failures and the forbidden Identity-H/V combination retain their separate controls.

The older durable T11 claim that an independent exact-xref paired render control was missing is superseded. Current `unreadable_program_fallback_control_audit::unreadable_program_falls_back_like_absent_program_and_keeps_its_report` uses two exact-xref, non-recovered public PDFs with identical font metadata and content; the only difference is absent program versus `FontFile2` bytes that are not a font. It asserts identical pixels and text, visible ink, both origins (with independently computed second origin 34.012), the original refusal and incomplete status. This is useful evidence about the selected product policy, not ISO-mandated output. Table 125 requires `/Length1` for a TrueType FontFile2 program; the parent is adding the exact malformed byte length to this font stream dictionary, without changing the generic page content stream. Other tests cover simple/composite substitution, no route, forbidden identity, and readback; the composite path is conditional on a machine offering a usable face.

The ignored fixed-document sweep found 77/77 documents present and only two stale expectations, both for `PDFIUM-407-0.pdf`. The current page reports three `FontFile2` checksum disagreements and draws substitute glyphs; measured ink is 14.633. The old assertions expected `Text { operations: 197 }` and ink in 7.791..8.791, reflecting the earlier behavior that showed no fallback marks. Since A837 expressly chose the substitute, those are stale gate expectations, not evidence that substitution should be reverted. The parent owns the diagnostics update. The row should retain the three refusal reports and incomplete state while ratcheting the selected visible output.

No new test draft is warranted: the precise paired-control test that was missing in the old durable shard is now present and parent-reviewed as passing. This review does not certify every malformed font type, every host substitute face, or all composite routes.
