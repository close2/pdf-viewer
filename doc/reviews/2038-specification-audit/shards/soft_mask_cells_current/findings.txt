Soft-mask dictionary cells: bounded source/assertion review

The primary EC3 PDF places §11.6.5.1 prose on physical p. 433, printed p. 418; Table 142 itself begins on physical p. 434, printed p. 419. §11.6.4.3's graphics-state `/SMask /None` rule is on physical p. 432, printed p. 417. I checked annotation objects on physical pp. 432–434: the annotations are navigation Links only, with no editorial review annotations affecting these rules. Footer text on p. 434 confirms printed page 419. Table 142 is the correct table number.

The Table 142 dictionary cells are substantially represented in current code and public consumer assertions:

- `/Type` is optional and, if present, is `/Mask`. The parser does not depend on it. `image_masks.rs::a_stencil_under_the_graphics_states_soft_mask_is_drawn_through_both` uses a graphics-state soft-mask dictionary without `/Type` and checks literal masked and unmasked cells, so optional omission has a public valid-input witness.
- `/S` is required and selects exactly Alpha or Luminosity. `soft_masks.rs::an_alpha_mask_reads_the_groups_alpha_and_ignores_its_colour` changes group alpha while holding group color fixed and checks literal output; `a_luminosity_mask_takes_the_groups_grey_and_the_backdrops_outside_it` asserts luminosity and outside-BBox pixels. The independent `transparency_foundations_current` parent review records successful empty-Alpha and transfer-through-Alpha public tests.
- `/G` is required as the group source; a Luminosity group requires `/Group /CS`. `soft_mask.rs` fixtures exercise parsed Form transparency groups through `gs` and pixel output. `soft_mask_dictionary_audit.rs::a_luminosity_soft_mask_respects_a_knockout_group_against_normal_control` adds a literal normal-versus-knockout control. This is selected coverage, not all group-attribute combinations.
- `/BC` applies only for Luminosity, must have the component count of `/CS`, and defaults to that color space's initial value representing black. The Alpha test includes `/BC [1]` and proves it does not alter Alpha. Luminosity tests cover explicit one- and four-component backdrops and outside-group pixels. `soft_masks.rs::an_absent_backdrop_in_a_cmyk_group_masks_everything_away` exercises the absent default; the CMYK output-intent fixture associated with ADR 1764 independently distinguishes family black from the profile's all-zero paper value. Malformed wrong-length `/BC` behavior is recovery and is not treated as a Table 142 normative failure.
- `/TR` is an optional one-input/one-output transfer, defaulting to Identity; `/Identity` is allowed, and output outside [0,1] is clamped. Public tests assert omitted transfer versus explicit `/Identity` for both subtypes, transfer function results including outside the group BBox, an Alpha transfer, and both clamp endpoints. These literals are independent of another renderer, though they do not exhaust all function types or numerical sampling behavior.

For `/SMask /None`, §11.6.4.3 states that it removes an existing mask and makes the effective mask 1 everywhere. `soft_masks.rs::none_removes_the_mask` compares two exact-xref PDF fixtures: one paints through the zero-valued mask, the other applies `/None` before painting. Literal pixels distinguish masked from solid output. Although the content uses `q`/`Q`, there is no paint or assertion after `Q`, so the test does not establish restoration of the pre-save mask; that remains a narrow assertion gap, not a current behavior finding.

ADR 0027's mask-as-group-command and raster-resolution design is consistent with the public consumer tests, but is not itself proof of Table 142. ADRs 1755/1764 correctly support the specifically tested absent-`/BC` device-family case. ADR 2552's §11.5.3 luminosity choice is adjacent and separate; this audit does not reopen or certify that broader choice.

No additional valid-input consumer draft is proposed: the requested defaults, subtype distinction, group source, transfer, and reset have targeted current witnesses. Limits: no exhaustive function-type coverage, no malformed dictionary rejection certification, no every-color-space default matrix, no GPU run, and no whole-clause §11.5/§11.6/image-soft-mask certification. Image-object `/SMask` is deliberately excluded from graphics-state soft-mask dictionary conclusions.
