For the remaining cells, Table 115 supplies the required type/subtype/base font, collection metadata, descriptor, optional horizontal widths, vertical metrics, and glyph map. §9.7.3/Table 114 constrains collection identity compatibility; §9.7.4.3 gives the W and W2 array forms and defaults. These source rules map to current reader paths in `pdf-font/src/loading/opening.rs`, `composite.rs`, `metrics.rs`, and `loading/advances.rs`. They include producer constraints; this review does not turn every invalid value into a required read-side refusal.

Existing assertions give useful, bounded evidence: `composite_font_fixtures.rs::the_w_array_of_example_1_states_each_width`, `::the_w2_array_of_example_3_states_each_vertical_metric`, and `::dw2_of_example_2_places_a_glyph_no_w2_entry_names` assert literal source-derived values. The tracked `crates/pdf-model/tests/cid_map_stream_spec_audit.rs::cid_map_reads_big_endian_and_missing_entry_uses_cid_zero` exercises a valid embedded Type2 CIDFont through a page: CID 5 maps through bytes 10–11 to GID 37, and absent CID 6 falls back to CID 0/GID 36; both have real outlines and the document is not recovered. This is better evidence than API smoke tests, although the metric example tests themselves stop at their metric API and optional corpus tests may skip.

The one concrete assertion gap is the effective #106 path. The public embedded CIDFont fixtures use an indirect FontDescriptor, while inline descriptor unit/simple-font tests do not establish that `load_composite` and its embedded-program route accept a direct descendant descriptor. `drafts/direct_cid_font_descriptor.rs` compares direct and indirect descriptors in exact-xref PDF fixtures with identical LiberationSans bytes, CID map, and literal glyph/width expectations. Independently inspecting the bundled TTF with fontTools gives PostScript name LiberationSans, head bbox (-416,-621,2151,1864) at 2048 units/em, and GID 37 = B with hmtx advance 1366; the PDF descriptor bbox is that font bbox scaled by 1000/2048, and W/DW state 1366*1000/2048 = 666.9921875. The map states CID 5 -> GID 37 in high-byte-first order. The draft is a proposed assertion only; no Cargo run was performed. It does not assert rejection behavior or claim a current defect.

ADR 0029's distinction between code-to-CID and CID-to-GID mappings supports the map fixture and remains consistent with the separate code paths. ADR 0965 supports use of W2/DW2 dictionary metrics for vertical writing; it does not bear on descriptor indirectness. ADRs 2722/2162 discuss direct font dictionaries for transform/materialization behavior, not a tested embedded CIDFont display path. The source-plus-current-test review therefore supports a narrowly targeted direct-descriptor test, not a broad claim that Table 115 is fully certified.
