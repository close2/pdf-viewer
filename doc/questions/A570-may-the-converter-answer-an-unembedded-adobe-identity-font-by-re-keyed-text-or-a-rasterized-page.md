refinements the probes fixed ride into the build:

- **The archive writes the window's guess, and invents none.** On every axis where a re-keyed
  archive could be wrong, the window is wrong in exactly the same way — the viewer already draws
  these pages by CID → ToUnicode → a face's glyph (ADR 0270), so the converter writes down the
  glyph selection the window already makes and names it as a loss, where a commercial tool
  substitutes silently. What the file supplies is the character; what the build supplies is the
  face; the positions stay the document's.
- **The image branch chooses no font, because the font is never the missing piece.** The missing
  piece is the per-CID correspondence: §9.7.3 makes an `Identity` ordering the glyph order of the
  program the file did not embed, for which "no table could exist, and none is owed"
  (`composite.rs`); assigning glyphs to CIDs without it would invent which character each number
  names. So the image photographs the window's own rendering, blank marks included (ADR 0270's
  "a mark the reader loses"), and its worth is page salvage — the graphics, the images and the
  other fonts' text survive as pixels where a refusal archives nothing.
- **Both remedies repair an invalidity, not a choice.** §9.7.5.2: "The Identity-H and Identity-V
  CMaps shall not be used with a non-embedded font" — much of this population is a combination
  the standard forbids outright, so the owner's reading of these files as "already unclear in how
  they should be shown" is the standard's own, stated as a prohibition. The output is valid in
  both branches: re-keying makes the Identity CMap legal by embedding a program; the image keeps
  what was readable and discards what never was.
