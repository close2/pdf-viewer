## §14.13.2 — the form this reader would not name

The clause's first sentence carries no modal verb and is the whole of what it asks a reader: an
associated file's specification "represents either a file external to the PDF file or an embedded
file stream … within the PDF file". `attachment::associated` skipped a specification with no `/EF`,
and the comment above the skip called it "§7.11.1's refusal, which this program has no filesystem to
lift" — **two claims in one coat**. §7.11's own row states the distinction it elided, in a sentence
written for exactly this failure: "the difference between refusing a file and being unable to name
it", and it lists §14.13's associated files among the places where a name now reaches a person. It
did not.

`attachment::external_associated` reads the form now, `viewer_core::notes::about` says it once when
the document opens, and only the bytes stay refused. **Neither corpus has a witness** — the new
`associated_file_census` counts 0 external specifications over the 974 and 0 over
`CC-MAIN-2021-31`'s 65 944, all 89 of the specifications it finds being embedded — so both tests
are built and the report cannot move any page's diagnosis. What is left in the subclause binds a
producer, and nothing in this tree writes an `/AF`, so it is writer-side until the day it does.

## The one gate that failed, and it failed on nothing

`doc/todo/02` §2's full sequence, run whole on this branch with rounds 937 and 938 beside it:
**30 of 31 steps green, one red** — `pdf-transform --test foreign_corpus`, on the `bookmarks`
lane's §14.7 fault for `bug1997343.pdf`, where `mutool show` made 90 members of the source page's
parent-tree entry and 79 of ours. **The same command on the same bytes, ninety seconds later,
stated no fault at all** and one more identical page. Nothing in that lane is seeded or timed —
the writer runs under `Limits::DEFAULT`, which is counts — so what moved is what `mutool show`
*printed*, and `array_shape` cannot tell a short answer from a shorter tree.

That contradicts ADR 0852's own sentence, which says the identical rows move and "only the rows
that cannot move — the faults, the differences and the warnings — carry a verdict". It is trap 3
at one remove: the gate is only as good as how it invokes the other renderer, and a partial answer
is not a small one. The measurement and what would make it a verdict — the array length `mutool
show` states, checked against the members it prints — are written into the gate's own module
comment. **Not fixed here**: a round reading ledger rows has no business rewriting that gate on the
way past, and the guard is one commit for whoever owns the lane.

The launch gate passed, which is worth saying because session 933's run failed it on all four
documents' `peak_mib`: 28 figures banded, 2 not judged for a child that was not on the machine's
own clock, 1 outside and held. `doc/checks/launch-path.toml` was not touched — round 938 owns it.
